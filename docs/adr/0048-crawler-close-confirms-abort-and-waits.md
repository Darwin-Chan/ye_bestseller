# 0048. 采集界面关窗：确认中止，等待收尾后退出

- 状态：已接受（需求与设计）；2026-10-08 用户确认修正后的完整汇总；待实现与验收。
- 日期：2026-10-08（Asia/Shanghai）
- 范围：采集界面的正常关闭；不修改分析、交换程序。

## 背景

ADR-0008 采用“关窗不打断采集”，用后台继续和重开界面管理进程避免误关导致本轮放弃。用户现在明确要求：采集中关窗必须确认，确认后效果与“中止本轮（放弃）”相同。确认框保护误操作，后台继续不再是确认关窗后的结果。

只调用中止然后立即退出不足以实现同等效果：既有停止核验与超时兜底需要继续驱动。关窗必须等待原停止链路收口，而不能把请求已受理等同于进程已停止。

## 决策

1. 当前有采集进程或存在明确的暂停轮次时，关窗先确认；不只用进程存在与否判断是否需要确认。覆盖当前可识别的采集目标，不限于本窗口启动的子进程。已暂停、无采集且无待完成收尾时同样先确认：确认后才将该暂停轮次写为人工放弃，成功后关闭，数据保留且本轮不可续跑。无采集且本轮已完成或从未开始时不制造人工放弃。
2. ×、Alt+F4、任务栏关闭等正常关窗入口统一处理。采集中及所有暂停相关状态均先确认，默认取消；取消或关闭确认框保留窗口、不请求中止、不升级暂停、不自动恢复采集，已有暂停收尾继续。确认框无法显示也不放行关闭。
3. 确认后与中止按钮共用停止语义和机制：本轮人工放弃、已提交数据保留、不可续跑；先协作停止，超时走既有强制停止与归属校验。窗口保持响应，显示正在中止，禁止开始/续跑；停止与既有收尾完成后自动关闭。重复关窗不叠确认框或停止任务。
4. 关窗确认只授权弹框时的采集目标或明确暂停的轮次。原目标自然完成时保留真实终态；无新采集和待完成收尾时可关闭。目标改变时保留窗口、提示变化并要求重新确认，不将旧授权用于新目标。
5. 暂停停止中仍有采集进程时，关窗确认后升级为中止。已经中止收尾时不重新确认或发起中止，沿用原收尾并在完成后关闭。按已确认的 Q9 及用户澄清，进程已退出但暂停收尾未完成时，关窗先确认，确认后才升级为中止；将该轮次写为人工放弃并继续驱动原收尾，等收尾完成后自动关闭。取消则维持原暂停收尾，不升级为中止。不另起停止任务或扩大浏览器处置范围；本规则替代原“等待但不升级”的决定。
6. 目标不可确认、写库失败、强制停止失败等异常不静默关窗：保留窗口，说明原因并允许重试，既有核验与收尾仍需持续驱动。已写入人工放弃时不回滚为可续跑，不提供绕过身份保护的处置。
7. 收尾沿用现有浏览器归属与重试边界，不承诺关闭所有浏览器，也不擅自关闭用户或新目标的浏览器。
8. 确认文案反映真实状态：采集中、暂停停止中、暂停收尾中、已暂停分别说明当前阶段；共同明确中止后数据保留、不可续跑。不把进程已退出的暂停状态描述为采集正在运行。

## 取舍

- 放弃“关闭窗口但让采集后台继续”这一便利，换取用户确认后的明确停止结果。
- 按用户修订及澄清，暂停关窗必须确认，确认后结束本轮、有收尾则等待原收尾结束后关闭；取消关闭则保留暂停与续跑机会。确认框保护误操作，不改变暂停按钮自身保留本轮的含义，也不提供真正关窗后仍保留该暂停轮次的路径。
- 接受关窗需要等待停止收尾，以及失败时窗口不能立即消失的代价；不牺牲身份安全或已提交数据。
- 不另造一套直接杀进程的关窗机制，避免与中止按钮的轮次终态、超时和浏览器归属规则漂移。
- 不保留“后台继续”第三个关闭选项，也不将中止偷偷改成暂停。

## 边界与验收

已暂停但无采集进程的分支也必须确认人工放弃终态实际写入，不能把中止入口的空操作成功当成满足需求；写入失败保留窗口。不得把无进程的异常轮次直接当作已暂停轮次。任务管理器强制结束、断电等非正常关闭不在保证范围。启动后尚未取得可靠身份也不得绕过目标保护。正常停止后的自动关闭必须再核对目标状态，不能把后来出现的新采集当作已授权中止的旧目标。
