# 0058. 远端周包未到是干净结果

- 状态：已接受（2026-10-17）
- 日期：2026-10-17

## 背景

交换台按计划知道其他机器本周应负责哪些店铺。远端机器尚未上传整份周包时，本机仍可以完成自己的导出、拉取和汇总动作；当前实现把“还没收到的包”放入软告警集合，因此在没有其他问题时返回退出码 1。

这会让调度器把一种正常的跨机器时序状态当成需要人工处理的运行结果。报告已经单独记录“还没收到的包”，也不会把缺包机器负责的每个店铺和日期重复列成逐日缺口。

## 决策

整份远端周包未到（`missing_machines`）不再参与退出码的软告警判定。只要本机没有硬失败，也没有其他软告警，交换台返回退出码 0。

仍然保留以下区分：

- 远端周包已到，但包内缺少计划中的店铺或日期，属于远端覆盖缺口，继续返回退出码 1。
- 远端包已发布但本机拉取失败，属于通道问题，继续返回退出码 1。
- 导出失败、包导入失败、接收通道未就绪等本机未完成事项，继续按原规则返回退出码 2。

退出码只表达本次交换动作是否成功完成；周报仍保留缺包事实和下次待办，因此不会丢失跨机器交付进度。

## 结果

计划包含本机 `m1` 和远端 `m2`、本机完成自己的采集且 `m2` 没有发布本周包时：

- `RunOutcome.missing_machines == ("m2",)`；
- 周报继续写“还没收到的包”和对应待办；
- 若没有其他问题，最终结果为“干净（退出码 0）”。

已到包但缺少计划日期的场景继续由覆盖缺口测试保护，预期退出码仍为 1。
