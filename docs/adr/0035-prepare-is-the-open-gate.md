# 0035. 开轮前准备是界面闸门：窗口等准备落定，本地没有本周计划就从界面开不了轮

- 状态：已接受（2026-09-22）（决策 1 的默认勾选口径由票据 17 修订：本周计划归本机、且今天还没采够的店才默认勾选，见 [CONTEXT.md](../../CONTEXT.md) 的「今日采够」）
- 日期：2026-09-22

## 背景

真机首次上机（m4，2026-09-22）暴露的一串：无计划的情况下第一次打开采集程序，准备串在后台
生成并发布了本周计划（本机库也确实落了 12 家店），但开始页的默认勾选是空的。原因是界面把
「开轮前准备」放在后台线程，窗口一打开页面就画好了，而开始页此后没有任何重画机制（只在初始化
与切回页签时取数；轮询只在轮次跑起来之后才有）——准备落定后，那份刚到手的计划没有任何路径
回到页面上。同一根因还有第二个症状：拉不到计划库、本地也没有计划时（那天 00:07、01:10、01:11
三次打开），页面对"为什么默认勾选为空"一个字都不说，拒绝理由要点「开始抓取」才看得到。

第三个症状在设计里：界面的逃生口（确认后按"自由采集 + 记账为计划外"开轮）让"明知没有本周
计划也开轮"只需要一次点错——而分片采集最怕的正是三台各自脱网、把同一批店各打一遍。

## 决策

1. **窗口等准备落定**：界面打开时先走开轮前准备；准备落定之前不建窗口，开始页画出来时默认
   勾选就已经是本机份额。
2. **准备结果如实上页**：就绪时每店带标注——本机份额 `本机`、归别机 `归 m2`、计划没说到
   `计划外`；标注是标记不是锁，越权店仍可勾、照旧放行并记账。
3. **等待超时按"本地有没有本周计划"分岔**：等 30 秒仍未落定，有本地那份 → 按它在页上渲染，
   标「未能确认最新」，勾选与开始照常可用（与降级落定同一待遇）；没有 → 停在闸门。
   「重试准备」沿用同一段预算：30 秒之后不再锁页（照上面分岔），但页面继续等它落定。
4. **闸门**：本地没有本周已落库计划时，界面不开轮——只给理由与「重试准备」，不给勾选、不给
   开始。这条取代 spec §6 降级表末行的"界面确认"逃生口：逃生口只留命令行 `--ignore-plan`，
   记账口径不变（自由采集 + 计划外账）。规则收成一句话：**本地没有本周计划就不能从界面采**。
5. **跨周不自更新**：窗口开着跨了周不会自己重画；开始页发现落库计划不属于当前周时，提示重新
   打开界面。

## 被否掉的方向

- **开始页轮询重画 / 后端推（evaluate_js）**：页面会先画成空的再跳成满的，且要在"准备结果"与
  "用户已动的勾选"之间造一套合并规则；阻塞开窗让页面只在有答案时出现一次，这两笔都省掉。
- **阻塞但不设超时**：git 卡住（凭据交互、断网）时双击就是"没有窗口"——壳用 pythonw 无控制台，
  用户只能杀进程。30 秒兜底把"卡住"变成看得见的状态。
- **未确认到最新一律禁开轮**（超时或降级落定都禁）：会把断网周的采集全禁掉，而计划发布后本周
  不重算、本地即权威——禁掉的应该是"拿不准"，不是"旧"。
- **界面保留逃生口**：与"本地无计划不开轮"自相矛盾，且一次点错就产出计划外数据，污染汇总侧
  的冲突账。逃生口留给命令行这个"明知故犯"的入口。
- **只修标注、不修页面刷新**：用户仍会看到空的默认勾选，问题原样在。

## 结果与代价

- 开窗从此要等一次 git pull：常态 2–10 秒；首次生成并推送计划那次实测 8–20 秒。等待期没有任何
  反馈，第二次双击提示「界面正在启动，请稍候」（原提示假定"已有窗口"，此时窗口还没建）。
- 断网且本地没有本周计划时，界面点不动，只剩「重试准备」——这是有意的引导（先修通道：上机
  清单第 9/11 步），但意味着那种情形下"界面"不是逃生路径，逃生走命令行。
- 准备串里的慢活（缺口检查）移出阻塞段，落定后再做；阻塞段只保留"拉到/生成计划并落库"。
- 连带改动：spec §6 降级表末行由本条取代；`plan_step` 的拒绝文案与相关注释里"界面确认"的说法
  要去掉；开始页新增准备状态与重试入口（票 15）。
