# 0002. 跳过是独立的已处理状态

- 状态：已接受
- 日期：2026-09-11

## 背景

同日去重和同名暂缓都需要记下「本轮不访问详情」。早先的实现把它写成一条没有 SKU 的成功快照，于是「跳过」同时扮演了三个角色：已处理、库存证据、成功计数。结果是重复访问时的去重证据可能来自一次根本没打开的详情，跳过还参与失败率与库存统计。

## 决策

跳过单独记为 `page_status='跳过'`，与成功、失败并列：

- 计入已处理，不计入失败率。
- 不构成同日去重证据——去重只认一次完整的成功详情观测。
- 不参与 SKU 与库存统计。

## 结果

失败率不再被跳过污染，跳过也不会被当成库存证据。代价是所有按 `page_status` 过滤的查询都必须显式区分三种状态，新增统计口径时要一起考虑。

相关词汇见 [CONTEXT.md](../../CONTEXT.md) 的「跳过」「同日去重」；实现见 `bestseller_monitor/db.py` 的 `mark_skipped()` 与各 `page_status` 查询。
