# 先升级接收能力，再发布新版观测包

状态：已接受（部署顺序），2026-10-24；尚未实现。

完整观测批次将作为交换包的新证据。现有接收端可能忽略未知表，却按整包哈希记为已导入；如果先让旧程序收到新版包，升级后同一包可能因幂等账而跳过，造成库存看似到达、观测证据却无法恢复。用户确认采用“先升级并验证 m1/m2/m4 接收能力，再启用新版导出与历史重发”的顺序；m3 恢复时直接部署新版。

新接收端必须继续兼容旧包，并验证旧版先收新版包时的安全恢复路径；不能以“旧版未报错”作为证据兼容通过，也不能靠手工删除导入账收口。该顺序降低历史证据被旧幂等账吞掉的风险，代价是升级窗口必须先完成接收端部署和回退准备。

决策与验收范围见 [恢复计划](../design/exchange-recovery-plan-2026-10-24.md)，核查证据见 [三机报告](../reviews/三机交换台与数据完整性核查-2026-10-24.md)。
