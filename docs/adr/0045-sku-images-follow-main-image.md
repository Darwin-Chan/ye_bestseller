# 0045. SKU 图照抄主图口径：每观测重读重存 · 空图主图代填 · 不进匹配证据版本

- 状态：已接受并实现（2026-09-24；规格与票面见 `.scratch/sku-images/`，落地实况见文末）
- 日期：2026-09-23（草案随规格起草；2026-09-24 票 01–06 全部落地后转「已接受并实现」）

## 背景

库存行只有名称、价格、库存，没有图；名字里还堆着 `#C0WEK#` 这类内部码，汇总侧想按色辨认一个 SKU 只能再回 1688 页面。2026-09-23 实测（offer 588733952962）：SKU 的颜色缩略图就在采集器已在读的详情页内嵌 JSON 里（`skuModel.skuProps` 各规格值的 `imageUrl`），14/14 个颜色值与 14 个 SKU 一一对上、可下载——抓它不需要多访问一次页面。用户需求：采集每次都抓、交换台导出、汇总时汇总。

三个既有事实约束了设计：

- 商品主图的口径已由 README 文档化：每次真实观测重读重存（URL 不变也能识别内容变化）、缺图/失败不借用相邻观测、失败不挡库存；
- 匹配的「证据版本」= sha256(名称 + 商品主图哈希)——证据内容一变，全部已判对的缓存键失效；
- 包兼容实测：新增列宽容、**新增表会让旧程序读不出包**（汇总侧对交换集每张表都要求存在），而汇总会补收历史包，「新程序读旧包」迟早发生。

## 决策

1. **口径照抄商品主图**：每个 SKU 每次成功观测重读重存——图地址与库存行同源解析，字节随观测下载；留 SKU 图流水（含空图与失败，空也留行）；缺图不借用相邻观测；失败不挡库存、不进失败率。空图（页面没配，如颜色随机型规格、单规格商品）以**当次观测的商品主图**代填，来源三态（专属图 / 主图代填 / 无图）可区分；「空」与「失败」是两回事——失败走重试、不代填。
2. **数据形态**：新表 `sku_image_versions`（观测流水）+ 复用 `product_image_assets` 字节池（内容寻址、同哈希不重复存）；交换集由六张表增为七张；字节不进包，只走交换区图片通道——既有机制原样继承。
3. **证据边界**：SKU 图**不进匹配证据版本**——`matching.version` 仍是名称 + 商品主图哈希，判断缓存键与判定口径不变；本期也没有界面/分析消费，只到汇总机入库。
4. **兼容方向**：汇总侧对新表**软容忍**（缺席=旧包，照收，SKU 图这半为无）；原六张表维持硬要求；`EXPORT_FORMAT_VERSION` v1→v2。旧程序读新包无需改动（多出的表与元数据键被忽略，已核实代码路径）。

## 取舍（有意留在口径里的四条）

- **为什么不首见定稿 / 不跟地址变更（候选 A/B）**：C′ 每个观测重读，增量成本是 CDN 下载（约 5 张/商品/天）与流水行；买到的是与主图完全同构的语义——两套图片不用各自解释，且能识别「同地址换内容」。A/B 省流量，但要在文档里为 SKU 图单独讲一套节奏。
- **为什么代填而不是留空**：空图 SKU 占比不小（颜色随机型），留空让每个消费方各自兜底；代填把"这张能用"摆在数据里，来源可区分让「颜色证据」的误用可被挡。
- **为什么不进证据版本**：图一进摘要，全部已判对的缓存键失效，重判成本远超收益；边界留在数据层——图照收，判断不受影响。
- **为什么软容忍是硬要求**：汇总会补收历史包，新程序一定读到旧包；不做软容忍，每次交换台都会撞历史包报错。

## 没动的（挂账）

- 「商品证据版本」在术语表里仍只被引用、未定义（本线不动）。
- SKU 图若要进分组证据或分析界面展示，另开线评估（消费侧不在本期）。
- 历史回填不做（存量 2055 商品靠日常采集自然补齐）。
- coscli 真机契约与上机部署顺序（软容忍做好后两序皆可）归人工线与既有 ADR-0041。

## 结果与代价

- 采集：每台机每天多约 5 张/商品的 CDN 下载（按本机份额粗估两三百 MB/天）；每观测多一批流水行，包内每周万行级。
- 交换与汇总：COS 与拉图流量不变（只有新内容才传/拉）；包内多一张表（v2）、周报多一行计数。
- 后向兼容：旧包照收、旧程序读新包照读；升级顺序无约束。
