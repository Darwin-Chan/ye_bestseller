# 汇总机可以本机试采，但试采不属于正式采集与交换

- 日期：2026-10-08
- 状态：已接受（2026-10-08），命令行 01 与界面 02 已实现。**可用范围于 2026-10-10 修订：只有纯汇总机可以用本机试采**（见文末「修订」段）。

汇总机需要用真实采集流程测试程序，但试采所得数据不能共享给其他机器。保留汇总机角色和机器身份，新增显式本机试采入口；试采库存、图片、证据与轮次状态留在独立本地空间，不参与正式汇总、正式分析、raw 导出、图片上传或判断集发布。普通交换仍从正式空间收取与发布正常数据，不因试采被关闭。判断集由销量分析程序产生，正式判断集仍由交换台按现有通道发布与收取；本次不关闭或改动该共享功能。试采只运行采集，不运行试采分析，不把试采数据送入正式分析，因而不产生需要共享的试采判断集。

这是对 ADR-0034 的补充：那份决策中的过渡期采集仍是真观测、按正式数据共享；本机试采是另一类活动，不需要转换机器角色。正式采集角色闸门仍保留，仅显式试采获得例外。

不采用“进入正式库后只关导出”：它会改变本机正式库存，且 ADR-0039 的判断集发布与角色无关，商品名称、图片哈希和描述仍可能旁路外发。不采用临时切换 collector：试采不应恢复正式采集与外发权限。

试采沿用自己的历史和现有续跑、同日去重与日期边界，不新增每次测试的独立数据集，不自动清空，也不提供转正式数据入口。本次只开放采集页面，不增加试采分析；收益是隔离边界清楚，代价是同日重复运行可能跳过已采商品，也不能直接在正式分析里查看试采。

问答与验收边界见 docs/design/local-trial-collection-grill-decisions-2026-10-08.md。命令行实现与使用说明见 [本机试采命令行](../ops/本机试采命令行.md)；界面入口与跨入口监控见 [本机试采界面](../ops/本机试采界面.md)。

## 修订（2026-10-10）：可用范围收窄为只有纯汇总机

本决策从写下之日起就把试采定位为**纯汇总机的补偿手段**——标题是「汇总机可以本机试采」，
上文也写着「正式采集角色闸门仍保留，仅显式试采获得例外」。但首版实现（命令行 01、界面 02）
只做了「试采豁免角色闸门」这半边：试采入口在**任何**角色上都可用，采集机同样能从界面按钮或
`--local-trial` 进入试采。实现比决策更宽，本次把实现收回到决策原本的口径。

- **可用范围**：`role = merge_only` 是唯一判据，不设白名单、不设强制开关。角色在启动时从
  `config/config.toml` 读入，运行中途改文件要重启才生效（沿用全仓既有口径）。
- **采集机上的表现**：界面不渲染试采入口（不留永远点不动的死控件）；命令行 `--local-trial`
  明确拒绝，退出码与「纯汇总机拒绝正式采集」同为 2——语义都是「本机不承担这件事」。
- **拒绝落在库层**：试采存储的选择只有一处（`for_collection`），门禁加在那里，界面与命令行
  自动同时被覆盖；界面上的隐藏只是同一判据的投影。
- **想试采就走转角色**：采集机要试采，官方路径是按
  [ADR-0034](0034-machine-identity-and-role-change.md) 转成纯汇总机（那是含凭据档位核对的正规操作），
  而不是在采集机上开侧门。
- **遗留数据不代清理**：采集机上若已经存在 `local-trial/` 目录（首版实现期间留下的），
  改版后程序不再读写它，也不自动删除——清理是人工动作，理由与历史证据的处置同规。
- **护栏仍在，但定性为库层防御**：「试采上下文不得导出或交换」的两道校验留在原地。纯汇总机
  本就整趟跳过导出，门禁落地后这两道校验从真实入口再也走不到，它们的价值收窄为「有人绕过入口
  直接调库」时仍然拦得住；不再声称它们是产品级的隔离手段。
- **不采用**：给采集机留 `--force-local-trial` 一类强制开关（等于功能还在、只是藏起来，
  与本次收窄的目的相反）。

决策过程与逐轮取舍见 `.scratch/local-trial-merge-only/grill-decisions.md`；实施范围见同目录
`spec.md` 与 `issues/`。
