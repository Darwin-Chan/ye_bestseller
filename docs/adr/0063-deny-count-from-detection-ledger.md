# 0063. 界面 deny 次数从发生账本投影

- 状态：已接受并实现
- 日期：2026-10-25
- 取代：[ADR-0026](0026-click-event-semantics-in-one-module.md) 中界面 deny 次数只数 click_deny 的约定；其余点击结果分类保持有效。

## 背景

m1 在 2026-10-24 09:59:18 的本轮首次 deny 后开始 600 秒降温，10:03:52 暂停。
现场事件为 deny_hit=1、deny_cooldown=1、click_deny=0，两页却显示 0。
真实调用链回归证明：DenyTracker.record 先提交 deny_hit，再同步降温；暂停、中止或异常
可以阻止其返回，外层点击结果因而不产生。即使没有打断，降温期间旧界面也显示 0。
补采路径能够记 deny_hit 而没有 click_deny，单纯调整点击结果写入时机无法统一两条路径。

## 决策

**界面 deny 次数是本轮被识别为 deny 的发生次数；以降温前已提交的 deny_hit 为事实来源。**

- 次数按发生事件计，同商品再次命中是另一次；不是受影响商品去重数，也不是限流滚动窗口内次数。
- deny_hit 记录发生，deny_cooldown 记录首次降温记忆，click_deny 记录点击路径后续结果。
  后两者都不额外增加新版本的界面次数。
- Database.deny_count 统一持有轮次总数和店铺明细投影，run_view/result_view 共用。
- 兼容旧数据：以**同轮首个 deny_hit 的 event_log.id** 为边界，计入此前的 click_deny，
  再计全部 deny_hit；若本轮没有 deny_hit，则保留全部旧版 click_deny。
  边界在整轮定义后再按店铺过滤，不能每店另取边界。
- 事件 id 定义提交顺序，不依赖时间戳精度；只读查询，不迁移或回填账本。
- 查询使用固定店铺条件和 event 过滤，并补充 (round_id, event) 索引，避免每店查找
  首个 hit 时扫描整轮事件；索引由既有开库建索引流程自动补齐。
- 保留 ADR-0054 的首次降温、窗口衰减、跨续跑降温记忆与停止传播行为。
  重复读取、成功商品重复提交、暂停后成功续跑都不会新增 deny；真正再次命中会新增一次。

## 取舍与边界

直接把两个事件相加会把完整降温后的同一次 deny 算两遍；只数 deny_hit 又会使旧版历史轮次归零。
选用按轮次版本边界的兼容投影，既恢复本现场已有账本的计数，又保留升级前的点击事实。
边界假设该轮从旧版升级到新账本版本后不降级运行；它不是能任意配对异构事件的算法。
旧库首次打开会增加一次建索引工作和相应索引空间，后续刷新沿用索引；事件行保持原样。
界面只声称次数，不声称缺失的商品身份或页面已经恢复；原始 deny 页延迟存档、deny_hit 缺少
商品身份的相邻证据缺口已确认，本次不调整留证时序或 deny 判据。
