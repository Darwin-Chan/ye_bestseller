# 0053. 停顿配额账本按轮次累计、跨续跑延续

- 状态：已接受（2026-10-12）
- 日期：2026-10-12

## 背景

[ADR-0038](0038-pacing-counts-detail-visits.md) 把主动停顿的配额定为「每 180 次详情访问停一次」，
并沿 [ADR-0037](0037-paced-throttling-and-deny-ladder.md) 的旧口径写明「配额只活在进程内存里
（重启从 0 重数）」——当年的依据是「中断本身已经是一次降温」。

2026-10-08 晚 m2 打掉了这个前提：第一段进程跑了 210 次详情访问（21:13 主动停顿过一次），
21:50 操作者暂停本轮、约 **6 秒**后续跑（重启浏览器、开新进程）。续跑段又打了 153 次详情访问，
账本从 0 重数、**一次主动停顿都没有**。站点侧从 21:45 那次停顿算起连续收到 `30 + 153 = 183`
次访问，程序侧被拆成两笔、每笔都不到 180。22:01:36 起 3 分钟内连续 6 次 deny，触发整轮阈值，
本轮中止、不可续跑。另有附带事实：「这一轮已经 charge 了多少次」不落任何地方，事后只能数日志。

## 决策

**停顿配额账本按轮次累计、跨续跑延续：续跑（新进程）时从事件回读「本轮已用掉多少」，接着数。**

- **每次记账落一条 `pacing_visit` 事件**（`shop_key`、`phase=pacing`、`note=n=<距上次停顿的计数>`），
  与 `pacing_pause`/`pacing_resume` 同一条 emit 通道；写失败只记日志、绝不打断采集。记账点不变，
  仍在共享 seam（页面真的到手之后，deny 拦截页照算——ADR-0038 的口径）。
- **种子＝最近一条 pause/resume 之后的本轮 `pacing_visit` 条数**，在续跑入口回读，经参数传进
  账本构造（`Pacing(..., seed=N)`）。种子必须在 `resume_started` 写入**之前**算：那条事件一写，
  「本轮最后一条事件」就成了它自己，停机时长的判据失效。
- **停机清零**：本轮最后一条事件距计算时刻 ≥ `pause_sec[0]`（一次停顿的下限，出厂 25 分钟）时，
  配额视为已停过、种子交 0，并写一行日志说明。停机时长是唯一的时间规则——配额量的是访问
  次数，不是速率。
- **边界**：停在停顿中被打断（有 `pacing_pause` 无 `pacing_resume`）→ 种子 0（那次停顿已入账）；
  进程在刚好凑满后、下一次访问前死掉 → 续跑第一次访问就地停（罕见、方向正确、惰性语义不变）。
- **修复前的旧腿没有 `pacing_visit` 事件**：首个续跑种子算 0——等同改前行为，不需要回填。

## 结果与代价

- 续跑不再失去降温保护：本例里 183 次连续访问会被看见，账本在续跑段第 150 次访问处到点。
- 「这一轮已用多少」从此可审计：数事件即可复算，不再只能读内存或数日志。
- **代价**：每次详情访问多一条事件（量级与既有 `popup_open` 同阶）；新事件插入 (round, shop)
  事件链会改变该店后续事件的 `interval_ms`（链上相邻差）——与既有 pause/resume 同类，
  唯一消费方是研究工具 `tools/analyze_delay.py`，属可接受扰动。
- **反事实诚实注记**：本决策单独**不保证**拦住 2026-10-08 那次中止——修复后首次停顿落在续跑段
  第 150 次访问附近，与第 6 次 deny 谁先谁后按现有日志断不了。deny 侧的账本跨续跑延续与
  两级整轮降温是配套的另一条决策（见 [ADR-0054](0054-deny-ledger-and-round-cooldowns.md)）。
