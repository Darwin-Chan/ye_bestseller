# 0064. 交换台子进程隐藏窗口与周覆盖整段异常阈值

- 状态：已接受，已实现
- 日期：2026-10-25

## 背景

交换台窗口已经有自己的进度与结局输出，但它启动的 Git、COS CLI 以及 Windows 超时清理命令仍可能创建控制台窗口，运行时会抢焦点并遮挡其他工作。

周覆盖检查目前把计划中的每个店铺 × 日期缺口都直接计入异常。某店只缺一天时，这个结果没有区分“部分日期缺口”和“评估范围内完全没有数据”，会让退出码和待办过度报警。

## 决策

交换台启动的所有外部子进程都使用平台感知的无控制台启动策略。Windows 使用 `CREATE_NO_WINDOW`，其他平台保持零 flags；已有命令参数、输出捕获、超时、日志、进度和错误语义不变。该策略覆盖 Git、COS CLI 和 Git 超时放弃时的 `taskkill`。

周覆盖异常按“计划店铺 × 已评估日期范围”判断。评估范围继续使用 `week_days(week, as_of)`，未来日期不参与；一天是否覆盖继续以本机或已到包中存在至少一条库存观测为准。只有某店在评估范围内每天都没有库存数据时，才进入主缺口、退出码 1 和可执行待办。部分日期缺口保留日期与原因，作为报告提示，但不计入主缺口、不改变退出码、不进入可执行待办。整份远端周包未到继续使用“还没收到的包”的暂时性语义，其他通道、冲突、导入和判断集异常不变。

## 取舍与边界

隐藏子进程窗口不会隐藏交换台自己的窗口，也不会删除进度和日志；这样保留运行时反馈，同时避免外部命令反复弹窗。按整段判定降低了单日缺口的误报，但仍把完全空的店铺跨度明确标为异常；部分缺口仍可在报告中追查。

## 验证

覆盖 Git、COS CLI 与 taskkill 的启动 flags 测试；覆盖本地和远端的部分日期缺口、整段无数据、未来日期和远端整包未到；确认报告主计数、退出码和待办符合新口径。实现收尾按项目隔离副本与证据规范执行一次分段全量测试，并在对应工单记录证据路径与处置清单。
