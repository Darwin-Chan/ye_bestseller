# 0036. 拖动式验证页的真实文案进标记表：「验证码拦截」页改判「滑块」

- 状态：已接受（2026-09-22）
- 日期：2026-09-22

## 背景

1688 会以**正常详情 URL** 返回标题「验证码拦截」的拖动式滑块页（DOM 含 `nc_1_wrapper`、
`.nc-container`、`#nocaptcha`，可交互）。运行期存档（`<runtime>/data/raw_pages/`）里这一
家族共 **53 份**，横跨 round_10–35（2026-09-05 起）；其中 **21 份**至今在库里仍记着
「解析失败：详情页未解析出 SKU」，其余当轮靠重试/补采捞了回来。2026-09-22 18:27 的现场
（round_35 的 9 份全中）只是最近一次被发现——不是新现象。

`guard._intervention_of` 对它三支全漏：

1. 地址支全假——不是 punish / deny / login URL；
2. 正文支：页面真实文案「亲，请拖动下方滑块完成验证」「请按住滑块，拖动到最右边」与原表
   六项（向右滑动验证 / 请完成验证 / 滑块验证 / 拖动滑块 / 安全验证 / punish）**无一构成
   子串**——「滑块完成验证」不含「滑块验证」，「拖动下方滑块」不含「拖动滑块」，差之毫厘；
3. 容器支是唯一能兜底的，却被「点我反馈」否决——该页页脚恰带这条链接（与 ADR-0030 挂账
   同源的页面家族；豁免本为「纯反爬拦截页不该响铃」而设，但豁免只在正文带该记号时生效）。

后果：kind=None → 不进 `wait_for_resolution` → `play_alarm` 从不被调用；详情读取循环空转满
`DETAIL_READY_TIMEOUT_SEC`（10 秒）→ 记「解析失败：详情页未解析出 SKU」→ 存原始页 → 下一个。
现场每商品白烧约 10.3 秒并计入失败率，全程无告警——用户看到滑块在屏上，程序一声不吭。

## 决策

**`SLIDER_MARKERS` 补入「请按住滑块」「拖动下方滑块」**（样本：round_10–35 的 53 份存档页
面），并落回归用例
（`tests/test_guard.py::test_the_drag_captcha_page_copy_is_recognized_as_a_slider`，两句各自
单独钉住——抓取时机不同，页面上只渲染出其中一句是常态，存档里「拖动下方滑块」53/53、
「请按住滑块」22/53）。两词都落在单个文本节点内，`inner_text` 的换行拼接不影响子串命中；
正文支的标记循环在容器支之前，命中即判「滑块」。

**全档差分已核**（沿 ADR-0029/0030 的取证惯例）：218 份存档页里本次改动恰好翻转这 53 份
（原本全判 None），非家族页 0 变化。

**顺手删掉容器支里恒假的半句** `any(m in body for m in SLIDER_MARKERS)`（正文支的循环已
先返回，行为不变），并把「正文支先于容器支」的次序用 captcha=True 用例钉住——那是
「文案压过豁免」的唯一依托。

## 被否掉的方向

- **收窄「点我反馈」豁免**（如：命中滑块专属容器 `#nc_1_n1z` / `#nc_1_wrapper` / `.nc_scale`
  / `#nocaptcha` 就跳过豁免）：那才是结构性的兜底——文案会随语言与抓取时机漂移，容器不会。
  但豁免保护的那一类（有容器、无文案的真纯拦截页）**0 份存档样本**、被它误伤的这类有 53 份；
  证据一多一少仍不足以下这一刀（ADR-0030 的教训：不凭想象改判据）。挂账，见下。
- **加更宽的子串**（如「完成验证」）：它在 53/53 样本内当然成立，但宽词的问题是误报面
  （普通页面正文出现「完成验证」字样），今天没有样本能界定这个面，先不加。

## 结果与代价

- 这类页面从此进「等待人工 + 持续响铃 + `verification_appear`」的标准处置；无人处理则
  `InterventionTimeout` → 本轮暂停可续跑，不再是静默的解析失败。

## 挂账

- **豁免的样本账是反的**：保护类 0 份、误伤类 53 份。下次要动它时，优先按「滑块专属选择器
  命中即跳过豁免」的方向收窄。
- **未渲染空壳是另一种静默漏检**：4 份存档（round_11/20/22）只有引导脚本、可见文本为 0、
  容器元素不存在，三样证据全空——本表管不到，症状与本次相同（10 秒空转 + 解析失败 + 无告警）。
- **新词是无长度门的裸子串**：`LOGIN_MARKERS` 有 `len(body) < 3000` 门，滑块表没有；商品页
  正文引述该句会误判「滑块」（0/218 样本，低置信，先不设门）。
- **滑块先于登录的优先级不变**：同页两类文案都出现时归「滑块」而非「登录墙」（0 例；行为
  与响铃一致，仅影响 `analyze_delay` 按类型的统计分桶）。
