# 0042. 等待原语：条件 · 上限 · 轮询间隔 · 取消钩子收进一个 module

- 状态：草案（2026-09-23 随票 01 起稿；票 06 定状态。现状：票 01 已落地——`waiting.py`
  原语与 `Humanizer.sleep` 迁移；票 02–05 未实现）
- 日期：2026-09-23

## 背景

一笔「等页面」的知识在四个 module 各写一份，其中只有两个认得停止请求：

- 榜单页 `listing.wait_until` / `wait_cards`（10–18 秒）与 `wait_for_change`（10 秒）；
- 详情页可读轮询 `detail_visit.ReadyDetailVisit.observe`（10 秒，人工介入解决后重置窗口）；
- 浏览器调试端口等待 `browser_pw.open_session`（25 秒）；
- 人工介入等待 `guard.wait_for_resolution`（确认窗口 + 最长 10 分钟的响铃循环）与
  `delay.Humanizer.sleep` 的睡眠分片。

`stop_request.check()` 全仓只有三个直接调用点（delay.py:31、guard.py:252/274），
`listing`／`detail_visit`／`browser_pw`／`click_listing` 零 import。后果：单次页面等待
10–25 秒，远大于协作停止的窗口（ADR-0009：没回执 8 秒、回执后再 10 秒）——「暂停」落在
页面等待里时，采集进程到不了下一个检查点，几乎必然落成强制停止。同一个「等」的写法也各漂
各的：三处吞探针异常、一处不吞；两处用 `time.time`、一处用 `time.monotonic`；日志文案两套；
五处轮询间隔各调各的。

## 决策

**1. 一个等待原语：`bestseller_monitor/waiting.py` 的
`until(probe, *, timeout_sec, poll_sec, describe=None, cancel=None, on_wait=None)`。**

条件 = 探针的真值：返回它给出的第一个真值并原样交出去（四个调用点的结束值——`True`、观测
对象、Playwright 连接——都是真值）；假值继续等。`timeout_sec` 与 `poll_sec` 必填，各调用点
保持自己的现值（0.4／0.25／0.8／0.5／3 秒）。`time.monotonic()` 计上限、`time.sleep` 睡
轮询间隔，都经模块属性取用（沿用本仓 `patch.object(<模块>.time, …)` 的打桩习惯，测试可整块
替换 `waiting.time`）。到点记一行「等待「describe」超时(Ns)，按当前状态继续。」（沿用榜单页
现文案；`describe` 为空不记）并返回 `None`；`timeout_sec <= 0` 既不探测也不问取消，按超时
返回——保住「窗口 0 也要走一次出口」的既有行为。**末片切到上限为止**（`min(poll_sec, 剩余)`）：
一场等待的总时长不超过上限，睡眠迁移因此逐字保留「0.5 秒一片、末片切到剩余量」的切片语义。
每轮**先探测、后判到点**：条件恰在窗口末尾成立时算成立——响铃循环的既有次序（探针先于
到点判断）就是这样；榜单页原来的次序相反（先判到点再探测），那一轮多探测一次，随票 02 认账。

模块只依赖标准库与 `stop_request`：`listing`／`detail_visit`／`browser_pw`／`guard`／`delay`
依赖它，反向无依赖。

**2. 取消钩子默认接 `stop_request.check()`，与睡眠分片同一个判据。**

一轮 = 探针 → 问取消 → `on_wait`（如有）→ 睡；检查点在入口一次 + 每次睡前一次，与睡眠
分片「每片前问一次」同密度。`StopRequested` / `DayBoundaryReached` 原样上抛——两者已在
`pipeline._STOP_OUTCOMES` 登记，顶层按既有停止收尾；采集进程之外（界面、诊断工具、单测）
钩子未装，`check()` 是 no-op，零影响。探针抛出的异常同样原样上抛：吞异常是调用点写在探针
闭包里的知识（榜单页的谓词今天吞全部异常，必须保持——一次页面抖动不该终止等待）。
收敛后 `stop_request.check()` 的直接调用点只剩 `waiting.py` 一处。

**3. 四处循环迁移，公开行为不变**（签名、返回值、异常文案；日志文案没有测试钉着，允许变）。

榜单页三个函数内部换原语，`_POLL_SEC` 与 `WAIT_*_SEC` 常量不动（测试打桩继续生效）；端口
等待的 connect 重试换成原语，`last_exc` 记在闭包里，连接始终失败照旧抛 `RuntimeError`；
`Humanizer.sleep` 走纯等待的退化式 `until(None, timeout_sec=秒数, poll_sec=SLICE_SEC)`；
人工介入的确认窗口与响铃循环各是一段 `until`，次序（探针 → 不成 → 响铃 → 睡）逐字保留，
返回 `None` 即抛 `InterventionTimeout`。

**4. 窗口重置不进原语。** 详情可读轮询是四处里唯一带「人工介入解决后重开一个完整可读窗口」
的循环，用外层 while + `waiting.EXTEND` 哨兵表达：探针在介入被解决后返回这个真值哨兵，
原语结束本次窗口并把它交出去，外层再开一个完整新窗。

## 取舍（有意留在接口里的两条）

- **真值契约把 `browser_proc.wait_until_gone` 挡在外面。** 它是第五个同型循环但契约相反
  （等「探针不再是 True」，结束值 `False`/`None` 是假值）：要用真值契约表达得给探针套一层
  反转闭包，而它跑在界面进程里（没有钩子），迁移的收益只剩 locality。不迁，也不给原语加
  「反转」参数——结束值有两种读法就等于没有契约。（规格 §6 把它记在挂账，这里是那条挂账
  的理由。）
- **`on_wait` 为单一调用者留在接口里。** 今天只有人工介入的响铃循环用它（「还没等到时每轮
  要做的事」）。它收进原语是因为「探测 → 响铃 → 睡」的次序本身是那个循环的语义，留在调用方
  就是第五种循环写法。将来没有第二个使用者再考虑撤。

## 没动的（挂账）

- **`pipeline.py:403` 非停止的建立失败仍裸 traceback 退出**：给它停止家族以外的收尾是独立
  决定，不在本线。本线只保证停止路径更干净——端口等待被取消时 `StopRequested` 穿出
  `open_session`（它自带的清理照常：停 Playwright、终止自启进程、发布 UNKNOWN），由顶层
  停止收尾接住。
- **单次 Playwright 操作（`page.goto` / `wait_for_load_state` / `expect_popup`，最长
  `timeout_ms` 45 秒）仍然打不断**：ADR-0009 认过这笔账，本线不放宽也不承诺。
- **候选 07（采集入口的时间注入）不碰**（ADR-0027 挂起）。
- **不改任何判定语义**：停止协议、轮次、终态、失败率、详情机会、主动停顿的配额口径照旧；
  不缩短 Playwright 自身的 `timeout_ms`。

## 结果与代价

- **「暂停」的认领点从「检查点 + 长睡眠分片」扩到「页面等待」**：单次等待期间按暂停能在一两
  秒内被认领（上界是一个轮询间隔），不再等满窗口落强杀，也不留下被强杀的进程与浏览器。
- **一处有意的行为变化（可观测，随本条记账）**：暂停打断在飞的详情访问时，那张卡不再落一行
  失败。改前中途那次读取的失败会被记进失败率；改后中途即停。这是修正而不是损失（失败率不该
  为「没真的读完的那次」记账）；弹窗照关（点击路径 `_ingest` 的 `BaseException` 分支保证）、
  轮次保持可续跑、详情机会与账目复用不破。
- **代价**：`until` 成为四处的公共依赖——它的轮询／超时／取消语义错一处，四处一起错。它的
  契约因此由 `tests/test_waiting.py` 直接钉住，不靠打桩 `time.sleep` 间接观察；四处调用点的
  既有用例继续管各自的签名与异常文案。
- **收敛后的形状**：页面等待只剩一份实现，取消检查只剩一处直接调用点；以后新增等待不会再
  漏接停止请求。
