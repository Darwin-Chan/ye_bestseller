# 0003. 详情预算绑定轮次，耗尽即轮次终态

- 状态：已接受
- 日期：2026-09-11

## 背景

详情预算原先由各调用方用进程内计数器各自维护：点击式列表不检查上限，重启同一轮计数归零，因此它既挡不住超限，也能被绕过。尝试次数同样被拆开——初次访问与补采各从第 1 次算起，配置为 2 时实际访问可达 3 次。

## 决策

- 预算以「详情机会」为单位，即一个商品进入一次详情流程的名额；机会持久化在轮次上（`rounds.detail_budget_limit` 与 `detail_opportunities`）。
- 轮次首次申请时记录上限，续跑沿用同一上限，配置放宽不影响已开始的轮次。
- 同一商品的重试复用同一个机会；同日跳过会退还已占的机会，因此不消耗预算。
- 预算耗尽时立即结束本轮，落入终态「详情预算耗尽」：已抓数据保留，剩余商品留待下一轮重新发现。

## 结果

重启不再能绕过上限，重试也不再重复占用预算。代价是单轮可能因预算耗尽提前结束、需要下一轮补齐；该终态与「跨天中止」「失败率超限」并列，调用方必须各自处理。

相关词汇见 [CONTEXT.md](../../CONTEXT.md) 的「详情预算」「详情机会」「详情预算耗尽」；实现见 `bestseller_monitor/dedupe.py`。
