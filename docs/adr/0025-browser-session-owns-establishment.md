# 0025. 浏览器会话拥有建立与补偿清理

- 状态：已接受并实现
- 日期：2026-09-15

## 背景

ADR-0019 让诊断工具复用 `browser_pw.open_session()` / `close_session()`，并补了 CDP 连接超时的
浏览器收尾。但 `open_session()` 在启动 Playwright、取得默认 context、创建 page、设置 timeout 或
发布归属时仍可能在交付前抛错。调用方尚未拿到返回值，无法进入自己的 `finally`，于是“会话负责收尾”
只覆盖一个失败阶段。模块级启动状态还会被同进程的第二次打开覆盖。

## 决定

浏览器会话内部维护一次活动或待清理资源的私有账本。资源取得即登记；只有完整初始化并发布必要归属
后才向调用方交付。建立失败与正常关闭共用逆序清理，保留原始异常和仍需重试的精确句柄。同一进程的
第二个会话不得覆盖活动或待清理会话。

所有权必须来自本次仍存活的 Popen PID 与匹配的 OS creation proof；稳定 PID 的 capability 只能防
复用，不能产生所有权。profile handoff 到既有实例一律视为借用；端口、镜像名与当前配置不能授权终止。
无法证明归属时允许以 `UNKNOWN` 使用连接，但跨进程停止不能破坏该浏览器。

保留现有 open/close 公开形状、CDP 条件等待和各工具自己的页面等待。启动模式要求配置显式给出有效
浏览器路径；接管模式忽略路径。关闭失败只在当前进程内由重复 close 或下一次 open 重试，不增加后台、
退出扫描、跨进程互斥或持久清理表。

浏览器状态使用固定载荷，publisher 必须确认 target-aware CAS；身份已替换就中止建立。模块用短持有的
进程内锁防并发覆盖，慢 I/O 不在锁内；会话身份由本次的 `pw`/`br` 对象本身承担，迟到 close 因此命中
不了后继会话，不额外维护 token 字段。统一清理引擎取代 CDP 超时专属分支；无 proof 的端口强杀、
`own_pid` 分支、镜像名查询与旧测试兼容通道一并退役。

保证只覆盖已取得句柄的资源；外部副作用发生但 API 未交回句柄的原子性窗口不靠扫描恢复。终止后要用
原始句柄核验目标已 gone。借用会话保留失败的连接供精确重试，自有会话可在确认进程退出后收敛远端
资源。建立失败保持 `UNKNOWN`，`CLOSED` 只描述曾成功交付的会话。

## 预期结果与代价

调用方只处理已就绪会话，所有交付前失败都从同一处补偿；旧句柄和并发调用不能误关后继会话。代价是
同进程只允许一个活动会话、空浏览器路径不再使用内置 Edge 默认值，以及进程退出前仍未清理成功时可能
遗留一个浏览器。后者是明确的 safety-over-liveness 选择：不以恢复为名重新引入 PID/端口猜测。

完整状态、异常、清理顺序、兼容边界和测试矩阵见
[`browser-session-lifecycle` 规格](../../.scratch/browser-session-lifecycle/spec.md)。

## 与既有 ADR 的关系

- 扩展 ADR-0019 的共享会话决定，但不改写其历史诊断工具范围。
- 遵守 ADR-0024 的 target-bound browser proof：`UNKNOWN` 不产生破坏性授权，端口不是 ownership。

## 实现边界

生命周期账本留在 `browser_pw.py`，OS capability 留在 `browser_proc.py`，不增加数据库迁移或第三个
浅模块。实现删除专属失败分支、平台默认路径、端口终止回退和旧 GUI 测试兼容通道；自动化只使用 mock，
真实 Edge 黑盒冒烟可选且不得执行无 proof 强杀。

## 收口与挂账

2026-09-15 收口补跑了缺失的 Spec 轴审查，并清掉三处「文档有、实现在别处」的残留：从未被读取的
`token` 字段、无调用方的 `own_pid` 分支与镜像名查询、以及只为旧镜像名行为打桩的 GUI 用例。已关闭
句柄的保留上限（16 个会话）写进设计与代码常量。

终止后的验证等待曾是一条已知偏差：规格要求「终止命令成功后仍用原始句柄验证同一目标已退出，短验证
等待是模块内部上限」，实现却是终止后立即探测，真实的 `TerminateProcess` 竞态会把已终止浏览器记成
`CLEANUP_PENDING`、把本该完成的停止显示成「待清理」（方向安全、可自愈）。2026-09-15 经
`grill-with-docs` 收敛结案：判据不变，只加一个有界的等待窗口——仍是同一个原始句柄，2.0 秒上限、
0.1 秒间隔，探到已退出立即返回；不可核验照旧保留、不重试也不升级；两条终止路径（capability 与
会话自有 Popen）共用一个三态等待帮助函数；不增加配置项，所有权判据与授权规则不动。设计见规格的
「终止后的有界验证等待」一节，实现与自动化验证已完成（会话层收尾与跨进程关闭都改用
`browser_proc.wait_until_gone()`）。
