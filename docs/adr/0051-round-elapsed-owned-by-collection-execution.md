# 0051. 已抓时长属于轮次，由采集执行产出，一个 module 持有

- 状态：已接受（设计）；2026-10-08 grill、测试接缝、spec 与三票方案已确认，工单已发布；随后用户授权实施 01；01/02 已实现并通过各自独立复审/隔离全量验收，03 未实施，整项未关闭。
- 日期：2026-10-08（Asia/Shanghai）
- 范围：2026-09-23 架构候选 #elapsed；只替代 elapsed 的会话归属，不全面重构界面/准备状态。

## 背景与证据边界

归档架构审查提出 GUI 分散维护已抓时长、结账路径不足、结果页混用总耗时和墙钟直读问题。
实施前基线 c8d0fb9 已重新核实：GUI 分散操作累计和起点，暂停请求时结账；结果页仍优先使用轮次跨度。
采集公共入口之前还有准备，不能把整个子进程寿命直接称为有效采集时长。

以上是设计阶段的源码控制流证据与风险推论。01 的测试随后复现了过程页不读已保存采集时长、公共入口缺少计时接缝及基础检查点；已通过真实 SQLite 和可推进时钟修复。
这不证明所有退出方式都有故障；崩溃/强杀现场和完整跨入口矩阵仍未验证，不沿用旧报告行号作为当前结论。

ADR-0048 的正常确认关窗已接入中止与停止监督链路，等待收尾再退出；正常关窗不是 GUI 强杀。
本设计接现有链路，不重新实现关窗，也不把其自动化通过当作 elapsed 验收或原生人工验收。

## 决策

### 定义与归属

已抓时长是本机数据库中某轮有效采集执行段的累计，不是轮次开始到结束的墙钟跨度。
同轮恢复累加，新轮隔离；采集 2 分钟、暂停 10 分钟、再采集 3 分钟，累计 5 分钟。

不计开轮前准备（包含子进程内部准备）；准备完成且轮次确定后的有效执行计入，包含浏览器
启动/连接、页面加载/读取、人工验证、重试退避、自动节流。停止请求后仍活跃的执行计入；
执行已经结束后仅 GUI 核验/浏览器归属清理不计。用户暂停间隔、未进入执行的失败/忙碌拒绝不计。

轮次持有数字，采集执行贡献时间段。GUI 只显示；命令行执行、重开 GUI、接管和历史结果读取
同一份本地事实。正常确认关窗按现有中止链路在有效执行结束时结账，不以窗口消失为段终点。

### 一个持有者与窄 interface

一个计时 module 收起开始、段累计、检查点、幂等结账、完整性解释和轮次取值知识。
调用方表达生命周期，不掌握累计公式。views 只格式化解释好的事实，不再选轮次跨度冒充时长。
具体 interface 命名、内部类与 schema 在实现中确定，不把旧报告示意当作强制设计。

deletion test：拿掉 module 后，累计、完整性、持久化、跨执行与幂等知识会重新散回调用方。
若只是搬 GUI 私有字段、保留原调用方的公式，或 views 仍解释两个不同量，则不算深化完成。

### 时钟、持久化与可证明范围

活跃段差值用单调时钟；基点只属于产出该段的进程。不将不同进程或重启前后的单调基点相减。
持久化已计算出的累计秒数、段身份、轮次归属与完整性；墙钟只作可读时间戳/调查，不补未知时间。

采集侧活跃检查点目标约每秒更新，叠加页面刷新可短暂滞后；不是异常情况下最多丢 1 秒或硬实时
承诺。GUI 只显示成功保存的快照，不从收到快照的时刻继续外推。活跃快照滞后不等于历史缺失。

正常完成、协作暂停、中止、确认关窗及能走到计时收尾的异常，在结束并成功保存后完整结账。
强杀、崩溃、最终保存失败仅保留最后成功记录的下界；GUI 迟到发现退出的时间不能补入。
GUI 强杀而采集继续运行，不自动结束执行；计时保存成功也不能被当作停止收尾完成。

每个执行段有唯一身份，绑定轮次及现有进程归属证据。检查点保存该段累计值，重复结账幂等，
读取不写计时状态；已结账不再增长。迟到事件不能结账新段，重复被拒启动不清旧累计。

### 展示与旧数据

过程/结果两页统一“已抓时长”：完整记录显示确定值；未知历史或未记录尾段显示“至少”及说明；
完全无记录显示“未记录”。不新增轮次跨度指标，不能用默认零掩盖未知。

没有计时记录的旧轮次不反推。旧轮后续新段可证明，但整轮仍只能为下界；新段完整不能消除
旧缺失。新轮记录与同轮续跑须正确区分。只使用本地数据库，不扩展交换包或跨机器汇总。

## 对旧决策的替代范围

- 仅替代 ADR-0011 中“本次已抓时长是 GUI 会话事实”的归属；views 的 module 划分、
  调用方提供时刻/连接、公开取数 seam 和其他会话事实保留。
- ADR-0047 只恢复 elapsed 的设计与后续实施；prep-owner 和其他挂起候选保持原状态。
- ADR-0048、停止监督、准备阶段、超时、终态及进程/浏览器归属规则保留。
- 本 ADR 是已接受设计；01/02 已验收，03 尚未完成，不宣称整项实现已完成。

## 取舍与否决方向

- 接受本地数据库的计时存储、检查点及执行身份复杂度，换取会话独立与可证明的恢复。
- 接受显示短暂滞后，避免 GUI 外推复制第二套计时知识。
- 接受下界与未记录，而非伪造精确历史；硬杀时未记录尾段无法恢复。
- 不采用整个轮次跨度或子进程寿命：前者含暂停，后者含准备，均不符合已确认定义。
- 不仅封装 GUI stopwatch：无法支撑 CLI、GUI 强杀期间记录、重开/历史及跨执行完整性。
- 不增加通用时钟/状态机或全面页面契约，不借机处理 prep-owner 或候选 07。

## 测试与交付

用户已确认公开 seam：GUI 生命周期/页面取数、公共采集执行入口、计时 module 窄 interface、
views/页面消费。真实 SQLite、可推进时钟及现有进程/停止 adapter，逐条红→绿；不依赖 sleep
或私有计时字段。行为失败复现与源码推论、模拟退出与真实操作系统现场分别标注。

实施后在规范隔离副本执行一次不带 -f 的分段全量，证据写主仓，记录合计/对账/结论及绝对路径。
完成双轴审查；关闭票前记录副本、证据和保留/可删除候选/暂留待确认，不自动删除。

发布工单时尚无实现。随后用户授权 01：elapsed module 提供 begin / Segment.checkpoint / Segment.settle / read，差值由执行进程单调时钟产生，本机 SQLite 保存段累计。01 只接现有采集检查入口，不提供约每秒调度保证。02/03 仍待实施；01 的验收及限制见后续单票交付记录。
