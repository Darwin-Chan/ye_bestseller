# 0005. 轮次身份绑定北京日期与店铺范围

- 状态：已接受
- 日期：2026-09-12

## 背景

轮次表只记 `started_at`，没有日期列；店铺范围也不是固定事实，而是每次启动往 `shop_rounds` 追加。`start_or_resume()` 因此只能返回「任意进行中的最后一轮」，续跑既不比较日期、也不比较店铺范围，与 [CONTEXT.md](../../CONTEXT.md) 的两条 Rules（轮次严格绑定北京时间日期、续跑不得增删店铺）不符。

跨天检查也拦不住：判据是「当日时刻 ≥ 23:55」，过了零点恒为假。真实运行数据里已经发生过——轮次 #16 从 2026-09-08 23:13 跑到 2026-09-09 01:22，其中 9/9 写入 1044 条快照与 953 条事件；全库 23 个轮次只有这一轮跨天。

## 决策

- 轮次身份 = 北京日期 + 店铺范围。日期在启动时确定并落库；范围以 `shop_rounds` 的整行集合承载，启动时一次写全，续跑以轮次自身的店铺名称与地址为准，不再读 shops.csv 增删。
- 同一日期、同一范围才可续跑。跨日启动时先把过期轮次按跨天终态收尾、再新建轮次，并在返回值里告知调用方；同日但范围不同则拒绝，不并入、也不自动换轮。
- 轮次终态是封闭集合，用稳定标识表达，不再靠中文状态串与 note 文本互相区分；终态写入后不可改写，同一终态重复收尾可忽略，不同终态不得覆盖。
- 截止线与跨日判定由轮次日期与当前北京日期比较得出，不只看当日时刻；检查点包括提交之后、进入详情之前、每家店榜单开始之前。时钟由调用方注入，模块不读挂钟。
- 失败率超限与详情预算耗尽的检测仍归采集流程，轮次模块只拥有终态身份与转换规则。

## 结果

调用方（GUI 的三处轮次查询、启动页摘要、`tools/summary.py`）改为经轮次模块读取轮次事实；`rounds.status` 列删除，「进行中」由「没有终态」表达；轮次改由采集子进程创建。

代价有两处：同日换店铺范围从「静默并入」变成「拒绝」，用户必须先中止本轮；续跑不再读 shops.csv，对进行中的轮次改配置不再生效——这正是「启动时固定」的本意。

历史轮次 #16 不拆分：它的库存日期按实际采集时间写入，差分与同日去重都按日期键，不受影响；拆轮要重写近两千行且无法回滚，只会把一个真实发生过的过程改成看起来整齐的记录。

相关词汇见 [CONTEXT.md](../../CONTEXT.md) 的「轮次日期」「轮次店铺范围」「续跑」「轮次终态」；工单为 IS-44。
