# 01: 统一准备接纳、预算与开窗等待

**What to build:** 从Api请求准备，经单一持有者执行，到main等待建窗及UiState消费事实的一条完整路径；重复请求不启动额外任务，预算只从接纳时计算，准备落定后开窗不等缺口扫描。

**Blocked by:** None (can start immediately after explicit implementation authorization).

**Status:** ready-for-agent

- [ ] 单一准备模块持有接纳、单调截止点、等待、异常落定和扫描编排；快照区分未开始、预算内运行、超预算运行、落定、试采绕过。Api/views不继续拼装旧四字段知识。
- [ ] request原子接纳；直接prepare、retry及交叉重复在未落定时均拒绝，超时也不排队、不重跑、不重置截止点。重复Api.prepare记录并返回None；retry保留ok/error。
- [ ] 接纳时建立30秒单调截止点，派发延迟计入；29.999/30/30.001及墙钟回拨可控验证，后加入等待者只有剩余预算。
- [ ] wait_for_open只等指定运行落定/剩余预算；wait_for_finish等同次worker连同扫描，保持同步prepare语义；已落定事实优先于过时超时判断。
- [ ] 实际main经公开Api准备辅助入口等待，已有运行可显式等待同次；删除其私有事件/线程/预算编排。UiState消费单一快照，JSON不回退。
- [ ] 普通异常与派发失败落定并唤醒、可再试；finally通知worker完成；BaseException清理后保留传播。main正常及异常等待均有集成测试。
- [ ] 每次独立运行凭据及落定/完成通知；外来owner凭据拒绝。A落定扫描未完可接纳B，A等待/扫描/完成不得改写B。基础身份安全本票即成立。
- [ ] 准备及扫描绑定原配置、调用方连接能力和周；不自行按路径开库，不借用可变Api连接。正式owner与试采bypass选择及模式同步基础本票成立，等待不持Api锁。
- [ ] 落定先于扫描，扫描/日志失败不撤销结果；可控挂起扫描时窗口仍创建。运行中包括超时后仍保留模式切换限制。
- [ ] 正常开窗、重复请求、精确预算、异常/派发失败及基本身份/上下文隔离的公开接口测试通过；不退化现有计划、elapsed、关窗/停止行为。
