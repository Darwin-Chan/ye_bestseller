# 02: 所有暂停状态确认后升级为中止

Status: ready-for-agent

**What to build:** 用户在暂停停止中、暂停收尾中或完全暂停时关窗，全部先看到符合真实状态的确认。确认后放弃本轮并等待必要收尾；取消保持原暂停流程或暂停状态。即使没有采集进程，也不能跳过确认或用空操作成功替代人工放弃终态实际写入。

**Blocked by:** 01：采集中确认关窗，中止并等待收尾。

## Acceptance criteria

- [ ] 覆盖所有正常关窗入口和页面；三个暂停阶段均先确认，不能将“已暂停、无采集进程且无待完成收尾”解释成无确认直接关闭。
- [ ] 文案按真实阶段显示“本轮正在暂停，采集进程正在停止”“本轮正在完成暂停收尾”或“本轮已暂停”；共同说明中止的后果、数据保留与不可续跑，不把进程已退出描述为仍在采集。
- [ ] 默认取消，取消、关闭确认框或确认框显示失败均保留主窗口且不升级为中止；暂停停止中或收尾中继续原操作，已暂停保持暂停，不自动恢复采集。
- [ ] 暂停请求已发出但进程仍在时，确认后将已授权轮次升级为人工放弃，复用原停止与收尾，完成后关闭，不重复发起停止或扩大目标范围。
- [ ] 采集进程已退出但暂停收尾未完成时，确认后实际写入人工放弃，继续驱动原收尾；完成后关闭，不重新启动停止任务、不扩大浏览器处置范围。
- [ ] 已完全暂停、无进程且无待完成收尾时，确认后实际写入并核实对应轮次的人工放弃终态，已提交数据保留、本轮不可续跑，再关闭窗口。
- [ ] 不将缺少 GUI 记忆轮次或采集身份时的中止入口空操作成功当成终态完成。必须可靠关联明确暂停的轮次；关联不可靠或写入失败时保留窗口、说明原因并允许安全重试。
- [ ] 不凭进程消失或查询到任意无终态轮次就认定明确暂停，不制造或放弃未经确认的其他轮次，不绕过轮次终态不可改写约束。
- [ ] 确认后的等待显示中止状态、保持窗口响应、禁止开始与续跑；重复关闭不重复确认或停止。沿用 01 的目标授权、安全失败和已有收尾驱动。
- [ ] 已成功写入人工放弃后，即使后续停止或收尾报告失败，也不回滚为暂停或可续跑；提示不得将失败描述为暂停成功。
- [ ] 三阶段分别有确认、取消和显示失败的关窗集成测试；断言窗口、真实终态、数据保留、原暂停行为、停止/收尾完成及无重复停止等外部结果。
- [ ] 有完全暂停且入口空操作成功、无法可靠关联暂停轮次、终态写入失败的测试；这些场景不提前关窗或误放弃其他轮次。
- [ ] 本票相关测试通过且 01 行为回归通过，有可复核记录；不改变暂停按钮本身保留本轮续跑机会的含义。

## Boundaries and handoff

- 父规格为本功能目录中的《采集程序正常关窗：确认、中止本轮并等待收尾》，遵循 ADR-0048。最终暂停政策只有“先确认、确认后中止”，先前无确认或仅等待而不升级的解释均失效。
- 依赖 01 已提供统一关闭协调、确认安全默认、非阻塞停止收尾与失败保留能力，复用同一机制，不建立第二套暂停关窗停止引擎。
- 确认期间及关闭等待期间的完整跨入口目标变化体验由 03 集成；本票不得扩张旧授权或缺失基本目标保护。
- 不新增关闭后继续保留该暂停轮次的产品路径，不重做异常恢复、进程发现或轮次模型，不改变浏览器归属和清理边界。
- 实施收尾及工单关闭遵守项目全量测试、隔离副本、证据和目录处置规范。
