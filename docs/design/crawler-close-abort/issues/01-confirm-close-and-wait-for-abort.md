# 01: 采集中确认关窗，中止并等待收尾

Status: ready-for-agent

**What to build:** 用户在采集程序的任意页面通过正常入口关窗时，先确认中止本轮；确认后保留已提交数据，将本轮记为人工放弃、不可续跑，等待停止与既有收尾完成后自动关闭。取消保留窗口且采集继续。已结束或未开始任务的场景直接关闭，不制造或改写终态。

**Blocked by:** None (can start immediately).

## Acceptance criteria

- [ ] 右上角 ×、Alt+F4、任务栏关闭统一进入正常关窗策略；判断依据是实际采集、明确暂停轮次和待完成收尾，而不是当前显示页面。
- [ ] 采集中需要确认，包括节奏休息与等待人工验证；确认前主窗口不销毁。提示明确效果同“中止本轮（放弃）”、已提交数据保留、本轮不可续跑。
- [ ] 默认选择取消；按钮表达“中止并关闭”与“取消”，系统按钮不可定制时正文补足动作解释。不提供“关闭但后台继续”选项。
- [ ] 取消、关闭确认框或确认框无法显示时，保留主窗口，本次关窗不发起中止，原采集继续；对话框异常不视为自动确认。
- [ ] 确认后复用现有中止语义及停止监督机制：人工放弃终态先行、已提交数据保留、不再可续跑；不另造一套直接杀进程的关窗机制。
- [ ] 收到中止请求或返回请求成功不等于停止完成；持续驱动停止与既有收尾，在完成前保持主窗口和必要驱动存活，不依赖即将销毁的页面继续轮询。
- [ ] 等待时窗口保持响应并显示“正在中止采集，请稍候…”；开始和续跑请求被拒绝。重复关窗不叠确认框、不重复启动停止任务，最终受控关闭不重新弹确认。
- [ ] 协作停止、既有超时强制停止兜底、目标冻结与身份核验保持有效；不得按裸 PID 或未经核验的目标强制结束。浏览器清理保持既有归属、有限重试和完成判定，不保证关闭所有浏览器。
- [ ] 数据库写入、目标核验或强制停止失败时保留窗口，说明原因并允许安全重试；既有核验和收尾继续驱动。已写入人工放弃不回滚为暂停或可续跑。
- [ ] 已在中止或中止收尾中的目标不再次确认或停止，继续原收尾后关闭；中止已完成则直接关闭并保留终态。
- [ ] 本轮自然结束且无进程、无待完成收尾时直接关闭，不改成人工放弃；尚未开始任务且无采集、明确暂停轮次或收尾时直接关闭，不制造轮次记录。
- [ ] 确认授权只覆盖原目标；基础实现即保持冻结目标与拒绝未经授权处置的安全边界。最终关窗前核对目标与待完成收尾，不因后来出现的新目标静默关窗。跨入口及完整竞态体验由 03 扩展，不以此为由先交付不安全实现。
- [ ] 增加关窗事件集成测试：使用假窗口及确认结果、真实轮次逻辑与临时数据库、可控进程运行时与确定性时钟，验证确认、取消、数据和终态、等待收尾、失败保留、重复关闭与直接关闭分支；主要断言外部行为，不绑定内部字段或线程形式。
- [ ] 替换旧“提示后关闭并继续后台采集”的相反行为测试；相关单文件或单用例测试通过，有可复核记录，不以保住旧测试为由保留旧政策。

## Boundaries and handoff

- 父规格为本功能目录中的《采集程序正常关窗：确认、中止本轮并等待收尾》，遵循 ADR-0048。双锁、轮次终态不可改写及既有停止归属保护继续有效。
- 暂停三阶段的完整交付由 02 承接；在其完成前，遇到明确暂停状态不得误用“无进程直接关闭”或静默放弃，无法按最终规则处理时保留窗口。该过渡保护不是最终暂停产品政策。
- 03 承接跨入口目标识别、授权变化与全部竞态场景，并完成整体验收。每票自身的安全保护和对应测试不可后移。
- 不要求新增数据库字段，不做广泛重构，不改变分析或交换程序的关窗政策，不涵盖任务管理器强制结束、断电等非正常退出。
- 必要的小重构随本票行为完成；实施收尾及工单关闭遵守项目全量测试、隔离副本、证据和目录处置规范。
