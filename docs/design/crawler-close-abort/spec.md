# 采集程序正常关窗：确认、中止本轮并等待收尾

Status: ready-for-agent

- 日期：2026-10-08（Asia/Shanghai）
- 需求状态：产品规则与测试方案均已获用户确认，待实现与验收。
- 执行边界：本次只落规格文档；用户明确要求“先不要动代码”。`ready-for-agent` 表示规格已就绪，不表示现在授权实现。
- 决策依据：ADR-0048；先前澄清记录中的所有暂停关窗分支，以“先确认，确认后中止”为最终规则。

## Problem Statement

用户关闭采集程序时，需要明确知道本轮是否会结束，以及关闭动作是否已真正停止采集。当前关窗仍采用提示后让采集后台继续的旧政策，与用户期望的“确认关闭后，效果同中止本轮”不符。

暂停不等于本轮结束。暂停停止中、采集进程已退出但暂停收尾中、暂停已完成都保留本轮续跑机会；用户希望关闭程序时也先确认，确认后明确放弃本轮，而不是悄悄留下可续跑的暂停轮次。反过来，自然结束的轮次不应仅因关闭窗口而被改成人工放弃。

关闭还必须等待必要的停止与既有收尾，不能把“收到中止请求”当成“中止完成”，不能误停替换后的目标，也不能在停止失败时悄悄退出。

## Solution

所有正常关窗入口统一处理，包括右上角 ×、Alt+F4、任务栏菜单关闭；判断依据是实际采集目标、明确暂停的轮次与未完成收尾，不取决于当前显示哪个页面。

### 关窗行为矩阵

| 实际状态 | 是否确认 | 确认或关闭后的行为 |
| --- | --- | --- |
| 正在采集，包括节奏休息、等待人工验证 | 是 | 确认后中止本轮，等待停止与收尾完成，自动关闭 |
| 已请求暂停，采集进程仍在 | 是 | 确认后从暂停升级为中止，等待原停止与收尾完成，自动关闭 |
| 采集进程已退出，暂停收尾尚未完成 | 是 | 确认后写入人工放弃，继续原收尾；不另起停止任务；完成后关闭 |
| 已暂停，无采集进程且无待完成收尾 | 是 | 确认后实际写入并核实人工放弃终态，再关闭 |
| 已在中止或中止收尾中 | 否，不重复确认 | 继续原中止与收尾，完成后关闭；不得重复发起停止 |
| 中止与收尾均已完成 | 否 | 直接关闭，保留已有终态 |
| 本轮自然结束，无采集进程与待完成收尾 | 否 | 直接关闭，保留真实终态，不改成人工放弃 |
| 尚未开始任务，无采集进程、明确暂停轮次与待完成收尾 | 否 | 直接关闭，不制造轮次或人工放弃记录 |

该矩阵不是“过程页面关窗一律中止”：自然结束、已经中止完成、未开始任务等情况不新写人工放弃。进程消失也不是明确暂停的充分证据；不得把任意无终态轮次自动认成已暂停。

### 确认与取消

- 确认框说明：关闭将中止本轮，效果与“中止本轮（放弃）”相同；已提交的采集数据保留，本轮不可续跑。
- 首句按真实状态显示“采集正在进行中”“本轮正在暂停，采集进程正在停止”“本轮正在完成暂停收尾”或“本轮已暂停”，不得把已暂停描述成正在采集。
- 按钮表达“中止并关闭”和“取消”，默认选择取消。若系统按钮标签不能自定义，正文必须清楚解释对应动作。
- 取消、关闭确认框或确认框无法显示，均不授权中止，也不关闭主窗口。采集中继续采集；暂停停止或暂停收尾继续原操作；已暂停保持暂停，不自动恢复采集。
- 不提供“关闭但后台继续”第三个选项。

### 确认后

窗口保持响应，显示“正在中止采集，请稍候…”；禁止开始或续跑。实际停止与既有收尾完成，并确认没有未经授权的新目标后，自动关闭。

写入失败、目标身份暂不可确认或强制停止失败时，保留窗口，说明原因并允许重试；继续驱动已有停止核验与收尾，不绕过身份保护。已写入人工放弃后不回滚为暂停或可续跑。

## User Stories

1. 作为正在采集的用户，我希望正常关窗前看到确认提示，以便知道关窗会中止本轮。
2. 作为使用右上角 × 的用户，我希望关闭动作受同一策略保护，以便避免误关造成未预期的中止。
3. 作为使用 Alt+F4 或任务栏关闭的用户，我希望获得与 × 相同的行为，以便关闭入口不会改变后果。
4. 作为切换到其他页面的用户，我希望程序仍按真实采集状态判断关窗，以便页面切换不会绕过保护。
5. 作为采集暂时休息或等待人工验证的用户，我希望这些阶段仍按采集中处理，以便不会误以为本轮已经结束。
6. 作为已请求暂停但进程仍在的用户，我希望关窗先确认再升级为中止，以便保留取消后的暂停选择。
7. 作为处于暂停收尾中的用户，我希望关窗先确认再放弃本轮，以便进程退出不代表我已经同意放弃。
8. 作为已经完全暂停的用户，我希望关窗先确认再写入人工放弃，以便清楚知道续跑机会将被取消。
9. 作为取消关窗的用户，我希望窗口保留且本次操作不发起中止，以便继续原来的工作。
10. 作为采集中取消关窗的用户，我希望采集继续，以便取消不会产生额外副作用。
11. 作为暂停停止或收尾中取消关窗的用户，我希望原暂停流程继续，以便不被误升级为中止。
12. 作为已暂停并取消关窗的用户，我希望保持暂停而不是自动续跑，以便由我决定是否继续。
13. 作为误触确认框的用户，我希望默认按钮是取消，以便降低误放弃本轮的风险。
14. 作为关闭确认框或遇到对话框故障的用户，我希望程序按未确认处理，以便故障不会替我授权中止。
15. 作为确认关闭的用户，我希望本轮效果与中止按钮一致，以便没有两套不同的放弃规则。
16. 作为确认关闭的用户，我希望已提交的数据保留，以便本轮中止不会删除已经得到的结果。
17. 作为确认关闭的用户，我希望本轮变为人工放弃且不可续跑，以便关闭结果明确而非隐式暂停。
18. 作为等待停止的用户，我希望窗口保持响应并显示进度状态，以便知道程序正在收尾而不是卡死。
19. 作为正在等待关闭的用户，我希望不能再开始或续跑，以便不会在关闭途中启动新任务。
20. 作为重复点击关闭的用户，我希望不出现多个确认框或停止任务，以便不会重复处置同一目标。
21. 作为已经点击中止本轮的用户，我希望关窗等待原中止完成，以便无需再次确认或重新停止。
22. 作为本轮自然结束的用户，我希望关窗保留真实终态，以便完成记录不被改成人工放弃。
23. 作为尚未启动采集的用户，我希望直接关闭窗口，以便没有多余提示或虚构记录。
24. 作为本机另一个入口启动了采集的用户，我希望可识别的目标也受相同关窗策略约束，以便命令行或旧界面启动不会留下未预期的后台采集。
25. 作为确认期间目标发生变化的用户，我希望重新确认新目标，以便旧授权不会误停后来启动的采集。
26. 作为确认期间原目标自然结束的用户，我希望保留其真实终态，以便迟到的确认不会抹掉完成结果。
27. 作为遇到数据库或停止故障的用户，我希望窗口留下并说明原因、允许重试，以便知道关闭尚未完成并能处理问题。
28. 作为已有人工放弃记录的用户，我希望停止失败也不让本轮重新可续跑，以便不可撤销的中止结果保持一致。
29. 作为使用自己的浏览器的用户，我希望清理继续遵守浏览器归属边界，以便关窗不会误关无关浏览器。
30. 作为等待程序退出的用户，我希望停止与收尾真正完成后自动关闭，以便不用再次操作，也不会提前丢失收尾驱动。

## Implementation Decisions

1. **统一关窗协调。** 将正常关闭事件纳入同一策略，协调确认、授权校验、既有中止、收尾与最终关闭；不按页面分别定义规则，不新增独立停止引擎。
2. **真实状态分类。** 综合可靠的采集身份、明确暂停的轮次、终态和待完成收尾判断。暂停是保留轮次的停止语义，不是操作系统挂起进程；不能仅因无进程就认定为暂停。
3. **复用中止语义。** 以现有中止入口与停止监督机制为基础，写入人工放弃，保留已提交数据，使本轮不可续跑；有活跃采集时沿用终态先行与协作停止，超时沿用既有强制停止兜底和身份校验。
4. **请求与完成分离。** 中止请求被接受不能直接放行关窗。必须持续驱动停止与收尾直至完成，不依赖即将被销毁的页面继续轮询；关闭等待不能阻塞界面响应。
5. **暂停升级只改变已授权轮次的结局。** 暂停停止中或暂停收尾中，确认后升级为人工放弃，复用原停止与收尾；进程已经退出时不得再启动重复停止任务或扩大浏览器处置范围。取消不改变原暂停请求。
6. **无进程暂停分支核实终态。** 已完全暂停时也先确认，确认后必须实际写入并核实对应轮次的人工放弃终态。现有中止入口在缺少目标信息时可能空操作成功，不能以此作为关窗完成依据；写入失败不得关窗。
7. **冻结授权对象。** 确认授权仅覆盖弹框时的采集目标或明确暂停的轮次。进程目标沿用 PID、启动身份与归属证明，不仅按 PID 判断。目标改变时保留窗口、提示变化并要求重新确认，旧授权不得转移到新目标。
8. **处理自然结束竞态。** 弹框期间原目标自然完成时保留真实终态；没有新目标及待完成收尾时可关闭。已有收尾则等待，不将自然完成改成人工放弃。最终自动关闭前再次核实状态与授权范围。
9. **覆盖已有目标范围。** 包括当前界面启动、命令行启动、先前界面留下的可识别采集；不限定为当前界面的子进程，也不绕过现有目标可信性要求。启动后尚未取得可靠身份时保留保护。
10. **重入与关闭守卫。** 同一时间只允许一个关窗确认；确认后或已有中止时不重复发起停止。进入关闭等待后禁止开始与续跑，最终完成后允许受控关闭，避免自动关闭再次弹框。
11. **失败保留与重试。** 确认显示失败采取未确认策略；写入、身份核验或强制停止失败保留窗口并提示原因，允许安全重试。已写入人工放弃不回滚，失败不能伪装成暂停成功。
12. **保持既有清理边界。** 浏览器归属、条件清理、有限重试与错误报告沿用现有规则；不是保证关闭所有浏览器，更不能因关窗扩大清理权限。
13. **保持既有领域约束。** 不合并界面锁与采集锁；不破坏轮次终态不可改写、身份登记与目标冻结。当前没有必须新增数据库字段或更改轮次终态定义的需求，优先复用已有领域状态。
14. **政策替代与实现状态分离。** 新政策依 ADR-0048，在实现收口时替代旧的关窗后继续采集政策；保留旧决策的双锁和身份保护。只有实现与验证后才同步领域上下文的运行行为说明，本规格不将新行为描述为已上线。

## Testing Decisions

### 已确认的测试入口

2026-10-08，向用户提出以“用户触发关闭窗口”为统一高层测试入口：模拟窗口及确认结果，使用真实轮次逻辑与临时数据库，控制采集进程状态、停止运行时与确定性时钟。用户回复“好的”，确认该方案。

优先在这一条关窗事件集成缝上验证整体外部行为：窗口是否保留或销毁、是否展示正确确认、轮次真实终态与数据是否保留、停止收尾是否完成、开始或续跑是否被拒绝，以及新目标是否受到保护。不以私有字段、内部函数调用顺序或线程实现形式作为主要断言，不额外造一套停止机制。

### 既有设施与先例

- 采集 GUI 测试已有假窗口、可控停止时钟、真实接口与数据库测试，以及跨会话中止场景，作为主要扩展基础。
- 分析窗口关闭测试已有取消保留、重复关闭、停止收尾先于窗口释放、关闭期间出现新任务等先例；仅借鉴测试结构，不改变分析程序关窗政策。
- 既有停止目标与停止请求测试覆盖 PID 复用、目标替换、不可核验身份、强制停止失败及浏览器清理边界；复用其可控运行时与回归断言，必要时补充行为用例，不为关窗另设独立领域机制。
- 原有“关窗提示后让采集继续”的测试属于被替代政策，实现时应调整为新要求，而不是为保住旧测试保留相反行为。

### 必须覆盖的验收场景

| 场景组 | 外部行为断言 |
| --- | --- |
| 所有正常关闭入口、不同页面 | 同一状态得到相同策略，不绕过确认或收尾 |
| 采集中、节奏休息、等待人工验证 | 需要确认；确认前主窗口不销毁 |
| 暂停停止中仍有进程 | 取消继续暂停；确认变成人工放弃，停止与收尾完成后关闭 |
| 进程退出但暂停收尾中 | 取消不升级；确认写人工放弃并继续原收尾，不启动重复停止 |
| 完全暂停且无进程、无收尾 | 仍需确认；真实终态写入成功后才关闭，不能接受空操作成功 |
| 确认取消、关闭对话框、显示失败 | 保留窗口，不授权中止；原采集或暂停行为不变 |
| 确认文案与默认选择 | 反映真实阶段，说明数据保留与不可续跑，默认取消 |
| 活跃采集确认关闭 | 人工放弃、不再可续跑、已提交数据保留；请求被接受不等于窗口立刻销毁 |
| 停止等待与超时兜底 | 等待时窗口可响应；协作停止与既有超时兜底均受身份保护 |
| 重复点击、模态框重入 | 不叠确认，不重复停止，不提前退出 |
| 已在中止或中止收尾中 | 不再确认，完成原收尾后关闭 |
| 自然结束、中止完成、未开始任务 | 直接关闭，已有终态不被改写，不新增虚构记录 |
| 无进程但无明确暂停证据 | 不凭无进程将未知轮次认作已暂停并写人工放弃 |
| 非当前界面启动的可识别目标 | 遵循相同确认和中止语义，目标范围不扩大 |
| 确认期间原目标自然完成 | 保留真实终态；无新目标和收尾才可关闭 |
| 确认期间及等待期间目标替换 | 旧授权不误停新目标；保留窗口并提示需重新确认 |
| 同 PID 不同启动身份、身份暂不可确认 | 不误杀、不跳过核验、不静默关窗 |
| 数据库写入失败、强制停止失败 | 窗口保留、原因可见、允许重试；已有人工放弃不回滚 |
| 关闭等待中开始或续跑 | 请求被拒绝，不产生新任务 |
| 浏览器归属与有限清理重试 | 不误关借用或无关浏览器；遵循既有收尾完成判定，不无限扩大清理 |

后续实现阶段先跑相关单文件或单用例测试，最终按项目规范在隔离副本中串行分段跑一次全量，并保留主仓票证据与对账结果。本次仅规定测试方案，未修改测试、未执行测试、未创建隔离副本。

另需后续 Windows 人工验证：×、Alt+F4、任务栏关闭的实际接线；确认框默认取消及关闭对话框；不同状态的中文提示；等待期间窗口响应与自动关闭。集成测试不替代原生窗口交互验收。

## Out of Scope

- 本次不实现功能，不修改产品代码、测试代码、运行配置或壳，不提交代码，不启动真实采集。
- 不自动拆实施工单，不因规格标记 ready-for-agent 而自动开始实现。
- 不保证任务管理器强制结束、系统强制终止、断电等非正常退出能确认或完成收尾。
- 不提供“关闭窗口但后台继续”选项，不把关闭确认后的中止降格为暂停。
- 不改变暂停按钮本身保留本轮续跑机会的含义，不增加关闭后仍保持该暂停轮次的产品路径。
