# prep-owner：开轮前准备运行态持有者

Status: ready-for-agent

日期：2026-10-09
授权：最终grill共同理解及测试seam已确认；规格明确不代表工单或实施范围获批。

## Problem Statement

准备接纳、运行状态、确认预算、等待、结局及后置扫描分散在多个界面入口。开窗、页面和开轮闸门会以不同规则解释同一次准备；测试被迫拼装私有状态。

隔离基线诊断12项：6个通过对照、6个行为断言失败、0 error。已复现直接重复准备并发进入且提前显示非运行、重试派发延迟重置预算、墙钟回拨恢复确认期、旧READY掩盖新异常、旧扫描在切试采后改用试采连接、页面确认期锁定但后端开轮通过。它们是受控行为证据，不是生产事故或数据损坏记录。旧事件重复使用、派发失败卡住及其他迟到覆盖风险属源码推论；重复知识属locality债务。

## Solution

一个准备模块持有接纳、预算、等待、落定及后置扫描编排，Api、main和views消费同一事实。30秒耗尽后后台仍继续，有本周本地计划按既有规则降级，无则守闸门。试采绕过正式准备，不消费其他上下文结果。默认保持用户行为；已明确批准的收紧是start_run在确认期也拒绝，与开始页一致。

## User Stories

1. 作为操作员，我希望首次开窗前等准备落定，以便页面消费明确事实。
2. 作为操作员，我希望只等该次运行剩余的30秒预算，以免派发延迟或后来等待延长阻塞。
3. 作为操作员，我希望超时有本周本地计划时仍能按规则开轮，并知道最新状态未确认。
4. 作为操作员，我希望没有本周本地计划时仍守闸门，以免无计划采集。
5. 作为操作员，我希望超时后台继续，以便最终真实结果可供消费。
6. 作为操作员，我希望重复prepare/retry均拒绝，以免额外并发任务。
7. 作为操作员，我希望墙钟变化不改变相对预算。
8. 作为操作员，我希望异常或派发失败唤醒等待者，并允许明确重试。
9. 作为操作员，我希望旧成功只作历史，不掩盖本次超时或异常。
10. 作为操作员，我希望缺口扫描再慢也不占开窗等待预算。
11. 作为操作员，我希望扫描失败只作提示，不撤销准备结果。
12. 作为操作员，我希望落定后能明确重试，而旧扫描不覆盖新运行。
13. 作为操作员，我希望本机试采不触发正式计划或Git副作用。
14. 作为操作员，我希望回到原正式上下文可恢复原事实，不自动准备。
15. 作为操作员，我希望不同上下文不复用结果，旧工作仍只访问原上下文。
16. 作为操作员，我希望跨周、本周计划分流、JSON和页面重画行为不改变。
17. 作为操作员，我希望开始页与后端开轮对确认期有一致判断。
18. 作为操作员，我希望准备不计入已抓时长，停止与确认关窗不被重写。
19. 作为维护者，我希望从公开接口控制时间与交错，不改私有字段或真实等30秒。
20. 作为维护者，我希望每次运行的等待者取得对应结果，不被后续重试替换。

## Implementation Decisions

### 职责与上下文

- 新准备模块持有者拟名Preparation，固定绑定配置、调用方提供的稳定连接能力、业务时刻来源及准备专用runtime adapter。不自行按路径开库，不检查任意闭包，不增加热重载、配置指纹注册表或缓存。
- Api保留正式owner；试采选择bypass owner；返回原正式上下文恢复同一owner。新配置、数据库或机器能力对应新owner。模式切换沿用现有路径、进程归属与停止守卫；未落定准备包括超时后仍禁止切换。
- 计划模块保留准备和计划业务；owner持有接纳、预算、等待、异常落定和先落定后扫描的编排。Api保留界面、模式与采集接线。
- 准备及扫描固定原配置、连接能力和周，worker不重新读取可变Api配置或连接字段。

### 状态、预算和结果

- 不可变PreparationSnapshot区分未开始、运行且预算内、运行且预算耗尽、已落定、试采绕过，提供phase、派生running/confirming、当前result、失败类别和一份历史result。
- 成功接纳时建立唯一单调时钟30秒截止点，派发延迟计入，30秒整即耗尽。业务日期/跨周沿用业务时刻来源，不与单调时钟混用。快照按截止点推导，不靠定时器维护第二份状态。
- 超时不等于结束、取消成功或可重跑。若等待者读取时已经落定，返回真实落定状态，不保留过时的超时状态。
- 新尝试清空当前结果，保留最近一份可用历史；失败重试不抹掉历史，不回填旧READY。PrepResult类别仍由计划业务解释，有结果不自动意味着可开轮。
- 本次超时/异常，有本周本地计划按未能确认最新降级，无则守闸门。可为计划判断增加可选历史输入，仅保留原跨周提示，不证明当前成功，不假造PrepResult；Api/views只转交事实。

### 公开接口和接线

- request原子接纳并安排执行，返回明确决定与不透明运行凭据。未落定时所有入口拒绝重复，不排队、不隐式重跑、不重置预算；试采绕过；派发失败明确返回失败。拒绝可携带已有凭据供显式等待，不代表请求被接纳。
- wait_for_open(run)等指定运行落定或其剩余预算，返回该次快照，不包含扫描，不接受新预算。
- wait_for_finish(run)等指定worker连同扫描结束，返回该次result或None，保留同步prepare语义；不用于开窗，不受30秒限制。
- snapshot一次读取当前不可变事实；不向main暴露事件/线程。外来owner凭据拒绝。
- 同步Api.prepare经request和wait_for_finish；重复拒绝并记录、返回None，不隐式等待。retry_prepare保留ok/error JSON，派发失败返回error。
- 公开Api开窗准备辅助入口请求/等待，已有运行时可明确等同一次；main删除私有等待、线程和预算编排。
- UiState用单一快照替代零散准备字段，既有JSON形状和无自动重画行为不变；prepare_running/confirming_now可保留为纯委托。
- start_run在确认期内拒绝为已批准收紧；不改变过程页resume_run、停止、关窗。Api选择owner及request使用既有模式同步保护，等待前释放Api锁。

### 运行身份、异常与慢活

- 每次接纳有独立落定/完成通知及结果。A落定扫描未完时可以接纳B，A的两种等待仍对应A，A扫描/完成不得写B状态。未落定准备不并发；不新增取消、抢占或通用任务框架。
- 状态与落定通知在同一同步保护下发布，等待不持状态锁，唤醒后重读指定运行及剩余预算。
- 普通准备异常和派发失败落定唤醒，可明确再试；finally发布worker完成。BaseException清理唤醒后保留传播，不伪装成功。进程终止不保证进程内唤醒。
- 落定先于扫描，扫描只访问原上下文并作提示；后置扫描或日志异常不能撤销结果或覆盖新运行，无自动重试或扫描队列。

### Deletion test及既有决策

- 调用方必须真正删除重复接纳、墙钟预算公式、私有等待、旧成功回填、分散落定/扫描顺序及借用可变连接的知识，不只是搬四个字段。
- ADR-0035的30秒兜底、本周计划分流、跨周及不自动重画保持，确认期后端拒绝已获批准，不增加逃生口。
- ADR-0011调用方提供连接能力不变；ADR-0016/0048停止、确认关窗和进程归属不重写；ADR-0049试采隔离模型不重写。
- ADR-0051已抓时长仍属于轮次采集执行，准备不计入，GUI/views不累计、不恢复旧公式。无数据库schema变更。

## Testing Decisions

- 优先Api公开接口、实际main配合已有窗口/进程adapter及views输出；owner公开接口仅补精确时间/身份矩阵，不以类单测代替集成。
- 经Api注入单个准备专用runtime adapter，只提供单调读时、安排后台执行、等待通知。生产使用单调时钟/daemon线程/事件等待，测试推进时钟并控制派发/等待；规则不下放adapter，不做通用框架。
- 用既有隔离SQLite、本地Git夹具，可控事件/adapter制造交错；不靠sleep碰运气，不真实等30秒，不改私有准备字段。旧私有fixture在等价公开覆盖就位后替换，不能长期保留两套知识。
- 验证首次正常准备及实际main等待/建窗；main异常唤醒；29.999/30/30.001边界、派发延迟、后加入者剩余预算、墙钟回拨。
- 验证超时有/无本周本地计划的页面/后端闸门、后台继续及最终落定；首次/重复prepare与retry交叉仅安排一次任务。
- 验证旧READY后新超时/异常、历史保留、跨周提示；派发失败及异常后重试。
- 验证A落定扫描未完接纳B，A等待/扫描/完成不影响B；拒绝陌生owner凭据。
- 验证扫描阻塞时窗口仍建、扫描失败不撤销结果、切模式后扫描用原连接。
- 验证试采不触发正式连接/Git/计划副作用、原正式上下文恢复、新上下文不复用；main、UiState、开始页和start_run一致，JSON不回退。
- 保留elapsed准备后起算、关窗确认及停止监督回归。日常只跑相关单文件/用例；实施收尾在隔离副本根跑仓库分段全量运行器，显式指定主仓票证据绝对目录，不加-f，记录合计/对账/结论。旧elapsed全量及诊断红测均不作本项验收。
- 实施交付需要Standards/Spec双轴审查及deletion test；不把adapter覆盖说成原生窗口或真实故障现场验收。

## Out of Scope
