# 三机交换台恢复与完整性验收计划

日期：2026-10-24。状态：Q1–Q12 决定已确认，尚未进入实施。

依据：[三机核查报告](../reviews/三机交换台与数据完整性核查-2026-10-24.md)。本稿只拟定后续工作，不代表已经修复、重发或完成上机验收。m1/m2 结论来自核算包，m4 来自本机只读检查，时间截点不同。

## 目标与既有约束

已确认目标：分阶段恢复 m1、m2、m4 的交换与判断通道，覆盖全部现存且可恢复的历史，先 W42/W43 闭环、再补早期周，使接收后的 SKU 库存、当次图片与观测完整性能够被分析程序实际使用。各机按角色执行，纯汇总 m4 不承担新采集数据导出。

m3 硬件故障、重新部署时间尚未确定（用户于 2026-10-24 告知）。m3 在线部署与现场验收延期，不阻塞 m1/m2/m4 本轮交付；其历史与恢复后增量留待后续补验。机器离线不等于托管仓库不可访问：如已有批准的 m3 历史包可读，本轮仍可汇总；没有数据或未核实的部分明确留账。不得由机器故障推定远端为空、历史从未存在或全网已经完整。

已有 ADR-0031 要求各机汇总同一批包后确定性收敛到同一份全量数据；不把本机 m4 修好作为三机全部通过的替代。m4 为纯汇总机，但其退役前的真实采集史仍是历史数据来源，不能仅按当前采集名册排除 raw-m4。m4 自己已有的采集史也不能靠收取自己的包恢复，现场与备份需要保留。

沿用 ADR-0058：本次交换动作的成功与数据覆盖完整是两项结论。远端当周整包尚未发布可以返回退出码 0，但报告必须保留待收事实；来源接入失败、已发布包拉取失败、已到包覆盖不足、计划未知应分别表达。已确认：没有有效当周计划时显示“完整性未核验”并列待办，继续可执行的交换；没有其他硬失败时整趟返回 1。这个规则不把所有待收包改判失败。

沿用商品主图与 SKU 图的当次观测语义：缺图不借用相邻观测。完整观测批次是分析取证所需证据，不等于图片实体数或库存行数。

## 第 2 轮确认的边界

- m3 暂不移出采集名册，不调整机器编号，也不据此重分周计划。m3 部署与验收延期；本轮没有安排 m1/m2 自动代采。已发布计划及故障期间实际缺失的观测照实记录；若需要人工临时代采，另行明确安排。
- 周计划有效性未知与真实缺包分开报告：无有效当周计划时完整性未核验、退出码至少为 1；其他硬失败优先按既有退出码规则处理。远端整包尚未发布继续遵循 ADR-0058。
- 本轮包含原始数据来源清单和持续核对、自动接入。来源覆盖当前采集机及历史生产者，与当前采集名册和判断来源清单解耦；m3 暂停和 m4 转角色不自动删除历史来源。清单维护者与发现方式在第 3 轮确认。

## 实施阶段与依赖

### 阶段 0：固定验收范围与保全现场

- 记录三机程序版本、角色、配置摘要、周计划身份、各来源提交和采集/交换截止时刻；不采集明文凭据。
- 在任何上机修复前保留正式库的一致性备份、失败日志和相关 Git 工作区状态；不直接删除克隆、清空正式库或覆盖脏现场。
- 本轮验收建议先固定到 2026-10-24 的一份明确来源快照；后来继续采集的数据另记增量，避免比较不断变化的总数。
- 按已确认范围分阶段交付：全部现存且可恢复历史纳入，m3 在线验收延期；故障期分工、报告规则和最终关闭条件已按 D9–D12 固定。

产物：三机现状与版本表、来源/周包快照、验收范围清单。

### 阶段 1：恢复现有通道，完成程序修复设计

运行恢复线：

1. m2 查清 raw-m2 的 Git 暂存失败，保留失败现场后按实际原因修复，验证 W43 导出及图片发送。按既有判断来源接入规则修复 judged-m2 与其他失败来源，检查发布和收取各自结果。
2. m4 接入批准的 raw-m2 来源；m1 排查 m2 的来源接入与包发现；m2 排查 raw-m4 历史包接收。对 m3 区分故障机器与托管来源：批准且可访问的历史来源仍核查、汇总，依赖 m3 重新部署的项目延期。每机核对来源地址、实际可用性和导入账，不能只看存在一个 raw 目录就通过；真实通道错误仍如实报告。
3. 运行恢复可先交付阶段结果，但仅标记为“通道恢复”；历史与 SKU 取证仍未通过时继续保留待办。

程序修复线：

4. 为纯汇总机设计明确的计划确认入口，复用已有计划有效性与发布后不重算契约，不依赖实际启动正式采集。区分未知计划、有效本地计划但最新状态未确认、已确认当周计划。
5. 设计原始数据来源的权威范围：当前采集来源与仍需重放的历史来源分别保留依据；不直接把判断来源清单当成原始数据来源清单。
6. 报告分列动作执行结果、覆盖核算是否可判定、已知缺包/缺口、证据可用性。缺计划或应接来源不可用时，不能用“没有待办”掩盖未知状态。
7. 补齐完整观测批次的交换契约：明确身份、关联时间、SKU 集合与完整性、主图引用、冲突处置；核对其与现有按日期/店铺定序及粒度切换规则的一致性。
8. 设计新旧包兼容、幂等导入与历史同周重发；旧包没有批次时保留“未知”，不从库存或邻日图片推造完整观测。新程序应能继续接收旧包；旧程序消费新包的能力须验证后确定部署顺序。

依赖：通道排障和设计可以分别推进。批量历史重发与最终取证验收，要等观测交换修复和接收端就绪，避免只补一次库存后误报收口。

### 阶段 2：实现、验证与部署

兼容性新增风险：当前接收端只读取已知表，并按整包哈希记幂等账。若旧版先接收带观测批次的新包，可能忽略新表却把整包记为已收；升级后同一哈希会跳过结构化数据。仅验证“旧程序没有报错”不足以证明新证据可恢复。须增加“旧版先收、升级后重放”的回归或明确不支持该部署顺序并提供安全恢复路径；不通过手工删除导入账规避。

- 按确认后的设计拆成有独立验收条件的工单：覆盖核算、原始来源接入、观测导出、观测汇总与兼容、跨机运行恢复。
- 重点回归：未知计划不报无待办；远端未发布整包仍遵循 ADR-0058；批准来源缺失能被识别；有效旧计划降级有明示；单来源失败不吞掉其他来源的成功。
- 观测回归：旧包无批次、真实批次完整/不完整、无图与失败、同日多次观测、不同顺序导入、重复导入、相同周重发、跨机冲突、单/多规格粒度切换。
- 以实际生产取证函数验证导入后可以定位精确观测与当次图片；有图片资产而没有当次观测依据时，仍应明确缺证据。
- 实施收尾按项目规范在隔离副本分段跑一次全量，证据写主仓工单日志目录；不以本次审计的诊断失败数替代项目测试。
- 部署顺序由兼容验证决定。部署前保留可回退程序版本与一致性数据备份；现场数据恢复另列步骤，不靠盲目重建解决。

### 阶段 3：历史重发与重放

- 按来源和周制作清单：源机确实存在的库存、图片版本、完整观测批次、图片实体，以及已丢失或从未采集的部分。
- 已确认优先 W42/W43 验证整个链路，再覆盖全部现存且可恢复历史；已有可靠批次可重发。暂时拿不到源机证据记为待核实，不能直接判为不可恢复；源机与可用备份核查后确无证据的部分单独留账，不推造历史观测。
- 纯汇总 m4 不承担新的采集导出；raw-m4 既有历史包可以在其他机器重放，缺少的旧内容是否需受控补发另行设计，不通过改机器编号绕过角色。
- 汇总后重复执行同一包，验证数据不重复、不倒退；更换导入顺序，按既有合法冲突规则比较最终业务数据。

### 阶段 4：共同截止范围下的验收

| 验收层次 | 通过依据 |
| --- | --- |
| 交换动作 | 导出、汇总、判断集发布/收取逐项有真实结果，失败能定位到来源与命令 |
| 来源覆盖 | 应接当前来源与历史来源逐项核对；未发布、未接入、拉取失败可区分 |
| 数据覆盖 | 同一来源快照、同一截止范围，逐日期/店铺比较主键集合与库存/价格等值；合法冲突按确定性规则对账 |
| 图片与观测证据 | 哈希与引用正确，批次身份、精确观测时间、完整性及当次图可解释，实际 SKU 分析取证通过 |
| 未知与欠缺 | 未采集、已采未导出、已导出未汇总、证据历史不可恢复分别留账；无凭据不得宣称全量完整 |
| 重复与顺序 | 相同包重放幂等；同一批合法包不同到达顺序产生相同业务结果 |

本次 95,210 行只是三机日期/店铺组最大库存计数的合计下界，适用于本次样本比较；不是最终应有总数，也不能作为每机必须恰好达到的目标。新增数据、m3 数据和合法粒度冲突都需要另外解释。

## 实施拆分

以下五组工作按依赖顺序执行。每组完成后保留可复核产物；未通过时保留现场、上一版清单或阶段状态，不以删除数据、重建仓库或手工清理导入账来“收口”。

### A. 现场核查与证据保全

- **输入与责任**：以 2026-10-24 来源快照、三机核算包、本机 m4 现场为输入；由 m1、m2、m4 分别提供本机版本、配置摘要、计划身份、来源提交、交换截止时刻、数据库备份和失败日志。m3 只核对当前可访问的托管历史，不把部署前置到本阶段。
- **依赖**：先固定共同截止范围和快照身份；任何修复、升级、重发前完成保全。保留 m2 raw-m2 暂存失败现场、judged-m2 接入失败现场、正式库一致性备份、Git 工作区和导入账。
- **产物**：三机现状与版本表、来源清单快照、周计划快照、失败命令及 stderr、数据库备份校验、保全清单和待查项清单。
- **通过条件**：每个结论都能回到具体机器、提交、计划、来源、包或备份；密码和 token 不写入证据；脏现场可复现或可解释。
- **未通过保留状态**：保留原现场和上一版可用来源清单，标记“现场证据不足”或“待核查”，不删除克隆、不重建正式库、不覆盖失败日志。

### B. 程序修复与契约验证

- **输入与责任**：使用 A 组证据和现有交换、计划、导入、分析代码；由本机开发流程修复 m4 纯汇总计划核验、原始数据来源清单维护与自动接入、完整观测批次导出/汇总/导入及报告状态。m1/m2/m4 的现场只用于验证，不在未完成接收端验证前启用新版生产包。
