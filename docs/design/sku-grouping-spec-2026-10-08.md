# SKU 粒度同款分组与展示规格

Status: ready-for-agent

- 日期：2026-10-08
- 来源：SKU 分组访谈 Q1–Q31 及用户后续修正，业务规则已逐项确认。
- 实施状态：尚未实现；本次仅发布规格，不授权修改运行代码、迁移数据或删除旧记录。
- 文档主本：`docs/design/sku-grouping-spec-2026-10-08.md`；本地工单库发布副本：`.scratch/sku-grouping/spec.md`。两份正文保持一致，后续修改先更新主本再同步副本。
- 关联决定：ADR-0050；访谈记录：`docs/design/sku-grouping-interview-2026-10-08.md`。
- 测试边界：用户于 2026-10-08 明确确认符合预期，采用分析服务公开接口为主、真实浏览器／离线报告及交换台跨机集成为辅的方案。

## Problem Statement

当前销量分析按商品判断和确认同款，把商品下的 SKU 捆绑在一起。一个商品中的不同 SKU 可能是不同款，也可能分别对应其他店铺商品中的某个 SKU；商品级归组会混入不属于当前同款组的销量。SKU 名称中还存在跨店可用的商家内部编码，现有商品级证据不能直接表达这条强归组依据。

展示也依赖商品粒度：结果组取销量最高的商品作为代表，展开商品的全部 SKU，图表聚合商品序列。仅修改匹配规则或页面文案不能修正代表图片、名称、销量、构成和报告。用户需要以具体 SKU 判断、调整和核对同款组，并清楚知道自动归属依据、多候选风险和需要重新确认的变化。

## Solution

以“店铺＋商品编号＋平台 SKU 编号”标识每个组成员，贯穿取证、同款判断、人工操作、确认、统计、排名、搜索与离线报告。跨店同有效编码默认同组，不同有效编码默认不同组；至少一方无有效编码时才走商品名称＋SKU 名称＋SKU 图片判断。人工决定优先。颜色、包装及销售件数差异不影响同款判断，也不用于推算销量换算倍数。

单 SKU 商品保留商品名称，模型输入的 SKU 名称为空；保留原始名称用于编码提取与核对。缺 SKU 图时允许同次观测的商品主图代填。多候选由模型推荐唯一归属并解释，不能通过一个无编码 SKU 合并不同编码组，不能明确推荐则暂时独立。

组代表改为组内区间销量最高的 SKU；组销量和曲线仅汇总组内 SKU，保留“店铺 → 商品 → SKU”阅读层级但不带入组外 SKU。确认页可按同款分组编号查找组及其成员。旧商品级记录保留、隔离，新 SKU 结论与人工决定继续跨机共享。

## User Stories

1. 作为分析用户，我希望以具体 SKU 而非整件商品分组，以便不同款的 SKU 不被捆绑。
2. 作为分析用户，我希望同一商品的不同 SKU 可以归入不同组，以便匹配其他商品中的对应款式。
3. 作为分析用户，我希望同码规则跨店生效，以便识别不同店铺销售的同款。
4. 作为分析用户，我希望两个有效编码相同的 SKU 默认同组且不再请求模型核验，以便减少重复判断和费用。
5. 作为分析用户，我希望两个有效编码不同的 SKU 默认不同组，以便避免仅因图片相似而误合并。
6. 作为分析用户，我希望至少一方无有效编码时结合商品名称、SKU 名称和 SKU 图片判断，以便没有编码也能识别同款。
7. 作为分析用户，我希望人工决定优先于所有自动规则，以便纠正同码误合并或异码误拆分。
8. 作为分析用户，我希望颜色、包装和销售件数差异不阻止同组，以便比较同一主体实物款式。
9. 作为分析用户，我希望识别半角和全角井号包围的编码，以便兼容名称的常见写法。
10. 作为分析用户，我希望编码比较忽略首尾空白和英文字母大小写但保留内部字符，以便不误拆同码也不误合异码。
11. 作为分析用户，我希望空编码和未闭合片段不作为有效编码，以便不产生错误强制归组。
12. 作为分析用户，我希望重复同码正常使用、多个不同编码显示歧义，以便系统不随意选码。
13. 作为分析用户，我希望单 SKU 商品的匹配输入保留商品名称而让 SKU 名称为空，以便不重复或伪造名称证据。
14. 作为分析用户，我希望单 SKU 的原始名称仍被保留，以便提取编码并人工核对。
15. 作为分析用户，我希望仅在单 SKU 没有真实 SKU 名称时从商品名称提码，以便默认单规格商品也可使用编码。
16. 作为分析用户，我希望只有系统默认占位名称才被视作无真实名称，以便正常采集名称不被误删。
17. 作为分析用户，我希望缺 SKU 图时使用同次商品主图并标注来源，以便知道图片证据的具体程度。
18. 作为分析用户，我希望单 SKU 库存和价格沿用真实数据及既有默认行规则，以便不凭空制造数值。
19. 作为分析用户，我希望单 SKU 身份根据完整商品观测判断，以便筛选或零销量不会改变匹配输入。
20. 作为分析用户，我希望无编码成员同时匹配不同编码组时不把这些组合并，以便避免间接误合组。
21. 作为分析用户，我希望模型推荐一个候选组并解释理由，以便快速采用更合适的归属。
22. 作为分析用户，我希望默认加入推荐组的 SKU 同时显示多候选标记和其他候选，以便人工复核替代归属。
23. 作为分析用户，我希望无法明确推荐唯一组时暂时独立，以便不按组号或顺序武断归组。
24. 作为分析用户，我希望系统不把召回分数或模型置信度展示为相似度百分比，以便不被不真实的精度误导。
25. 作为分析用户，我希望人工拆开的同码组不会被重新自动合并，以便拆组决定持续有效。
26. 作为分析用户，我希望新同码成员遇到多个人工拆组时也经过候选比较，以便保留人工边界。
27. 作为分析用户，我希望同码或明确图文推荐的新成员可以加入已确认组，以便不必逐个手工添加。
28. 作为分析用户，我希望自动增员使整个组退回未确认并显示新增依据，以便重新核对改变后的成员集合。
29. 作为分析用户，我希望人工排除跨分析保留且重试不能撤销，以便纠正结果不会反复失效。
30. 作为分析用户，我希望排除绑定稳定 SKU 身份，以便改名、换图、改码不自动取消人工决定。
31. 作为分析用户，我希望实质证据变化触发重新确认而规范化后的等价编码不触发，以便只处理有意义的变化。
32. 作为分析用户，我希望已人工确认的成员改码后保留原归属并提示冲突，以便由我决定是否移走。
33. 作为分析用户，我希望人工混合编码组可以接纳其中任一码的新成员但不建立全局编码等价关系，以便局部决定不误合其他组。
34. 作为分析用户，我希望历史分析只使用结束日及以前的证据，以便未来变化不污染历史结论。
35. 作为分析用户，我希望当次缺图明确表示缺失而不偷用其他时期图片，以便证据来源可信。
36. 作为分析用户，我希望一个 SKU 在一次分析中只归一个组并计入整段有效销量，以便不重复统计。
37. 作为分析用户，我希望缺图不影响有效编码规则，但图文路径不退化为纯名称合组，以便在证据不足时保持保守。
38. 作为分析用户，我希望模型未配置、失败或停止时编码和有效人工决定仍生效，以便分析可继续使用已知信息。
39. 作为分析用户，我希望未完成的图文判断保留有效归属或暂时独立并说明原因，以便不把失败误读成非同款。
40. 作为分析用户，我希望重试和跨机复用有效判断及候选推荐，以便不为相同证据重复付费。
41. 作为分析用户，我希望候选成员、证据、规则或人工约束变化后重新检查推荐，以便不误用过期结论。
42. 作为分析用户，我希望旧商品级判断、人工决定和草稿可查但不自动展开为 SKU 结论，以便保留历史且避免错误迁移。
43. 作为分析用户，我希望新旧共享格式明确隔离并有可验证的升级门槛，以便不同版本不静默误用数据。
44. 作为分析用户，我希望组销量仅相加组内 SKU 的原有销量且不推算换算倍数，以便统计口径稳定。
45. 作为分析用户，我希望页面和报告说明组销量是销售单位数量合计而非统一实物个数，以便正确理解不同包装的合计。
46. 作为分析用户，我希望代表是组内销量最高的 SKU 而非销量最高的商品，以便首图和名称代表当前组实际畅销成员。
47. 作为分析用户，我希望代表销量并列时选择稳定，缺图也不偷换代表，以便同一分析的展示一致可追溯。
48. 作为分析用户，我希望代表显示自身图片、商品名称和 SKU 名称，单 SKU 只显示商品名称，以便正确识别组代表。
49. 作为分析用户，我希望代表链接仍打开所属商品详情且大数字明确叫组销量，以便不混淆代表销量和组销量。
50. 作为分析用户，我希望展开仍按店铺、商品、SKU 分层但只列组内成员，以便阅读方便且不混入其他款。
51. 作为分析用户，我希望商品层标为本组内销量小计，以便知道它不是商品全部 SKU 的销量。
52. 作为分析用户，我希望组曲线仅聚合组内 SKU、每个 SKU 展示自身图片名称编码销量及曲线，以便核对统计来源。
53. 作为分析用户，我希望确认卡片及移动、排除、添加均针对 SKU 并显示归组依据，以便准确调整而不连带同商品其他成员。
54. 作为分析用户，我希望搜索商品名称、SKU 名称、商家编码、商品编号和平台 SKU 编号，以便定位成员。
55. 作为分析用户，我希望按同款分组编号搜索对应组及其成员，以便直接定位要核对的组而不混淆榜单名次。
56. 作为分析用户，我希望店铺和商品去重计数、SKU 按成员计数，以便真实了解组构成。
57. 作为分析用户，我希望确认页按 SKU 数再按组销量降序、结果页按组销量排名，以便分别优先处理大组和查看畅销组。
58. 作为分析用户，我希望确认页摘要、结果页及离线报告使用一致的代表和统计口径，以便各处核对结果相同。

## Implementation Decisions

### 1. 身份、边界与优先级

- 分析快照、匹配证据、人工决定、草稿、共享记录及页面操作统一携带 SKU 身份：店铺＋商品编号＋平台 SKU 编号。商家内部编码是证据，不是身份；同款分组编号也不等于编码、平台 SKU 编号或榜单名次。
- 人工约束优先于编码，编码优先于普通图文判断。同码默认同组不意味着人工已确认；异码默认分开可以被明确人工决定覆盖。
- 两方都有相同有效编码时不请求模型再核验；都有不同有效编码时不以普通图文结果覆盖异码规则。至少一方无有效编码时使用商品名称、SKU 名称和 SKU 图片。
- 图文判断忽略颜色、包装和销售件数差异，但仍需识别同一主体实物；不因忽略这些差异而无条件合组。
- 同一 SKU 在一次分析只归一个组。无编码成员不能充当不同编码组之间的合并桥梁；人工拆开的组也不能被自动重合。

### 2. 编码解析与单 SKU 适配

- 半角和全角井号均为分隔符；取闭合片段，去编码首尾空白、英文字母不区分大小写，保留内部字符。空或未闭合片段不产生有效编码。
- 所有有效片段规范化后仅有一个不同值时使用该值；重复同码不算冲突。存在多个不同值则标记“编码有歧义”，不任取其一，走图文路径，保留原名称与歧义证据。
- 默认单规格行以及完整商品观测中恰好一个真实 SKU 均属于单 SKU。不能按过滤后的列表、零销量成员或累计库存残留行数推定单 SKU。
- 单 SKU 的模型匹配字段为商品名称有值、SKU 名称为空。原始 SKU 名称与模型输入分开保存，前者仍供编码提取和证据核对；不得把商品名称复制为 SKU 名称。
- 编码优先从原始 SKU 名称提取；仅在单 SKU 没有真实 SKU 名称时从商品名称提取。系统生成的默认占位名称视为没有真实名称，不把普通真实名称任意当占位符。存在真实名称但未提取到编码，不因此继续从商品名称兜底。
- SKU 专属图片优先，缺少时可用同次观测商品主图，保留代填来源。库存和价格保留真实 SKU 数据，默认单规格沿用已有商品数据填入默认行的基础规则，不重新发明数值。

### 3. 历史证据与销量

- 使用分析结束日及以前该 SKU 最近一次观测的证据；名称、图片尽量来自同次观测。当次缺图明确缺图，不借用之前或之后的其他时期图片；允许同次商品主图代填。
- 证据及其版本要能区分原始名称、匹配名称、有效编码或歧义、图片内容及来源、观测时间和规则版本，不能沿用商品级证据键命中 SKU 结论。
- 一个 SKU 以所选证据确定本次归属，整个区间有效销量计入该组；本期不另按名称或编码变化拆分归组时间段。已有库存规格形态有效段边界保持不变。
- 组销量为组内 SKU 按既有库存下降算法所得销量之和；不从名称推算销售件数倍数、不统一换算实物个数。单个装售出 10 件、双件套售出 10 套合计为 20，不是 30。
- 组级库存、销量曲线只聚合组内 SKU；商品层只计算该商品当前组内成员的小计。页面和报告说明合计是不同 SKU 销售单位数量，不是统一实物数量。

### 4. 多候选推荐与人工生命周期

- 对多候选比较，由模型返回唯一推荐归属及理由，默认加入推荐组，同时保存多候选标记和其他候选。无法明确唯一推荐时独立成组，标记“多个候选，无法确定归属”，不得按组号或顺序选组。
- 不新增相似度百分比；现有召回分数只承担召回预算作用，模型置信度不是组级相似度。除本规格明确改变的规则外，不借此任务任意重调既有预算和判断门槛。
- 同码被人工拆成多个组后，新同码成员同样走候选比较，保留人工拆组。人工混合编码组可以接纳与其任一码相同且无排除约束的新成员，但不把这些编码建立为全局等价关系。
- 同码或明确图文推荐可以给已确认组增员；整组退回未确认，并显示新增成员及同码依据或推荐理由。所有自动添加仍受人工排除约束。
- 人工排除按 SKU 身份跨分析保留，只能人工明确撤销或重新归组。普通分析、重试及证据变化不能自动撤销排除。
- 实质匹配证据变化时，原人工确认归属保留参考、相关组退回未确认并显示变化。已人工确认成员改码后不静默移组，明确提示新编码及组内差异，由人工决定。未经人工确认的自动组可按新证据重算。
- 仅编码大小写或首尾空白等规范化等价变化，不单独触发重新确认；不要将原始字符串变化一概当作实质变化。

### 5. 缺失、停止、缓存与跨机兼容

- 无 SKU 图且无可用同次商品主图时，有效编码规则仍可运行；需图文判断的成员标记“缺少图片证据”，暂时独立并允许人工处理，不退化为纯名称自动合组。
- 模型未配置、调用失败或停止不阻断编码与有效人工决定。未完成模型分支保留已有有效归属，没有则独立；区分缺少证据、需配置、失败、已停止与确定非同款。
- 重试仅补未完成调用，复用仍有效的判断和推荐。推荐缓存必须描述完整候选语境，包括候选组及成员、输入证据和规则版本；语境变化不得误命中，应用前重新检查人工约束。
- SKU 判断、人工决定及候选推荐缓存继续通过交换台跨机共享。复用针对相同有效输入，不保证不同候选语境也免调用；不能把当前仅写入的推荐快照直接宣称为已有可共享缓存。
- 旧商品级模型判断、人工分组、排除和草稿保留可查，但不自动展开为 SKU 结论。新分析从 SKU 证据建立分组；旧草稿不静默改格式，提示发起新的 SKU 分析。
- 新旧粒度及格式版本明确隔离。不支持新格式的消费者必须明确拒绝或走升级闸门，而非静默误用；实施前实测已部署旧版本的识别能力，必要时明确部署顺序，不能假设旧代码会自动出现新提示。

### 6. 确认页、结果页与报告

- 代表 SKU 为组内区间销量最高成员，并列按稳定 SKU 身份排序。选择与所属商品全部销量无关；代表缺图也不改选其他成员。
- 代表图使用自身 SKU 图或带来源提示的同次商品主图，缺图明确表示。名称显示商品名称＋SKU 名称；单 SKU 只显示商品名称，商家编码可独立作标签；链接仍打开所属商品详情。
- 结果行大数字标为“组销量”，不暗示是代表 SKU 销量。结果榜单按组销量降序，而非代表 SKU 或其所属商品销量。
- 构成保留“店铺 → 商品 → SKU”，只显示当前组成员。商品层标“本组内销量小计”；SKU 行显示自身图片、名称、编码、销量及库存／销量曲线。
- 确认页卡片及添加、移动、排除对象均为 SKU，不捆绑商品其他 SKU。卡片包含商品名称、SKU 名称、SKU 图、店铺、商家编码、SKU 区间销量，并展示人工／同码／图文归组依据，以及适用的推荐理由、多候选、编码歧义和主图代填提示。
- 确认页搜索覆盖商品名称、SKU 名称、商家编码、商品编号、平台 SKU 编号及同款分组编号。按组编号查找对应组及成员；不能用当前排名冒充组编号。此要求不额外引入结果页全局搜索。
- 店铺数和商品数按当前组成员分别去重，SKU 数为当前组成员数。确认页按 SKU 数降序再按组销量降序；结果页按组销量排名。
- 确认页摘要、结果页及离线报告采用相同代表与统计语义。单 SKU 匹配名称为空不等于删除原始名称或隐藏核对证据。在线分页与离线全量导出沿用既有行为，不能只导出当前页。

### 7. 与既有架构决定的关系

- 沿用默认单规格库存承载、库存计算有效段和运行锁／停止机制，不把 SKU 粒度改造扩成采集器重写。
- 对既有同款装配决定的修改限于 SKU 身份、编码优先、多候选不桥接以及自动增员后整组重新确认；不静默沿用“已确认组绝不自动增员”的旧约束。
- 重新开放已收集 SKU 图片的匹配和展示消费；扩展共享判断与人工决定的粒度及推荐缓存，同时保留旧记录隔离。关联 ADR 记录设计变更而非宣称已部署。

## Testing Decisions

### 已确认的测试边界（2026-10-08）

优先一个主边界：分析服务的公开操作，使用真实临时库存库、历史观测、图片与决定存储，仅在外部模型调用处提供可控响应。通过最终快照、归属、状态、销量和可观察的模型调用复用验证规则，不断言私有函数调用顺序或装配算法内部结构。

另保留两个不可替代的集成边界：少量真实浏览器 → 本地 HTTP → 分析服务用例覆盖实际页面及离线报告；既有交换台双本地世界与 bare remote 集成覆盖真实发布、收集和版本隔离。不为每个辅助模块新建 mock 接口；服务测试穷举规则，浏览器只验证关键用户路径与展示语义。

既有先例：`tests/test_analysis.py`、`tests/test_analysis_reuse.py`、`tests/test_analysis_drafts.py`、`tests/test_analysis_conflicts.py`、`tests/test_replay_groups.py` 的服务／回放行为；`tests/test_group_editing.py` 与 `tests/test_analysis_results_screen.py` 的真实页面和离线导出；判断集／交换台测试的双世界夹具。重段沿用 `tests/git_repos.py` 的 `WorldTemplate`／`GitSandbox.world`，不逐用例重建整个 Git 世界。

### 验收场景

| 编号 | 输入／动作 | 必须可观察到的结果 |
| --- | --- | --- |
| T01 | 两店同码 SKU，颜色、包装、销售件数均不同 | 默认同组，不请求模型核验；状态不冒充人工已确认 |
| T02 | 双方有效编码不同，图片相似 | 默认不同组；人工明确合并可以覆盖 |
| T03 | 同商品两个不同款 SKU 分别匹配外店成员 | 可属不同组；移动其中一个不连带另一个 |
| T04 | 半／全角井号、首尾空白、大小写、内部连字符 | 前三类等价；内部字符差异保留 |
| T05 | 空片段、未闭合、重复同码、多个不同码 | 无效不提码；重复同码有效；异码标歧义并走图文 |
| T06 | 默认单规格、完整观测单真实 SKU、多 SKU 经筛选只剩一个 | 前两者模型 SKU 名为空、商品名有值；后者不能误判单 SKU |
| T07 | 真实 SKU 名含码、真实名无码、系统默认占位名、真实同名文本 | 原名保留；仅无真实名的单 SKU 从商品名兜底；不靠随意名称猜占位 |
| T08 | SKU 专图、同次主图代填、当次双缺图但其他日期有图 | 分别展示真实来源；不偷用别期图；缺图时只保留编码／人工路径 |
| T09 | 分析结束日后发生改名／改码／换图 | 未来证据不进入历史分析；一次分析一个 SKU 只归一组 |
| T10 | 无码 B 同时匹配异码 A、C 所在组 | A、C 两组不合并；B 仅进推荐组，保留理由和多候选 |
| T11 | 多候选比较无法明确唯一推荐 | B 独立并显示“多个候选，无法确定归属”，不按顺序选组 |
| T12 | 同码人工拆组后再分析及添加新同码 SKU | 不恢复合并；新成员按候选推荐或暂时独立 |
| T13 | 同码／明确图文推荐向已确认组增员 | 合法添加后整组未确认，并能看到新增成员与依据 |
| T14 | 人工排除后重跑、重试、改名、换图、改码 | 排除仍有效；只有明确人工操作才能改变 |
| T15 | 已人工确认成员改码；另有未确认自动组改码 | 前者留原组、整组未确认并提示差异；后者可重算 |
| T16 | 仅编码大小写／首尾空白变化；实质证据变化 | 前者不单独撤销确认；后者触发未确认和变化提示 |
| T17 | 人工混合 A／B 编码组加入 A 或 B 新成员 | 可加入并撤销确认；其他 A／B 组不被全局合并 |
| T18 | 模型未配置、失败、停止及重试 | 编码和有效人工决定继续；未完成不算非同款；仅补未完成调用 |
| T19 | 同候选证据重试／跨机收集；改变候选或成员证据 | 有效推荐可复用；过期语境不误用，人工约束再次检查 |
| T20 | 旧商品级判断、排除、人工组和草稿加载 | 保留可查但不命中／展开为 SKU 结论；草稿提示重新分析 |
| T21 | 新旧客户端／载荷组合 | 新端隔离旧数据；不支持新格式的消费路径明确拒绝或经实测升级闸门阻断，不静默误用 |
| T22 | 单个装销量 10、双件套销量 10 | 组销量为 20，页面和报告说明销售单位合计；不换算成 30 |
| T23 | 商品甲组内 SKU 销量 5、组外 SKU 销量 100；商品乙组内 SKU 销量 9 | 代表为乙的 SKU；组销量 14；甲小计 5；树和曲线无组外 100 |
| T24 | 代表销量并列；选中代表缺图但其他成员有图 | 选择按稳定身份可复现；缺图不偷换成员图名 |
| T25 | 确认卡片、结果摘要、离线报告打开同一组 | SKU 图名和来源一致，单 SKU 标题只含商品名，详情链接归属正确 |
| T26 | 分别按六类字段搜索，特别是同款分组编号 | 确认页能定位相应成员或组；组号不等同名次、商家码或 SKU 号 |
| T27 | 同店多商品、同商品多 SKU 分组并人工移组 | 计数去重正确；确认排序按 SKU 数再按组销量，结果按组销量 |
| T28 | 多于一页结果、零销量过滤、保存后返回与离线导出 | 既有分页／保存交互不退化；报告是全量且只含各组实际成员 |
| T29 | 缺图图文分支、歧义、多候选、调用失败卡片 | 原因分别可见；没有把召回分数／置信度伪装成相似度百分比 |
| T30 | 库存规格形态变化及已有库存有效段边界 | 既有销量边界保持；只改变分组归属和汇总对象，不改库存算法 |

本次只写规格，不执行上述测试。实现时日常用单文件／单用例快速反馈，收尾依仓库规范在规定隔离副本分段跑一次全量并对账，将证据写入主仓票证据目录；不能只跑新增用例就宣称交付。

## Further Notes

### 实施前事实核验（不是待重问的业务规则）

1. 核实历史数据是否能恢复完整商品观测的 SKU 集合及完整性，不能用累计残留行或过滤列表判断单 SKU；无法证明时要暴露证据缺口，不伪造确定结论。
2. 核实 SKU 名称、图片和商品主图能否关联同次历史观测，以及系统默认占位名的来源标识；不能仅因文本相似就抹掉真实名称。
3. 核实旧客户端对未知共享版本的实际行为，确定必要升级闸门及发布顺序；没有验证不能宣布兼容完成。
4. 明确候选推荐载荷与证据版本的完整语境，并验证人工约束变化后的复用合法性。
