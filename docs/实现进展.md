# 实现进展与关键结论（2026-09-04）

## 结论：路线 A 可行，之前卡住是因为两个被遗漏的关键点

### 1. 浏览器必须“连接接管”，不能由 DrissionPage 启动

- 让 DrissionPage / Playwright 直接`启动`浏览器，1688 会把该会话判定为“受控机器人”，
  对受保护端点（店铺商品列表、SKU/库存）一律要求登录或直接踢回登录页。
- 解决办法（已验证）：用**普通进程**启动浏览器并开启远程调试端口：

  ```
  msedge --remote-debugging-port=9222 --user-data-dir=profiles/account1_edge <店铺/首页URL>
  ```

  然后 DrissionPage 只`接管`（`ChromiumOptions().set_address('127.0.0.1:9222').existing_only(True)`）。
  这样浏览器被视为“人启动”，店铺 offerlist / 详情页都能正常打开（不再跳登录）。

### 2. 价格/库存藏在页内 JSON `skuInfoMap`，不是普通 DOM 文本

- 详情页的 SKU 价格、真实可售库存（`canBookCount`）、`skuId` 都在页面的 `skuInfoMap` 里，
  用 DOM 文本或去掉 `<script>` 后解析都会得到 0。
- 解决办法（已验证）：从页 HTML 中正则提取 `"skuInfoMap":{...}` 并 JSON 解析，
  得到每个 SKU 的 `specAttrs`（名称）、`discountPrice/price`、`canBookCount`（库存）、`skuId`。

## 还没解决的部分

## 重要突破：点击商品卡进入详情（可自动枚举店铺商品）

店铺商品列表页的商品是**图片卡片**，没有 `<a href>`，但**点击图片/名称的“可点击父元素”会跳详情**。
用 Playwright 在页面上下文中“**从图片向上找最近的 `onclick`/`<a>`/`cursor:pointer` 父元素并触发真实 click**”，
即可像手工一样点卡片进详情，从而拿到每个商品的 offerId/URL。

实测（第 10 轮）：店铺 A01 第一页 **15 个商品全部命中**，成功抓取 **13 个商品、104 个 SKU 库存**，
写入数据库并导出 `output/日报_*.xlsx`；另有 2 个商品两次尝试未解析出 SKU（原始页已存
`data/raw_pages/round_10/`，待后续校准解析）。
