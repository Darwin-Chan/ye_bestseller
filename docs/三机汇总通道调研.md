# 三机汇总通道调研（git 私有库与对象存储）

调研日期：2026-09-20。取证方式：调研子代理经 `curl` 抓取官方页面正文（本机 WebFetch 被环境拦截），
逐条标注来源；阿里云 OSS 那条政策由主代理在原公告页二次复核。**未注册任何账号、未提交凭据、未付费。**

本调研服务于 wayfinder 地图「多机分片采集与数据汇总」，判定票据 01（主通道可行性）。

## 结论速览

**A. 分工计划 + 结构化数据包 → Gitee 私有库（主选）；GitHub 仅在实测可达时作镜像。**

- 0 元/月。Gitee 免费额度硬约束：单仓库 500 MB、单文件 50 MB、账号总 5 GB、私有库协作总人数 5 [S1]；
  个人账号不能用 Git LFS（仅对付费企业开放）[S2]。周包 gzip 后 2–4 MB，一机一库即可长期装下（见 A4）。
- 免密推送用 SSH key（每台一把 ed25519，加到同一账号的账户公钥）；多机并发 push 会被 git 以
  non-fast-forward 拒绝，脚本须先 `pull --rebase` 再推并重试 [S12]。

**B. 图片包 → 腾讯云 COS（主选，≈0.6 元/月，前 6 个月约 0.5 元）；七牛 Kodo 作"长期 0 元"备选；
阿里云 OSS 出局；Cloudflare R2 仅作可选第三副本。**

- **阿里云 OSS 有政策硬伤**：2025-03-20 起新开通 OSS 的用户，中国内地 Bucket 经默认公网域名调用
  数据类 API（上传/下载等）一律被拒（`PublicEndpointForbidden`，HTTP 400，EC 0048-00000401），
  须改用自定义域名，而内地 Bucket 域名必须 ICP 备案 [S17][S18]。三台家用机、无备案域名，直接出局。
  **本机复核**：原公告页 HTTP 200，含上述错误码、影响时间 2025-03-20 与受影响 API 清单。
- 腾讯云 COS 默认域名仍可正常调数据 API，限制只是"不预览、强制下载、apk/ipa 禁下"（对程序化 GET 无影响）[S24]。
- 七牛免费额度（实名用户每月）10 GB 存储 + 10 万 PUT + 100 万 GET + 上传流量不限 [S26]，
  且提供 S3 兼容端点，可绕开"测试域名 30 天回收且忽略 URL 参数"的坑 [S27][S28]。

## A. git 托管（承载周计划与结构化包）

### A1 官方配额（一手）

| 项 | Gitee 社区版（个人） | GitHub Free（个人） |
|---|---|---|
| 仓库数 | 1000 个（不限公私）[S1] | 公开/私有均不限量 [S10] |
| 单仓库容量 | **500 MB**（Git）/ 400 MB（SVN）[S1] | 建议 <1 GB、强烈建议 <5 GB（软性）；`.git` 建议 ≤10 GB [S6][S7] |
| 单文件 | **50 MB** [S1] | >50 MiB 警告、**≥100 MiB push 被拒** [S7] |
| 账号总容量 | **5 GB**（含所建组织下所有仓库）[S1] | 无总上限（软性）[S7] |
| 单次 push | 未见官方数值 | 硬限 2 GB [S6] |
| Git LFS | **个人不可用**（付费企业才有）[S2] | Free/Pro 10 GiB 存储 + 10 GiB/月（现行计费平台文档）[S8][S9] |
| 其他 | 私有库协作总人数 5 [S1][S4] | push 速率建议 ≤6 次/分/库 [S6] |

### A2 Windows 免密推送

- **SSH（推荐）**：`ssh-keygen -t ed25519 -C "gitee-m1"` → 公钥加到 Gitee「设置→安全设置→SSH 公钥」
  （账户公钥；部署公钥默认只拉取）[S3]；`ssh -T git@gitee.com` 验证 [S3]；
  remote 用 `git@gitee.com:user/repo.git`。三台各生成一把、互不共用，换机/吊销只影响一台。
- HTTPS + 私人令牌也可（Git Credential Manager 缓存），但 GCM 内置支持列表不含 Gitee，
  走 Basic 通路即可 [S13]。**结论：SSH 最省事，无令牌轮换。**

### A3 多机并发 push

- 分支更新只允许 fast-forward；落后于远端的 push 会被拒绝（"not a fast-forward"），
  官方解法是先 `git pull` / `git pull --rebase` 再推 [S12]。脚本模板：

```bash
for i in 1 2 3 4 5; do
  git add -A && git commit -m "m1 $(date +%F)" || true
  git pull --rebase --autostash && git push && break
  sleep $((RANDOM % 30 + 10))
done
```

- 降低冲突的面板设计：**一机一目录/一机一库**（互不写同一文件），周计划按机名分文件
  （`plan/2026-W38-m1.md`），天然无文本冲突。不用 `--force`。

### A4 落地方案与容量测算

1. 4 个私有库：`raw-m1`、`raw-m2`、`raw-m3`、`plan`（周计划，几 KB）。
2. 每周产出 `data/2026/2026-W38.json.gz`（提交前 gzip：18 MB 文本约压到 2–4 MB）后提交；
   三机各自只写自己的库。
3. 容量：每机每年 ≈ 52 × 3 MB ≈ 150 MB，单库 500 MB 可撑约 2–3 年；账号 5 GB 可放 10 年+。
   库内接近 400 MB 时新建 `raw-m1-2028` 轮换，旧库保留只读。
4. 汇总：每台机器 clone 全部库，pull 后本地跑汇总脚本（无中心节点，符合"每台都能执行"）。
5. Gitee Release 附件（单文件 100 MB、单库附件共 1 GB [S1]）可作备选，脚本化上传未核实，不建议首期采用。

**每月花多少**：0 元。**人工环节**：注册+实名+每台配 SSH 公钥（一次性）；每 2–3 年轮换仓库；
重试 5 次仍失败的 rebase 冲突需人工（一机一目录后极少见）。

### B2 月成本（按存 1 GB、月写 500 MB、月读 1 GB 估）

| | 月成本 |
|---|---|
| 腾讯云 COS | **≈0.63 元**（前 6 个月存储免费 ≈0.51 元） |
| 七牛 Kodo | **≈0.26 元**（存储/请求/上传在免费额度内，仅读流量计费） |
| Cloudflare R2 | **$0**（全在免费额度内） |

按本项目真实量级（月写 <150 MB、月读 <300 MB），COS/七牛都在 0.1–0.4 元/月。

### B3 内容寻址与鉴权做法

- **key 设计**：`img/<sha256前2位>/<sha256>.<ext>`（分片前缀利于列举；R2 key 上限 1024 B、
  七牛 ≤750 B [S38][S30]，64 位十六进制完全够）。内容寻址 → PUT 幂等，先 HEAD 再 PUT 省请求；
  七牛上传策略支持 `scope=bucket:key` + `insertOnly=1` 限"仅此 key、禁覆盖" [S30]。
- **下载鉴权**：各机持有**只读凭据直接 GET** 最省事；预签名 URL 留给临时给第三方的场景。
  私有桶 + 只读子账号，勿开公共读（防流量盗刷）。
- **清单分发**：图片 key 清单（`manifest.json.gz`，几 KB）随 git 周包分发；各机比对本地已有 key，
  只下载缺失的（首次 ≈150 MB，之后每周每台只拉 7–30 MB）。
- **最小权限**：COS 用 CAM 子用户 + 限定到桶内 `img/*` 前缀的 `GetObject/PutObject/HeadObject` [S22][S23]；
  七牛 IAM 子用户 + action 级授权 [S32]；R2 API Token 天然按桶 [S35]。AK 不进 git、各机独立一份、
  建议 3–6 个月轮换；只读汇总机只给 Get/Head。

### B4 推荐与人工环节

**主选腾讯云 COS**（默认域名即可用、工具链最全、几毛/月）；**长期 0 元选七牛 Kodo**
（用 S3 端点或源站域名，**绝不用测试域名当生产地址**）；R2 需国际支付且大陆可达性未核实，仅作第三副本；
**阿里云 OSS 出局**。

一次配置：注册实名 → 建私有桶 → 建子用户按前缀限权 → AK 分发到各机（写进工具配置）→
上传/下载脚本 → 设"免费额度第 6 个月到期"提醒 → 每月看账单。
人工环节：一次性注册/建桶/发密钥；额度到期提醒；AK 轮换 3–6 个月；账单检查。
