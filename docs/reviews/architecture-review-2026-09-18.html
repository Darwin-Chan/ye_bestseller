问题

ADR-0024 花整条 ADR 立的不变量——begin 时冻结 opaque capability、此后不再按 PID 重选——在「自有子进程」这支上退化成「调用方给谁就是谁」：凭 PID 相等收下 Popen，处置再回抄一份 adapter 本来就有的实现。

改法

让 ProcessStopRuntime 独自把冻结的 capability 变成效果（缺省分支转正），Api 只交目标事实，不交 Popen、不交动作。

两处实现已经漂开：gui 那份吞掉 OSError 后回「成功」，runtime 那份回 terminate_failed 进核验重试；browser.port is None 的守卫只在 gui 侧；browser_enabled 否决门只在 runtime 侧。
后果可静态确证：一支已经死掉的旧 Popen 只要 PID 与身份行相等就被当目标，下一 tick 判 GONE，把真正在跑的那次执行的身份行与 browser facts 清掉，界面显示「没有在跑」。
可静态计数：ProcessStopRuntime 全仓只有一个构造点 gui.py:132，两个回调每次都给了——:281-307 的缺省分支在生产里从不执行。
locality：绑定判据收成一条leverage：一种处置，两处消失死缺省转正测试 seam：一条替身覆盖自有与外来

测试 seam：StopRuntime adapter 替身（已有 RecordingStopRuntime）；自有子进程与外来目标走同一条绑定判据后，两种目标共用一组用例。

Deletion test：删掉 gui 的两个方法与两个回调参数、bind 的 own_process 分支——规则集中进 runtime（同款实现已在），唯一要搬的是「port 为空就没有可关的浏览器」一条守卫，它本属 browser facts 状态机。是集中，不是挪走。

ADR-0024：无字面冲突——这是把它的不变量与删除清单走完。同批未走完的还有 begin(target=None) 与 forget()（本轮判为 Worth exploring，见文末）。

问题

响应流是唯一一处「观察者比判据知道得多」的信号：它被当成参数穿过五个 module，而 intervention_kind 对它的真假完全不敏感——同一个谓词在 :136 已经早退，:150 的兜底分支永远到不了。

改法

让 guard 持有它认的全部信号：要么补上「见到 punish 响应、地址正常」这条真判据，要么把 punished 从五个 interface 上撤掉。二选一，不留一条无人用的参数。

不可达已核对：punished 为真时 :136 已返回，为假时 :150 的条件不成立——两个取值都不改变返回值。
现状只能钉住「信号穿到了」：tests/test_browser_pw.py:32 断的是 opened.punished，没有一条用例断言过它判出了什么。
旁证：本库 721 条 verify 事件全是 slider，没有 login 样本，漂移不会自己暴露。
locality：判据与信号同处一室interface：五处收成一处死分支消失leverage：两条路一次兑现

测试 seam：脚本化页面 adapter（tests/helpers.py 的 FakeCard）已经能在不打浏览器的情况下摆出「有响应、地址正常」这一幕；判据收进一处后，用例从「信号穿到没有」改成「这一幕判成什么」。

Deletion test：删掉整条线，对任何输入行为逐字不变（判真的唯一场景已被早退覆盖），复杂度不挪给任何调用方。通过。

ADR-0020 / ADR-0023：不冲突，但更正两条挂账的前提——两处都写着「补采路径缺响应监听」，实际上点击路径这份监听也早已不参与判据。无论删还是救，都会动 ADR-0023 写明的 OpenedDetail(punished=)。
Top recommendation

先做 01：停止目标不能有第二条授权通道

它是本轮唯一被两路独立扫描从 seam 两端分别撞见的候选：一路从界面侧看到处置规则被回抄一份，一路从 adapter 侧看到绑定判据被绕开一条。两者的结论是同一处改动——缺省实现已经在位，删掉多余的那条通道即可，不需要新写逻辑；而且是这轮唯一有具体错误后果的一条（PID 复用下会把真正在跑的执行判成「没有在跑」）。
