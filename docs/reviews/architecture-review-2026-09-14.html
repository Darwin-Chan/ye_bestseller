问题

详情访问的 interface 暴露了“先读、后等、再解析”的顺序知识；observe_page(lambda: html) 成了浅的调用方式，真正的读取异常还在它外面。

改法

把整段读取过程放回观测的 seam 内，让等待后的页面成为输入；deny 规则继续由 guard 持有，事件继续由调用方记录。

隔离复现 A：第 2 次尝试中，验证已解决、页面已有库存；实际只读过 1 次 HTML，结果仍为“失败”，额度耗尽。
隔离复现 B：额度为 2，第一次导航异常；实际只导航 1 次，写入裸异常，未继续第二次尝试。
locality：访问顺序集中leverage：两条路径共用depth：异常进入同一规则

测试 seam：真实临时 SQLite + 脚本化页面 adapter；生产 adapter 为 Playwright。保留成功事件序列，加“验证页变商品页”与“导航失败后成功”两条跨步骤行为验证。

Deletion test：删除 pipeline 中缓存 HTML 再包装、以及预期读取失败的第二条处理路径，复杂度集中回完整观测；只另抽一个导航函数不会增加 depth。

ADR-0013 / ADR-0018 / ADR-0020：延续“失败只翻译一次、deny 共用账目”；验证后重读与导航重试是有意的行为修正。响应流 punish 识别仍是 ADR-0020 的独立挂账。

把停止目标贯穿整个停止窗口

↓

问题

StopWatch 的 interface 收了停止目标，但只在回执阶段使用；强制停止时组合“杀自有子进程、读当前身份、关浏览器”，目标约束泄漏出 seam。

改法

让停止 module 负责从请求到处置的目标一致性；把散开的进程动作按同一个目标与归属组织，已有身份 module 继续提供事实。

隔离复现：begin(ABORT, A) 后把身份换成 B，再推进至 9 秒；真实 StopWatch 调用了 stop_foreign(B) 与浏览器回收。全部动作使用记录型 adapter，未结束真实进程。
locality：目标判据完整leverage：暂停与中止共用depth：调用方少管顺序

测试 seam：从 StopWatch 的 begin / tick 进入，以真实临时库 + 可推进时钟 + 记录动作的 adapter 验证 A→B、同 PID 不同启动时刻、身份暂缺；生产用现有进程动作 adapter。

Deletion test：去掉“强杀时再选目标”这条第二规则，目标知识集中在停止 module；删除 crawler_identity 只会把身份规则复制回来，它应保留。

ADR-0009 / ADR-0016 / ADR-0021：延续进程身份语义；不改变 8 秒 / 回执后 10 秒窗口。未知目标如何收尾、浏览器归属如何跟随目标，是选中后需 grill 的决策。

问题

会话 interface 没有兑现完整的失败保证：端口连接失败已有回收，启动 Playwright、创建页面、设置超时失败却越过它，调用方的 finally 尚未开始。

改法

把资源取得与失败回收收成会话内部一条完整路径；每个阶段只回收已取得且属于本次启动的资源，归属不靠调用方补齐。

3 个隔离故障注入：在 start()、new_page()、set_default_timeout() 分别抛错；浏览器回收调用均为 0，已启动进程的全局引用仍保留。后两种情况 Playwright 的 stop 调用也为 0。
locality：失败回收集中leverage：采集与工具共用depth：交付保证完整

测试 seam：直接从 open_session 注入阶段失败，用 Playwright / 进程的 mock adapter 观察回收；保留现有端口超时与接管既有浏览器的验证。

Deletion test：删除“只有端口超时才回收”的专属分支，让它并入统一建立过程；单把这些分支搬去新文件只会搬动复杂度。

ADR-0019：这是既有失败保证的补全。它否决过“仅为少写几行改成 context manager”；本候选可保留 open / close，不以换调用方式为前提。

问题

点击事件的 interface 包含事件名与卡片身份格式，知识却散在采集、数据层、工具、测试替身；当前生产者与消费者已不相认。

改法

把编码、分类与旧事件解释收成一个 deep module，隐藏原始 note 规则；调用方继续决定何时记录，各指标保留自己的计数单位。

子 agent 内存库复现，主 agent 已核对源码：放入 1 条 click_ok 与 1 条 click_parse_error，真实分析工具返回 attempted=1、success_rate=1.0；解析失败在查询时已被过滤。
locality：事件语义集中leverage：采集与两种统计共用depth：隐藏历史兼容

测试 seam：让真实遍历经事件 adapter 写临时 SQLite，再由数据层与工具消费；保留历史事件兼容。生产 adapter 为数据库事件记录，测试已有事件收集器与临时 SQLite。

Deletion test：去掉多份事件集合与位置编解码，复杂度集中于协议 module；只抽常量仍会把身份与兼容规则留在调用方。

ADR-0013 / ADR-0017 / ADR-0018：事件仍由调用方发，两个指标的公式不合并；日志写失败目前会被吞掉，部分日志却参与轮次失败率，事实的写入保证须在 grill 中明确。

问题

dedupe 的 implementation 需要学习一组只为它存在的 Database interface，以及隐式提交；上层测试也直接依赖 identity / offer_id 物理列。

改法

把机会规则和 SQLite 实现作为一个 module 维护，收起细粒度存储原语；用“另一个商品能否进入、重启后是否仍受限”检验行为。

静态证据：添加、绑定、删除机会的生产调用方只有 dedupe；已有临时 SQLite 用例覆盖预算绑定、重启、合并与退还。这里主要改善 locality，未证明性能问题。
locality：账本规则与存储同处leverage：上层测试少认列depth：内部 seam 收窄

测试 seam：生产持久 SQLite，测试临时 SQLite adapter；保留关库再开的预算用例，将上层物理行断言换成下一次申请的可观察行为，无需新造存储 port。

Deletion test：删除 dedupe 会让预算规则重新散到点击与补采；应吸收它下面的原语。若七个方法原样换个公开类，复杂度只是搬家。

ADR-0003 / ADR-0013 / ADR-0014：预算固定、点卡前申请、跳过退还均保留；已有单采集进程互斥，不以假设并发问题扩大范围。

问题

同一 list_status 被用来表示榜单完整性、是否跑完、续跑动作与界面分组；补采中断后，已完成榜单也失去“完成”事实。

改法

把一店的阶段事实、转换与下一步工作收在一个 deep module；调用方表达中断发生在哪个阶段，读方不再从一列与备注推断多种含义。

源码控制流推论：保存完整榜单 → 补采撞阈值 → 改失败 → 续跑不在 completed_listing_keys → 再遍历榜单。现有用例只覆盖中断那次，未贯穿第二次续跑；未做现场复现。
locality：阶段转换集中leverage：采集、续跑、界面共用depth：读方少猜含义

测试 seam：真实临时 SQLite + 现有 Playwright / ScriptedListing 页面 adapter；完整跑“榜单完成→补采中断→续跑→补完”，同时观察界面与终态事实。

Deletion test：只删记录未完成的 helper 不会减少知识；要吸收的是阶段转换和多处读方判据，单独搬 _run_listing_pw 没有 depth 收益。

明确重开 ADR-0020 的取舍：它有意把补采到阈值的店改为未完成；重开依据是完整榜单事实被抹平，续跑重复遍历与界面含义随之耦合。ADR-0006 的残缺榜单只增不减仍保留；本项不扩展为页级断点续跑。

问题

轮次判定与 views 已接受时刻，采集调用方仍各读挂钟；时间成了隐藏 interface，测试必须知道 detail 内部恰好调用几次 utcnow。

改法

将采集相关的时刻来源从入口传入，把日期与检查点用法收在轮次采集的 seam 内；复用既有轮次判定，不创建通用时间框架。

已知挂账，当前验证：同一条现有“完整提交成功”测试，中午运行通过，模拟北京时间 23:56 则抛 DayBoundaryReached。截止规则正确；问题是该测试没有自主控制时间。原报告已记下 23:55–24:00 的测试窗口。
locality：时间约定可见leverage：整条采集可推进depth：测试无需数内部调用

测试 seam：真实临时 SQLite + 已有脚本化采集 adapter + 可推进时钟，验证 23:54→截止→次日、提交后停止仍留数据；保留与真实时钟无关的解析测试。

Deletion test：删除多个挂钟别名的顺序打桩，时间知识集中在一个可推进来源；只给 utcnow 再套一个同名函数不会增加 depth。

ADR-0005 / ADR-0011：沿用“时刻由调用方给”的方向。本项是已知测试债务的架构形态，不宣称新发现了生产跨日故障。
证据范围 · 源码静态核对 + 只读子 agent 独立探索 + 临时 SQLite / 模拟页面、时钟、进程动作的隔离复现。6 个相关测试文件共运行 96 条：95 通过，1 跳过；未运行全套测试，也未用真实 1688 页面验证。首次回收测试运行被本次临时脚本的日志禁用干扰，修正脚本后重跑通过。
筛选依据 · db.py 虽有 17 次近期改动，计数与迁移已有 ADR-0017 / 0015 承接；不因文件较长就继续拆分。旧报告已完成的六项没有作为未做工作重新列出。
