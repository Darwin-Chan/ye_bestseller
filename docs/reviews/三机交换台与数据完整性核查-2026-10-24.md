## 二、两个程序行为问题已复现

### 1. 无法核算覆盖时仍给出“干净”

`exchange._assemble` 从数据库读取本周计划。计划不存在时，计划机器集合、缺包列表和缺口列表都为空；退出码软告警条件不含“计划未知”，待办也就落到“本周干净”。`_pull_others` 只遍历已经存在的 `raw-*` 目录；已经有一个远端目录时，检查并不能逐台指出名册内尚未克隆的采集来源。

对本机正式库通过 `mode=ro`、`query_only=on` 调用实际报告组装函数，结果为：

```json
{"plan_known": false, "gaps": 0, "missing_machines": [], "exit_code": 0, "todo": ["没有待办：本周干净"]}
```

代码位置：`bestseller_monitor/exchange.py:350`（接入检查）、`:458`（只拉已有目录）、`:782`（只读数据库计划）、`:840`（退出码判据）；`bestseller_monitor/plan_step.py:186`（计划读取契约）。

这与 ADR-0058 的“远端本周尚未发包可返回 0”不同：本例是连应收范围都没有核实，且已有历史来源漏接。修复不能简单把正常的“远端周包未到”重新全部改为失败。

### 2. SKU 完整观测批次没有跨机交换，导入后的图片/证据不可完整使用

- 实际已发布并缓存的 `W42-m1.db.gz` 包含库存 5,120 行、SKU 图片流水 5,120 行、商品信息版本 969 行、图片资产元数据 2,758 行，但 **没有 `sku_observation_batches`**。
- 当前 `export.EXCHANGE_TABLES` 没有该表，`merge._merge_all` 也不导入它。本机正式库中该表行数为 0。
- `sku_drafts._evidence` 依赖完整观测批次或本机快照来定位当次观测。导入库存的日期较新、没有相应观测批次/快照时，会保留库存但无法建立精确观测时间与完整性；没有精确时间时，图片证据读取也不连接已导入的图片流水。
- 实际只读复现：A01 / 商品 `1005822057964` / SKU `6165511159987`，库存日期 2026-10-17。库中存在同日 SKU 图片，哈希 `ae3457532d977e0e3fcb1d6944afd2862b612d46221f317beceef10f32df6004`，来源“主图代填”；实际生产取证函数仍返回 `observed_at=null`、`observation_complete=false`、`image_source=missing`、`image_hash=null`，提示“当次 SKU 图与商品主图均缺失”。
- 因而“图片流水与库存一样多”“资产哈希无损”都不能单独证明 SKU 分析可用。只补 clone、重跑交换不能补回当前载荷未包含的完整观测语义。

代码位置：`bestseller_monitor/export.py:144`、`bestseller_monitor/merge.py:400`、`bestseller_monitor/sku_drafts.py:18`、`:104`。

**主图计数须单独解释：** 两个核算包把 `sku_observation_batches.main_image_hash` 的计数叫“主图”。它不是库内所有商品主图版本的计数。本机虽然该项为 0，`product_information_versions` 实际仍有图片版本，例如 10-12 为 9 行、10-17 为 960 行且哈希非空，9-22、10-03～10-10 也有。因此不能声称“主图实体全部丢了”，也不能由批次口径断言 10-12 前完全没有主图功能。

## 四、建议处理顺序与验收

1. **恢复 m2 本周发布。** 在 m2 保留失败现场，核查 `raw-m2` 的 Git 暂存失败；查清后完成 W43 发布与图片上传。补齐本机 `judged-m2`，查清 judged-m1/m4 的状态读取失败。验收要看到真实发布成功及接收结果，不能只看进程退出。
2. **补齐采集数据来源。** m4 明确要接入 raw-m2/raw-m3；m1 排查 raw-m2/raw-m3 的克隆与包发现；m2 检查 raw-m4 历史归档通道，使 m4 的 W36/W37/W39 历史包可以重放。保留既有克隆及脏现场，不直接删库重建。
3. **修正纯汇总机的覆盖核算。** 让交换流程能按现有计划确认契约取得可验证的当周计划，计划未知或应接来源缺失时明确报告“完整性未核验”，不能显示“没有待办”。不应要求纯汇总机实际启动正式采集来取得计划。
4. **补齐 SKU 观测交换契约。** 为完整观测批次及当次主图/SKU 证据增加兼容的导出与幂等导入，再重发受影响周包。验收同时验证库存、SKU 图、观测完整性、精确时间和分析实际取证结果；不能仅放宽图片时间匹配或借用邻近观测来掩盖缺证据。
5. **按相同截止范围重新核算。** 原始库存至少应覆盖本次已知 95,210 行的组级下界；最终总数还要考虑后续采集、m3 额外数据和合法冲突裁决。逐日期/店铺对齐后继续核对主键、库存/价格值、图片引用及完整观测。确认“未采集”与“已采但未收到”分别记账；前者不能通过同步虚构历史观测。
