现状

改法

编排收进一个有 start / tick / state 的 module；采集侧让每个停止异常自带 scope 与本店备注，驱动只按 scope 收尾。

收益

  • locality：窗口只在一个 module 里
  • depth：测试按状态推进，不改进程
  • 承重的 except 顺序变成结构

证据

协议本身没有 module：self._stop 被 pause_run:570、abort_run:602、_begin_stop:702、_stop_state:712、_enforce_stop_deadline:718、_note_stop_ack:739、_force_stop:754 七处读写，测试只能 api._stop["deadline"] = time.time() - 1 来把窗口推到点（tests/test_gui.py:213/228/241/688/707/721/735）——这是穿过 interface 之后在测 implementation。

采集侧的同一族知识摊在三处：STOP_EXCEPTIONS（pipeline.py:38-39，只声明了半族）、_run_listing_pw 的六段阶梯（:409-432，决定本店备注）、_run_round_locked 的五段阶梯（:177-209，决定轮次终态）。因为 RoundDenyExceeded 继承 RoundPauseRequired（browser_pw.py:219），:412 必须排在 :422 之前——两段对调，整轮中止会静默降级成「暂停、可续跑」，而这个顺序没有任何地方声明。

ADR-0009 定的窗口与顺序不动，这条只是把编排收进一个 module，让它能被按状态推进地验证；ADR-0009「关掉界面就没有强杀兜底」那条代价也才有一处可以指认。
