# 三机上机清单（m1 增量 · m2/m3 · 纯汇总机 · 三机验收）

机制与口径全文在 `.scratch/multi-machine-collection/spec.md` §12（机器本地文档）；术语见
[CONTEXT.md](../CONTEXT.md)。本文件是**可执行的操作单**：m1（现机，采集机）已完成的部分
与待人工的步骤、m2/m3 接入、纯汇总机接入、三机验收怎么跑，一条一条来。

一句话背景：三台采集机各自采自己的份额，靠**交换区**（4 个 Gitee 私有库 + 1 个 COS 私有桶）
交换每周的结构化包与交换集；各台最终收敛到同一份全量库（收敛成立的前提：m1 要把
2026-09-05 起的历史按周补发出去）。

机器专属值（本机）：`machine_id = m1`，角色采集机，交换区根 `F:/AI/bestseller_runtime/exchange`，
本机库 `F:/AI/bestseller_runtime/data/bestseller.db`。

## 二、m1 待人工步骤（按序）

### 第 8 步 · Gitee：SSH key 与四个私有库

1. 生成 ed25519 公钥（本机第一次；已有一把就跳过）：

```bash
ssh-keygen -t ed25519 -C "m1 collector" -f ~/.ssh/id_ed25519
```

2. 把 `~/.ssh/id_ed25519.pub` 的内容贴进 Gitee →「设置 → SSH 公钥」。
3. 在 Gitee 建 **4 个私有库**（空库即可，初始化与否都行）：`raw-m1`、`raw-m2`、`raw-m3`、`plan`。
4. 验证：

```bash
ssh -T git@gitee.com
```

判据：出现 `Hi <账号>`（首次问 fingerprint 输 yes）。

### 第 9 步 · clone 四个交换库（顺带验写权限）

```bash
mkdir -p F:/AI/bestseller_runtime/exchange
cd F:/AI/bestseller_runtime/exchange
git clone git@gitee.com:<你的账号>/raw-m1.git
git clone git@gitee.com:<你的账号>/raw-m2.git
git clone git@gitee.com:<你的账号>/raw-m3.git
git clone git@gitee.com:<你的账号>/plan.git
```

判据：

- 四个目录都在（`raw-m2` / `raw-m3` 先空着没事——别机还没接入；数据交换台会把「本机的
  raw 库没 clone」「没有别的 raw 库可收」如实记进报告）；
- **写权限**（spec 第 8 步的判据放在这里——要先 clone 才有东西可推）：在 `raw-m1` 里推一个
  空提交成功、对 `plan` 拉取成功：

```bash
cd F:/AI/bestseller_runtime/exchange/raw-m1
git commit --allow-empty -m "verify write access"
git push
cd ../plan && git pull --rebase
```

  **推送被提示实名**（票据 01 的遗留实测项）：按提示完成，结论记回
  `.scratch/multi-machine-collection/issues/01-primary-channels-git-and-object-storage.md`。

### 第 10 步 · COS：私有桶与最小权限 AK

1. 腾讯云建一个**私有**桶（如 `bestseller-exchange-<APPID>`）。
2. 建一把只允许 `img/*` 前缀读写的子账号 AK（采集机档位；策略里 Resource 写桶下 `img/*`）。
3. 装 [coscli](https://github.com/tencentyun/coscli)，按它自己的帮助配好这把 AK（配置在
   `~/.cos.yaml`，密钥不进代码仓、不进日志）：

```bash
coscli config --help
```

4. 验证（下面那条就是程序实际发起的命令形态）：

```bash
coscli ls -r cos://<桶名>/img/
```

判据：能列出（空桶也是成功）；再传一个测试对象能传能取；用这把 AK 访问 `img/` 以外的
前缀应被拒（被拒 = 配置正确）。
5. 把桶名填进 `config/config.toml` 的 `machine.cos_bucket`。

### 第 11 步 · 名册

在 `plan` 克隆里写机器名册并推送（**顺序即平局顺序**；m2/m3 没准备好就先不加——在册的
机器就要分担采集）：

```bash
cd F:/AI/bestseller_runtime/exchange/plan
echo '["m1"]' > machines.json
git add machines.json
git commit -m "add machine roster"
git push
```

判据：`plan` 库根目录有 `machines.json`。

> 共享店铺清单（`config/shops.csv` → `plan` 库，转 UTF-8 带 BOM）**不用手推**：第一次打开
> 采集程序时由准备串自动完成，之后本机那份是副本、两边按内容哈希同步。

### 第 12 步 · 第一次打开采集程序，走完准备串

双击 `dist/bestseller_gui.exe`（或 `python gui.py`）。判据：

1. 界面无报错；
2. 准备串走完：pull 计划库 → 同步清单（这次是「首次推送」）→ 生成并发布本周计划；
3. 开始页默认勾选 = 本周计划里归 m1 的店（现在名册只有 m1，应是全部 12 家）；
4. 去 `plan` 库确认：`plan/<年>-W<周>.json` 与 `.md`、`published/m1.md` 已发布，根目录多出
   `shops.csv`（UTF-8 带 BOM）。

### 第 13 步 · 首次数据交换台（含历史补发）

**本周那一趟改走交换台壳**：双击 `dist\bestseller_exchange.exe`（等价
`python exchange.py --window`），窗口里点「导出&汇总」——跑完窗口显示结局行（报告路径 +
退出码口径），看一眼再关窗。**补历史两条仍走脚本**（壳不接 `--week`，收到会明确拒绝并
提示走脚本）：

```bash
cd F:/AI/projects/bestseller
python exchange.py --week 2026-W36
python exchange.py --week 2026-W37
```

同一台机器同一时刻至多一次交换台运行（窗口与命令行同规）：窗口开着时命令行跑不动，
双击第二次壳会弹「已经在运行」后退出；运行中关窗只记录一笔（重跑能修：导出幂等、
导入有幂等账、报告同周重写——见 §六）。

判据：

- `raw-m1` 远端出现 `data/2026/W36-m1.db.gz`、`W37-m1.db.gz` 和本周的包（各带同名
  `.manifest.json.gz`）；行数如实——演练对照值：**W36 inventory 6,703 行、W37 15,612 行**、
  本周当前为 0 行（09-13 之后没采过；报告会把本机缺哪几天逐条说明——09-21 当天跑是 12 家店
  各缺 1 天，晚几天再跑条数随之增长）；
- 退出码：W36/W37 应为 **0**；本周若尚无采集应是 **1**（每条例外都有说明：本机缺哪几天）。
  出现 2 = 本机没做成事（看输出第一行的原因，多半是 clone 或凭据还没就位）；
- 报告落在 `F:/AI/bestseller_runtime/exchange/报告/<年>-W<周>.md`；同周再跑一次 → 重写同一份、
  开头「本次运行」写明这次做了什么（演练里第二次跑就是「本周包上次已发布（无新提交）」）。
  （采得较晚、在别人之后又收过包的那台，同周第二次运行可能再发一个包——见 §六 的说明。）

## 三、m2 / m3（采集机：采集 + 导出 + 汇总）

一台全新电脑，13 步全走；与 m1 同形的步骤只点差异（机制与判据的全文在 spec §12）。

1. **环境与依赖（第 1..3 步）**：Edge 在默认路径；Python 与现机同大版本（或留
   `BESTSELLER_PYTHON`）；clone 代码仓 → `pip install -r requirements.txt` →
   `python -m playwright install chromium`。判据：`python -c "import webview, playwright, PIL"`
   无错。**这一步顺带是 GitHub 大陆连通性实测**——clone 不通就退到离线分发（打包 zip 拷贝），
   结论记回 `.scratch/multi-machine-collection/issues/01-primary-channels-git-and-object-storage.md`
   （m1 现机 2026-09-21 实测：`ls-remote` 2 秒、`clone --depth 1` 31 MB 约 2 分 40 秒——通但慢；
   各机网络不同，仍要各自实测）。
2. **建壳（装 PyInstaller + 两只壳）**：`pip install pyinstaller`（不进 requirements，
   每台手装一次）；然后 `python tools/build_exe.py --target gui` 与
   `python tools/build_exe.py --target exchange`。判据：两条都以
   `OK：…（… KB），项目根 …` 收尾（自检断言产物 frozen、不含项目代码）；产物
   `dist\bestseller_gui.exe` 与 `dist\bestseller_exchange.exe`。exe 留在 `<项目根>\dist\`
   别挪（项目根按 exe 位置推导，挪走就起不来）。
3. **运行根（第 4 步）**：`data/` `logs/` `profiles/` `screenshots/` `raw_pages/` `secrets/`
   `exchange/`；把 `config/config.example.toml` 复制成 `config/config.toml`，`[paths]` 全写成
   本机绝对路径。
4. **浏览器与账号（第 5..6 步）**：`user_data_path` 指本机 profile、`attach_port` 用本机端口；
   `python login_chrome.py` 扫**本机专属**的 1688 账号（一台一账号）；冒烟采集
   `python run.py --pages-per-shop 2 --max-detail 20 --limit-shops <一家本机店>` 走通一轮、
   无登录墙/滑块告警。
5. **机器标识（第 7 步）**：`config.toml` 写 `machine.machine_id = "m2"`（或 m3）。
6. **凭据（第 8..10 步）**：Gitee SSH（ed25519 → 注册为本机账户公钥；判据：对 `raw-m2` 推一个
   空提交成功、对 `plan` 拉取成功；**推送若被提示实名就照提示完成**，结论记回 wayfinder 票据 01）；
   clone 4 个库到 `<运行根>/exchange/`；COS 私有桶 + 读写限 `img/*` 的 AK（能传能取；
   `img/` 以外被拒）填进 `machine.cos_bucket`。
7. **名册（第 11 步）**：把 m2（m3）加进 `plan` 库的 `machines.json` 并推送——**在下一份计划
   生成前加**，在册的机器下一份计划起就要分担采集。本机的 `config/shops.csv` **不用手建**：
   第一次打开采集程序时准备串会从计划库把共享清单拉下来当本机副本（UTF-8 带 BOM，与
   `plan` 库那份同字节）。
8. **第一次打开界面（第 12 步）**：双击 `dist\bestseller_gui.exe`（等价 `python gui.py`）。
   判据：准备串走完（pull 计划库 → 拉共享清单副本 → 读到本周计划
   并落库）；开始页默认勾选 = 本周计划里归本机的店（本周空手也有明说，是合法状态）。
9. **首次数据交换台（第 13 步）**：双击 `dist\bestseller_exchange.exe`，窗口里点「导出&汇总」
   （等价 `python exchange.py --window`；只跑一半点「仅导出 / 仅汇总」）。判据同 §二第 13 步：
   退出码 0，或 1 时每条「需要看一眼」都有说明；`raw-m2` 出现本周包；报告生成；同周重跑重写
   同一份。第一次运行还会把交换区里别的机器发过的**历史包**一起收进来（汇总这半不只收本周）。

## 四、纯汇总机（只合并与展示，不采集）

7 步，与采集机的差异都在「不装采集那半」。

1. 环境同 §三 第 1 步，但**不建 Edge 专用 profile、不登录 1688、`playwright install chromium`
   可跳过**（合并/分析路径不拉起浏览器；日后哪个工具报缺浏览器，补跑即可）。判据：
   `python -c "import webview, playwright, PIL"` 无错。
2. clone 代码 + 建运行根（同 §三 第 3 步）；**只建交换台壳**（`pip install pyinstaller` +
   `python tools/build_exe.py --target exchange`，同 §三 第 2 步）——不建采集壳 exe（纯汇总机
   不采集）；分析仍 `python analyze.py` 起。
3. 只读凭据：git——本机 ed25519 作为**只读部署公钥**加进四个库（判据：clone/pull 成功、
   push 被拒 = 配置正确）；COS——只读 AK（判据：下载已知对象成功、上传被拒）。
4. clone 4 个库到交换区根（同 §三 第 6 步）。
5. `config.toml` 的 `machine.role` 写 `"merge_only"`、`machine_id` 自取（如 `m4`）。判据：
   在本机试开采集（界面入口或 `run.py`）→ 明确拒绝并说明理由，库不被写轮次/快照/采集身份。
6. 冷启动：双击 `dist\bestseller_exchange.exe` 点「导出&汇总」（等价 `python exchange.py`；
   **一轮就够**——汇总这半会把交换区里的全部历史包重放一遍；「仅导出」按钮在这台机器上
   置灰，导出这半按「本机是纯汇总机，跳过」如实记）。
   前置：m1 的历史补发已完成（§二第 13 步）。判据：退出码 0；**第一次运行**的报告里
   「收进来的包」= 交换区全部历史包（含 W36/W37 那样的历史周）；交换集各表有数；图片按
   清单从 COS 补齐（首次全量，约 150 MB 量级）。之后每周再跑，表里只列本周的包（历史已经
   收进幂等账，不再占行）——「全收进来了没有」以 §五 核对工具那行「幂等账收进来 N/N」为准。
7. 展示验证：`python analyze.py`。判据：能选日期、出畅销品分析页；无「库为空」。

## 五、三机验收（一期真实运行；口径全文见 spec「三机验收口径」）

验收周跑完之后：

1. **收敛同步**：三台各再跑一次数据交换台（把别人最后发布的包都收进来——先跑的那台可能
   还没收到别人最后一版）；纯汇总机也跑一次它的冷启动那轮。
2. 把要对照的库文件拷到一起（三台的 `bestseller.db` + 纯汇总机那份），在一台上跑核对
   （`--week` 填验收周、`--as-of` 填那一周的周日；库文件路径按实际情况改）：

```bash
python tools/acceptance_check.py --week 2026-W42 --as-of 2026-10-18 --plan F:/AI/bestseller_runtime/exchange/plan --exchange-root F:/AI/bestseller_runtime/exchange --machine m1=F:/AI/bestseller_runtime/data/bestseller.db --machine m2=D:/验收/m2.db --machine m3=D:/验收/m3.db --merge-only m4=D:/验收/m4.db
```

判据：退出码 **0**、结果行「通过 · 跑 7 项：过 7 / 没过 0 / 跳过 0」。五条口径的读法写在
`tools/acceptance_check.py` 的模块 docstring 里：

- 计划核对行「相邻周同机器 0 处」（读 `plan/<周>.md` 那行人核对的那一行）；
- 三台各自完成本机份额（份额 × `rounds.run_date × shop_rounds` 逐条对照，缺口逐条带当天
  轮次终态当说明）；
- 三台都发布了本周包；缺席的必须在本机周报里被点名（「还没来的包」为空或已有说明）。
  报告是本机视角的：这条核的是**跑工具这台**那份周报——想要三台的报告都被核，就在三台
  各跑一次这个命令（或把别机的报告拷到对应交换区根的 `报告/` 下再跑）；
- 任取两台逐表一致（交换集里承载取胜结果的五张表；冷启动那台的 `inventory` 覆盖起止会
  打出来——应从 2026-09-05 起）；
- 纯汇总机冷启动重放：一轮收全交换区历史包、各表有数、图片补齐。
3. **分析一眼**：数据逐表一致 ⇒ 同一份数据上分析确定产出同一份结果；在任两台各跑一次
   `python analyze.py`，对一眼畅销品结果（这一步人看，工具不替）。
4. 证据（日期、退出码、报告路径、两份 analyze 截图或同值结论）记到票 13 的评论里。

## 六、之后每周的常态

- 采集机每周至少跑一次数据交换台（导出 + 汇总 + 周报）；用壳的走法：双击
  `dist\bestseller_exchange.exe` → 点「导出&汇总」→ **跑完再关窗**（运行中关窗只记录一笔，
  不拦——这一趟可能半途而废，但重跑能修：导出幂等、导入有幂等账、报告同周重写）；补历史或
  只跑一半之外的花样（`--week` 等）走脚本 `python exchange.py …`。
- 报告里「还没来的包」「缺口」「冲突」三节照实读：缺口补不了就如实记，冲突按赢家口径查；
- 名册加机器只在对方就绪后做（下一份计划起生效）；
- 谁错过了一周：它补发的历史包会被各台**下次运行自动收进来**（汇总这半不只收本周）；
- 同周再跑一次：报告重写同一份、「本次运行」行写明这次做了什么。注意一种正常现象：
  本周采得较晚、在别人之后又收过包的那台，同周**第二次**运行可能再发一个包（把合并进来
  的身份行补发一遍——机与机的时间戳就是这样互相 MAX 收敛的）；第三次起稳定为
  「无新提交」。判据按「重写同一份 + 本次运行行写明做了什么」看，别把这一份当异常。
