## 3. 演示路径与复现

规格演示路径：选日期 → 固定数据 → 模型建议 → 对比纠错 → 筛选批量确认与撤回 → 暂存 → 关闭重开 → 新日期复用 → 保存排名 → 离线报告。

复现方式：

```bash
python -m unittest tests.test_e2e_acceptance -v
```

`tests/test_e2e_acceptance.py` 共 5 项，全部走真实页面与真实服务：

| 用例 | 覆盖的流程段 |
| --- | --- |
| `test_demo_path_select_dates_to_offline_report` | 选日期 → 覆盖核对 → 固定数据 → 对比纠错（候选弹窗）→ 批量确认 → 撤回 → 暂存 → 关闭重开 → 继续上次分析 → 保存排名 → 导出 → 断服务离线打开 |
| `test_one_snapshot_feeds_sales_representative_tree_and_charts` | 规格切换 + 缺失 + 补货 + 跨店合并落在同一快照；代表商品、组总销量、构成树与图表同源 |
| `test_new_range_reuses_confirmation_in_the_browser_and_recomputes_sales` | 换到更长区间：页面按新数据重算，适用的已保存确认自动复用；旧分析不受影响 |
| `test_scale_review_stays_usable_at_3012_products_across_pages` | 12 店 3,012 件：覆盖表、全量搜索、跨页勾选、批量确认 |
| `test_draft_holding_all_four_states_survives_restart_and_source_changes` | 一份草稿同时含已确认/待确认/排除/撤回，暂存 → 终止应用 → 改源库存与商品图 → 重开恢复旧快照 |
