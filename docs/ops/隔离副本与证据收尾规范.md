# 隔离副本与证据收尾规范

生效日期：2026-10-08。创建/重用隔离副本、在副本中跑测试、工单关闭与清理时使用。
适用于本项目的开发/验证材料，不改变真实运行目录、程序产物和其他机器记录包的路径。

## 1. 先确定主仓与落点

“主仓”是承担本次工单的原始工作仓库，不是隔离副本。以下本机示例的主仓为
`F:\AI\projects\bestseller`；在其他机器按实际主仓替换，不能按副本当前目录重新推导。

| 材料 | 相对主仓的位置 |
|---|---|
| 隔离代码副本 | `.scratch/sandboxes/<feature>/<ticket>/bestseller/` |
| 并行 / 重跑副本 | `.scratch/sandboxes/<feature>/<ticket>/<run>/bestseller/` |
| 工单验收证据 | `.scratch/logs/tickets/<feature>/<ticket>/<run>/` |
| 诊断 / 截图输出 | `.scratch/tool-output/<feature>/<ticket>/<run>/` |
| 工单及收尾清单 | `.scratch/<feature>/issues/<NN>-<slug>.md` |

`feature` 与工单目录的 slug 一致，`ticket` 与票号一致；`run` 使用时间戳或有意义的唯一名称。
副本叶子目录固定叫 `bestseller`；既有测试和壳定位约定依赖它。

创建前将主仓、源和目标解析为绝对路径，确认目标位于主仓的 `sandboxes` 范围，
且目标及其父目录不是 junction / symlink 等重解析点。已存在的副本先核对所属工单、
提交和未保存材料；需要新环境就另开 `run`，不覆盖、合并或自动删除旧目录。
完成条件：在工单记下主仓、完整副本路径、来源提交与本次运行标识。

## 2. 创建副本：明确测试哪份代码

以下 PowerShell **示例只创建已提交代码的副本**，不是一键验收脚本。
替换 `feature` 和 `ticket`，按上节完成路径检查后执行：

```powershell
$ErrorActionPreference = 'Stop'
$MainRoot = 'F:\AI\projects\bestseller'
$Feature = 'example-feature'
$Ticket = '01'
$Run = Get-Date -Format 'yyyyMMdd-HHmmss-fff'
if ($Feature -notmatch '^[a-z0-9][a-z0-9-]*$' -or $Ticket -notmatch '^\d{2,}$') {
    throw 'feature 必须是 slug，ticket 必须是票号'
}
$RunRoot = Join-Path $MainRoot ".scratch\sandboxes\$Feature\$Ticket\$Run"
$ReplicaRoot = Join-Path $RunRoot 'bestseller'
if (Test-Path -LiteralPath $RunRoot) { throw '运行目录已存在，请另取 run' }
[IO.Directory]::CreateDirectory($RunRoot) | Out-Null
git clone --no-hardlinks -- $MainRoot $ReplicaRoot
if ($LASTEXITCODE -ne 0) { throw '克隆失败：保留现场，不自动清理' }
```

- 本机新副本默认用独立 Git clone；`--no-hardlinks` 避免与主仓共用对象硬链接。
  特殊需要使用 `git worktree` 时仍放上述范围，登记分支与 worktree 状态；
  之后按 Git worktree 的方式解除，不直接递归删注册目录。
- clone 只包含提交，不带主仓未提交修改或未跟踪文件。要验证当前工作改动，
  先点名本次测试所需文件，将其当前版本补入副本并记录清单；包括新增文件与删除操作。
  不靠“克隆成功”推断已测试未提交实现，不替其他会话暂存、提交或 stash。
- 按测试要求准备 `config/*.toml` 和 `shops.csv`；审查实际配置中的数据库、缓存、
  profile、交换库和其他写入路径，使它们指向该副本下的测试数据。示例配置也要审查，
  不将主仓真实配置原样复制后直接运行，更不能写入 `F:\AI\bestseller_runtime`。
- 不复制主仓整棵 `.scratch`、真实数据库、浏览器登录态或 `.venv`；只补点名且必要的
  测试输入。确需历史输入时记录来源并使用副本，不能覆盖原件。
- 虚拟环境在新副本路径重建，不搬运旧环境；创建失败或测试失败也登记残留位置。

完成条件：副本来源与待测工作改动核对一致，测试配置的写入路径已检查为隔离路径。

## 3. 证据写回主仓，不随副本一起删除

先固定主仓证据绝对路径，再进入副本。以下示例接上节变量，仅在副本准备好后执行：

```powershell
$Evidence = Join-Path $MainRoot ".scratch\logs\tickets\$Feature\$Ticket\$Run"
if (Test-Path -LiteralPath $Evidence) { throw '证据目录已存在，请另取 run' }
Push-Location -LiteralPath $ReplicaRoot
try {
    python tools/run_full_suite.py --log-dir $Evidence
    if ($LASTEXITCODE -ne 0) { throw "全量未通过，保留证据：$Evidence" }
} finally {
    Pop-Location
}
```

沿用 AGENTS.md 的分段全量收尾口径，不额外增加全量频率。运行器默认日志在**副本**内，
上述显式参数将日志和 `summary.txt` 放在主仓；工单记录“合计 / 对账 / 结论”和退出结果。
诊断工具若默认按当前副本定位 `.scratch/tool-output`，显式指定主仓输出目录；
工具不支持指定时，收尾前复制其必要产物到主仓并核对数量、大小和 SHA-256。

完成条件：证据能在主仓独立找到，工单有绝对路径，不能只靠副本内日志证明验收。

## 4. 工单关闭：逐项给出处置结论

关闭实施工单前补以下模板，无副本/无证据的项目也明确填 `未创建` / `无`。
仅当路径、保留材料和处置结论均已记录，才将工单置为终态：

```markdown
## 目录与证据处置

- 主仓：<绝对路径>
- 隔离副本：<每个完整路径；或未创建>
- 来源：<提交 / 补入的工作改动清单 / 测试配置来源>
- 验收证据：<主仓绝对路径与 summary 结论；或无及原因>
- 永久保留：<必要日志、截图、临时脚本、独有材料及其主仓保留位置>
- 可删除候选：<完整副本、旧虚拟环境、缓存的精确路径；或无>
- 暂留待确认：<路径、原因、负责人或后续确认条件；或无>
- 实际清理：<未执行 / 用户授权记录、执行日期、删除路径和校验结果>
```

“永久保留”指不随测试副本清理，并非已有异地备份；`.scratch` 不进 Git，
需要跨机器或长期备份的证据应另行打包并按项目记录通道保存，避免误认为提交代码会带走证据。
工单可带明确暂留原因关闭，但不能无记录地留下副本。已关闭历史工单不批量改写。

## 5. 清理前的门槛

可删除候选不等于授权删除。实际清理前：

1. 确認用户授权、所属工单与精确绝对路径；限定在点名副本内，检查所有父目录及子项的重解析点。
2. 复核无新增独有提交、改动、未跟踪/忽略材料、数据库或工作进程占用。
   不能仅凭 `git status` 干净、目录年龄或 `.scratch` 名称判断可删。
3. 必要材料先保存到主仓证据区/归档区，逐文件校验 SHA-256，并确认保留位置不在待删副本内。
4. 按明确路径清理，记录完成项；出错停止，不扩大删除范围。真实运行目录、其他会话材料、
   受保护历史快照与共享父目录均不在默认清理范围。

完成条件：实际删除与工单清单一致，保留证据仍可读取，留下操作记录。

本规范是创建与收尾的流程约束，不是后台监控或文件系统强制拦截；
不安装定时任务，不自动删除目录，也不批量迁移既有 `.scratch` 工单与快照。
