# m4 过渡期操作单（临时采集 → 转纯汇总机）

口径与理由在 [ADR-0034](../adr/0034-machine-identity-and-role-change.md)；通用判据全文在
[三机上机清单](三机上机清单.md)。本文件只写 **m4 这台机器**在过渡期要做什么、按什么顺序做。

**向导怎么跑**：在 Git Bash 窗口里 `bash tools/setup_wizard.sh`；PowerShell / cmd 里没有
`bash` 这个命令，用 `tools\setup_wizard.cmd`（双击也行，`--role-change` 等参数照传）。

三条定论先摆着，后面每步都从它们来：**编号 m4 终身不变**；**过渡期按采集机跑、测试期的观测
就是真观测**（不抹）；**转角色那天名册先撤、凭据真换、行为自证、库沿用不换**。

---

## 一、建库与上机（一次性）

1. **Gitee 建私有库**（空库即可）：`raw-m1`、`raw-m2`、`raw-m3`、`raw-m4`、`plan`，
   外加每台机器一本判断库 `judged-m1`、`judged-m2`、`judged-m3`、`judged-m4`。
   m1..m3 留给还没到位的三台采集机，先建着没内容。
2. **跑向导**：

   ```bash
   bash tools/setup_wizard.sh
   ```

   它按顺序做十步：开工检查（**第 1 步会问一次本机编号**——现在配置里是 `m1`，填 `m4`；编号定下
   不该再改，见 ADR-0034）→ SSH key → 建库指引 → clone（本机那条 + plan + 名册里别家的）
   → COS 桶与 `img/*` 限额 AK（采集机档核「能传能取」；腾讯云那些点击路径见
   [腾讯云 COS 上机手册](腾讯云COS上机手册.md)）→ 名册写 `m4`
   → DeepSeek key 与 `config/analysis.toml`（`direct` 模式 + 视觉档模型）→ 视觉通路实跑核验
   → 判断库（建 `judged-m4`、clone、验写权限）
   → 收尾。
3. **首次打开采集程序**（双击 `dist` 里的采集壳，或 `python gui.py`）：准备串会 pull 计划库 →
   同步共享店铺清单 → 生成并发布本周计划。判据：界面无报错；开始页默认勾选 = 本周计划里归
   m4 的店（名册只有 m4 时就是全部）。

## 二、过渡期：测试采集走真通道

4. **补发历史周**（脚本入口不接在壳上）：

   ```bash
   python exchange.py --week 2026-W36
   ```

   ```bash
   python exchange.py --week 2026-W37
   ```

   判据：`raw-m4` 远端出现 `data/2026/W36-m4.db.gz`、`W37-m4.db.gz` 与同名 `.manifest.json.gz`；
   退出码 0。
5. **限量冒烟采集**：开始页只勾一两家店、跑一轮。判据：界面无报错，库里当天有行。
   （不急着全量：过渡期的缺口会被周报如实记，验收看的是验收周。）
6. **导出 & 汇总**（真通道）：双击 `dist` 里的交换台壳 → 点「导出&汇总」（等价
   `python exchange.py --window`）。判据：退出码 0 或 1，报告落在 `<交换区根>/报告/<周>.md`。
   此时 raw-m1..3 还空着，报告会如实写「没有可收的包」——正常。
7. **分析**：双击 `dist` 里的分析壳（或 `python analyze.py`）。判据：同款确认页能给出模型建议
   （视觉通道在向导第 8 步已实跑验过）。

## 三、转角色那天

**前置铁律：历史补发必须已经跑完**（§二第 4 步）。角色一改成 `merge_only`，导出这半就关了
（交换台按「本机是纯汇总机，跳过」如实记）——本机采集史再也没有通道发出去；Gitee 凭据保留之后
这层顺序更隐蔽（没有「push 被拒」这种自证来提醒）。

> **2026-09-23：本机已走完这趟**——名册与历史补发由转角色会话做，档位、COS 收窄与自证收尾；
> COS 那次是**收窄原来那把采集机子账号的策略**（没有另发新 AK），效果同「只读档」。留档：
> `.scratch/logs/tickets/multi-machine-collection-impl/ticket11/转角色收尾与自证-2026-09-23.log`
> 与同目录的「转角色后发布判断集」日志；状态行在 [三机上机清单](三机上机清单.md) §一。

8. **跑转角色模式**：

   ```bash
   bash tools/setup_wizard.sh --role-change
   ```

   五步：现状（含本机采集史行数）→ 名册撤 m4 并推送 → 写 `role = merge_only` 与两个
   `read_only` 档位 → 换只读凭据的指引（**COS 换只读 AK；Gitee 公钥保留不撤**——判断库要发布
   判断，ADR-0039 决策 3；采集通道的「不写」由角色闸门承接）→ 行为自证与归档。
9. **判据**：COS 上传被拒（换上的 AK 是只读档）；判断库仍推得动
   （`git -C <交换区根>/judged-m4 push` = 转角色后照常发布判断集）；交换台的导出这半从此按
   「本机是纯汇总机」跳过（不靠 Gitee 凭据拦）；本机库归档到
   `<data_dir>/backup/bestseller-<日期>-pre-role-change.db`。
10. **之后**：交换台的导出这半自动按「本机是纯汇总机」跳过（入口保留）；汇总、周报、分析照常；
    名册保持为空，直到下一台采集机接入——**它接入的第一件事是把自己写进名册**（上机清单
    第 11 步），在那之前别在别的机器上跑准备串（空名册会让计划生成当场拒绝）。

## 四、不做的事（说在明处）

- **不换编号**：编号是身份，改了要付平局定序与冲突账的账。
- **不换库**：交换台不收本机编号的包，换库等于 09-05 起的基线永远回不来。
- **不删测试期的包**：观测是真的，删了那几天就是永久空白。
- **不移交 1688 账号与 profile**：身份跟机器走；将来若要再采，改回 `collector` 即可。
