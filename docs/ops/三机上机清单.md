机制与口径全文在 [多机分片采集机制](多机分片采集机制.md)；术语见

配置里写的还是 `m1`——缘由与代价见 [ADR-0034](../adr/0034-machine-identity-and-role-change.md)），
角色 `collector`（过渡期临时采集，终局转 `merge_only`，见
[m4 过渡期操作单](m4过渡期操作单.md)），交换区根 `F:/AI/bestseller_runtime/exchange`，
本机库 `F:/AI/bestseller_runtime/data/bestseller.db`。

## 二、本机（m4）的人工步骤（按序；2026-09-22 已按此走过一遍）

### 第 8 步 · Gitee：SSH key 与五只私有库（2026-09-22 ✅）

1. 生成 ed25519 公钥（本机第一次；已有一把就跳过）：

```bash
ssh-keygen -t ed25519 -C "m4 collector" -f ~/.ssh/id_ed25519
```

2. 把 `~/.ssh/id_ed25519.pub` 的内容贴进 Gitee →「设置 → SSH 公钥」。
3. 在 Gitee 建 **5 个私有库**（空库即可，初始化与否都行）：`raw-m1`、`raw-m2`、`raw-m3`、
   `raw-m4`、`plan`——m1..m3 留给还没到位的三台采集机，先建着没内容（ADR-0034 决定 6）。
4. 验证：

```bash
ssh -T git@gitee.com
```

判据：出现 `Hi <账号>`（首次问 fingerprint 输 yes）。

### 第 9 步 · clone 交换库（本机那条 + `plan`，顺带验写权限）（2026-09-22 ✅）

```bash
mkdir -p F:/AI/bestseller_runtime/exchange
cd F:/AI/bestseller_runtime/exchange
git clone git@gitee.com:<你的账号>/raw-m4.git   # 本机那条；别的机器换成自己的编号
git clone git@gitee.com:<你的账号>/plan.git
```

判据：

- 目录都在（本机那条 raw 库 + `plan`；名册里别家的等它们入册再 clone——交换台会把
  「本机的 raw 库没 clone」「没有别的 raw 库可收」如实记进报告）；
- **写权限**（第 8 步的判据放在这里——要先 clone 才有东西可推）：在 `raw-m4` 里推一个
  空提交成功、对 `plan` 拉取成功：

```bash

git push
cd ../plan && git pull --rebase
```

  **推送被提示实名**（票据 01 的遗留实测项）：按提示完成，结论记回
  `.scratch/multi-machine-collection/issues/01-primary-channels-git-and-object-storage.md`。

### 第 10 步 · COS：私有桶与最小权限 AK（2026-09-22 ✅，桶名已填 `machine.cos_bucket`）

1. 腾讯云建一个**私有**桶（如 `bestseller-exchange-<APPID>`）。
2. 建一把只允许 `img/*` 前缀读写的子账号 AK（采集机档位；策略里 Resource 写桶下 `img/*`）。
3. 装 [coscli](https://github.com/tencentyun/coscli)，按它自己的帮助配好这把 AK（配置在
   `~/.cos.yaml`，密钥不进代码仓、不进日志）：

```bash
coscli config --help
```

4. 验证（下面那条就是程序实际发起的命令形态）：

```bash
coscli ls -r cos://<桶名>/img/
```

判据：能列出（空桶也是成功）；再传一个测试对象能传能取；用这把 AK 访问 `img/` 以外的
前缀应被拒（被拒 = 配置正确）。
5. 把桶名填进 `config/config.toml` 的 `machine.cos_bucket`。

## 三、采集机接入（m1 / m2 / m3：采集 + 导出 + 汇总）

（DeepSeek key 与 `config/analysis.toml`）与视觉通路的核验；下面保留逐步版本供对照（机制与
步骤编号的权威清单见 [多机分片采集机制](多机分片采集机制.md)）。

1. **环境与依赖（第 1..3 步）**：Edge 在默认路径；Python 与现机同大版本（或留
   `BESTSELLER_PYTHON`）；clone 代码仓 → `pip install -r requirements.txt` →
   `python -m playwright install chromium`。判据：`python -c "import webview, playwright, PIL"`
   无错。**这一步顺带是 GitHub 大陆连通性实测**——clone 不通就退到离线分发（打包 zip 拷贝），
   结论记回 `.scratch/multi-machine-collection/issues/01-primary-channels-git-and-object-storage.md`
   （本机（m4）2026-09-21 实测：`ls-remote` 2 秒、`clone --depth 1` 31 MB 约 2 分 40 秒——通但慢；
   各机网络不同，仍要各自实测）。
2. **取壳（三只壳）**：壳随 clone 已在 `dist\`（2026-09-22 起）——`dist\inventory_fetch.exe`
   （采集壳）、`dist\inventory_exchange.exe`（交换台壳）、`dist\bestseller_analysis.exe`（分析壳）。
   判据：`dist\inventory_fetch.exe --check` 报 `ok`/`frozen`（或直接双击能起界面）。
   exe 留在 `<项目根>\dist\`
   别挪（项目根按 exe 位置推导，挪走就起不来）。
   只有壳正文（`shells/`）相对发布之后改过、想确认产物新鲜时才需要重建：
   `python tools/build_exe.py --target gui`、
   `python tools/build_exe.py --target exchange` 与
   `python tools/build_exe.py --target analysis`（`pyinstaller` 随 `requirements.txt` 装好），
   三条都以 `OK：…（… KB），项目根 …` 收尾（自检断言产物 frozen、不含项目代码）。
   **替代走法（发布包）**：在任意一台已建好壳的机器上跑 `python tools/release_shells.py`，
   把 `.scratch\tool-output\release\shells-<日期>\` 里三只 exe 拷到本机 `<项目根>\dist\` 即可
   （壳与机器无关，见 ADR-0007）；可选校验：`certutil -hashfile <文件> SHA256`
   对 `MANIFEST.json` 里的 sha256。程序改了不用重发，只有壳正文改了才需要重出包。
3. **运行根（第 4 步）**：`data/` `logs/` `profiles/` `screenshots/` `raw_pages/` `secrets/`
   `exchange/`；把 `config/config.example.toml` 复制成 `config/config.toml`，`[paths]` 全写成
   本机绝对路径。
   **已有 config.toml 的机器**（照现例复制即可的除外）先核对三个键：`[human]` 里**不能有**
   `pause_every_pages`（ADR-0038 之后旧键会让启动直接报错并同时点名新旧键），要写
   `pause_every_detail_visits = 180`（整段不写也行，缺省即 180）；`[run]` 的
   `deny_shop_limit` / `deny_round_limit` 要对齐 **3 / 6**（09-21 版示例写的是 7 / 10，
   留着会盖住新默认值）。一条命令核对：
   `grep -nE "pause_every_pages|pause_every_detail_visits|pause_sec|deny_shop_limit|deny_round_limit" config/config.toml`。
4. **浏览器与账号（第 5..6 步）**：`user_data_path` 指本机 profile、`attach_port` 用本机端口；
   `python login_chrome.py` 扫**本机专属**的 1688 账号（一台一账号）；冒烟采集
   `python run.py --pages-per-shop 2 --max-detail 20 --limit-shops <一家本机店>` 走通一轮、
   无登录墙/滑块告警。
5. **机器标识（第 7 步）**：`config.toml` 写 `machine.machine_id = "m1"`（或 m2 / m3）。
6. **凭据（第 8..10 步）**：Gitee SSH（ed25519 → 注册为本机账户公钥；判据：对本机那条
   raw 库推一个空提交成功、对 `plan` 拉取成功；**推送若被提示实名就照提示完成**，结论记回
   wayfinder 票据 01）；clone 本机那条 raw 库与 `plan` 到 `<运行根>/exchange/`（名册里别家的
   等它们入册再 clone）；COS 私有桶 + 读写限 `img/*` 的 AK（能传能取；`img/` 以外被拒）
   填进 `machine.cos_bucket`。
7. **名册（第 11 步）**：把本机编号加进 `plan` 库的 `machines.json` 并推送——**在下一份计划
   生成前加**，在册的机器下一份计划起就要分担采集。本机的 `config/shops.csv` **不用手建**：
   第一次打开采集程序时准备串会从计划库把共享清单拉下来当本机副本（UTF-8 带 BOM，与
   `plan` 库那份同字节）。
8. **第一次打开界面（第 12 步）**：双击 `dist\inventory_fetch.exe`（等价 `python gui.py`）。
   判据：准备串走完（pull 计划库 → 拉共享清单副本 → 读到本周计划
   并落库）；开始页默认勾选 = 本周计划里归本机、且今天还没采够的店（首次打开时都还没采够，全勾；本周空手也有明说，是合法状态）。
9. **首次库存数据交换（第 13 步）**：双击 `dist\inventory_exchange.exe`，窗口里点「导出&汇总」
   （等价 `python exchange.py --window`；只跑一半点「仅导出 / 仅汇总」）。判据同 §二第 13 步：
   退出码 0，或 1 时每条「需要看一眼」都有说明；本机那条 raw 库出现本周包；报告生成；同周重跑重写
   同一份。第一次运行还会把交换区里别的机器发过的**历史包**一起收进来（汇总这半不只收本周）。
10. **判断库（第 14 步）**：建 `judged-<本机>` 私有库并 clone 到 `<运行根>/exchange/`
    （本机那本 + 已建好的别人的几本）。判据：推自己那本成功、拉别人那本成功——详见 §二第 14 步。
    这是发布与收取判断集的通道，与采集那条互不影响；「只写自己那本」是纪律（Gitee 上按库收窄
    做不到）。

## 四、纯汇总机（只合并与展示，不采集）

8 步，与采集机的差异都在「不装采集那半」。

1. 环境同 §三 第 1 步，但**不建 Edge 专用 profile、不登录 1688、`playwright install chromium`
   可跳过**（合并/分析路径不拉起浏览器；日后哪个工具报缺浏览器，补跑即可）。判据：
   `python -c "import webview, playwright, PIL"` 无错。
2. clone 代码 + 建运行根（同 §三 第 3 步）；**只取交换台壳与分析壳**（壳随 clone 已在
   `dist\`，见 §三 第 2 步）——不建/不用采集壳 exe（纯汇总机不采集）；要重建的话只建
   `python tools/build_exe.py --target exchange` 与 `--target analysis`；
   分析仍 `python analyze.py` 起。
3. 凭据：git——本机 ed25519 注册为 Gitee **账号公钥**（判断库要发布判断）；采集通道的只读
   **不靠凭据**、靠角色闸门——`raw-*` 不导出（见第 5 条）、COS 换只读 AK（判据：下载已知对象
   成功、上传被拒 = 档位正确）。部署公钥只读、账号公钥全库可写，按库收窄没有机制——「只写
   自己那本」是纪律（§二第 14 步）。
4. clone 名册里各台机器的 raw 库与 `plan` 到交换区根（汇总这半要收所有机器的包；同 §三
   第 6 步）。
5. `config.toml` 的 `machine.role` 写 `"merge_only"`、`machine_id` 用本机编号（**本机 m4 将来
   就是走这条**：转角色当天按 [m4 过渡期操作单](m4过渡期操作单.md) 与 ADR-0034 跑；新加的
   纯汇总机自取一个编号）。判据：
   在本机试开采集（界面入口或 `run.py`）→ 明确拒绝并说明理由，库不被写轮次/快照/采集身份。
6. 冷启动：双击 `dist\inventory_exchange.exe` 点「导出&汇总」（等价 `python exchange.py`；
   **一轮就够**——汇总这半会把交换区里的全部历史包重放一遍；「仅导出」按钮在这台机器上
   置灰，导出这半按「本机是纯汇总机，跳过」如实记）。
   前置：本机（m4）的历史补发已完成（§二第 13 步）。判据：退出码 0；**第一次运行**的报告里
   「收进来的包」= 交换区全部历史包（含 W36/W37 那样的历史周）；交换集各表有数；图片按
   清单从 COS 补齐（首次全量，约 150 MB 量级）。之后每周再跑，表里只列本周的包（历史已经
   收进幂等账，不再占行）——「全收进来了没有」以 §五 核对工具那行「幂等账收进来 N/N」为准。
7. 展示验证：`python analyze.py`。判据：能选日期、出销量分析页；无「库为空」。
8. **判断库（第 14 步）**：建 `judged-<本机>` 私有库、clone 到交换区根，判据「推自己那本成功、
   拉别人那本成功」（详见 §二第 14 步）——纯汇总机照样发布判断集，判断库各写各的、
   与角色档位无关（ADR-0039 决策 3）。

## 五、三机验收（一期真实运行；口径全文见[多机分片采集机制](多机分片采集机制.md) 的「验收口径」一节）

验收周跑完之后：

1. **收敛同步**：三台各再跑一次交换台（把别人最后发布的包都收进来——先跑的那台可能
   还没收到别人最后一版）；纯汇总机也跑一次它的冷启动那轮。
2. 把要对照的库文件拷到一起（三台的 `bestseller.db` + 纯汇总机那份），在一台上跑核对
   （`--week` 填验收周、`--as-of` 填那一周的周日；库文件路径按实际情况改）：

```bash
python tools/acceptance_check.py --week 2026-W42 --as-of 2026-10-18 --plan F:/AI/bestseller_runtime/exchange/plan --exchange-root F:/AI/bestseller_runtime/exchange --machine m1=D:/验收/m1.db --machine m2=D:/验收/m2.db --machine m3=D:/验收/m3.db --merge-only m4=F:/AI/bestseller_runtime/data/bestseller.db
```

判据：退出码 **0**、结果行「通过 · 跑 7 项：过 7 / 没过 0 / 跳过 0」。五条口径的读法写在
`tools/acceptance_check.py` 的模块 docstring 里：

- 计划核对行「相邻周同机器 0 处」（读 `plan/<周>.md` 那行人核对的那一行）；
- 三台各自完成本机份额（份额 × `rounds.run_date × shop_rounds` 逐条对照，缺口逐条带当天
  轮次终态当说明）；
- 三台都发布了本周包；缺席的必须在本机周报里被点名（「还没来的包」为空或已有说明）。
  报告是本机视角的：这条核的是**跑工具这台**那份周报——想要三台的报告都被核，就在三台
  各跑一次这个命令（或把别机的报告拷到对应交换区根的 `报告/` 下再跑）；
- 任取两台逐表一致（交换集里承载取胜结果的五张表；冷启动那台的 `inventory` 覆盖起止会
  打出来——应从 2026-09-05 起）；
- 纯汇总机冷启动重放：一轮收全交换区历史包、各表有数、图片补齐。
3. **分析一眼**：数据逐表一致 ⇒ 同一份数据上分析确定产出同一份结果；在任两台各跑一次
   `python analyze.py`，对一眼畅销品结果（这一步人看，工具不替）。
4. 证据（日期、退出码、报告路径、两份 analyze 截图或同值结论）记到票 13 的评论里。

## 六、之后每周的常态

- 采集机每周至少跑一次交换台（导出 + 汇总 + 周报）；用壳的走法：双击
  `dist\inventory_exchange.exe` → 点「导出&汇总」→ **跑完再关窗**（运行中关窗只记录一笔，
  不拦——这一趟可能半途而废，但重跑能修：导出幂等、导入有幂等账、报告同周重写）；补历史或
  只跑一半之外的花样（`--week` 等）走脚本 `python exchange.py …`。
- 报告里「还没来的包」「缺口」「冲突」三节照实读：缺口补不了就如实记，冲突按赢家口径查；
- 名册加机器只在对方就绪后做（下一份计划起生效）；
- 谁错过了一周：它补发的历史包会被各台**下次运行自动收进来**（汇总这半不只收本周）；
- 同周再跑一次：报告重写同一份、「本次运行」行写明这次做了什么。注意一种正常现象：
  本周采得较晚、在别人之后又收过包的那台，同周**第二次**运行可能再发一个包（把合并进来
  的身份行补发一遍——机与机的时间戳就是这样互相 MAX 收敛的）；第三次起稳定为
  「无新提交」。判据按「重写同一份 + 本次运行行写明做了什么」看，别把这一份当异常。

## 七、出问题怎么记录（每台机器都适用）

这台机器上跑出的问题（报错、弹窗、拒绝、卡住、结果不对），第一件事是**留住现场**：别关窗口、
别重启、别删 `logs/`。然后双击 `tools\issue_bundle.cmd`（等价 `python tools/issue_bundle.py --prompt`，
命令行还可以 `--title "一句话点题"`）：它自动收机器事实、日志尾部、库与交换区状态、最近截图与
原始页面，生成 `REPORT.md`；把里面「一、问题描述」七个空填上，再按提示打成 `.zip`，整个拷走
交给 Claude 排查。规范、包里有什么、收到包怎么读：[问题记录与打包](问题记录与打包.md)。
