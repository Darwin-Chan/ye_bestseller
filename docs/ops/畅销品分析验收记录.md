## 3. 演示路径与复现

规格演示路径：选日期 → 固定数据 → 模型建议 → 对比纠错 → 筛选批量确认与撤回 → 暂存 → 关闭重开 → 新日期复用 → 保存排名 → 离线报告。

复现方式：

```bash
python -m unittest tests.test_e2e_acceptance -v
```

`tests/test_e2e_acceptance.py` 共 5 项，全部走真实页面与真实服务：

| `test_one_snapshot_feeds_sales_representative_tree_and_charts` | 规格切换 + 缺失 + 补货 + 跨店合并落在同一快照；代表商品、组总销量、构成树与图表同源 |

两条的共同前提——「未成功」只指**模型判断失败**，低把握与未召回是完成的判断、重试改变不了

缺证据不让按钮可用）、`test_failed_judgements_are_retryable_and_retry_reports_judged_products`
（可重试失败 → 重试 → 全部已判断，且缓存命中后调用数不变）、`test_config_failure_is_not_retryable`
（密钥缺失归「需配置」）、`test_disabled_matching_is_not_a_failure`（未启用不是失败）、
`test_summary_dedupes_reasons_and_counts_every_state`（计数口径与原因去重），以及两条老草稿回填
（`test_legacy_draft_without_state_codes_is_classified_on_restore`、
`test_legacy_draft_with_config_failures_still_says_needs_config`）。

浏览器侧四条：`test_button_reports_the_result_and_grays_out_once_judgements_complete`（亮 → 点击 →
结果 → 置灰 → 悬停原因）、`test_partial_failure_keeps_the_button_usable_and_names_each_reason`
（部分失败保留可用，切页签清结果、常显状态行接手）、`test_result_names_products_that_never_entered_
judgement`（未进入判断的商品数）、`test_button_is_disabled_and_explains_when_matching_is_not_configured`
与 `test_config_failure_leaves_the_button_disabled_and_points_at_the_config`（两种置灰原因）。

**本票回归**：独立副本（HEAD + 本票、副本含本机 `config/`、目录名 `bestseller`）
全套 **977 项通过（440.871 秒）**，基线 `244c139`。§5／§6 的数字是票 13 收口时的历史值，未改写。

- 口径：覆盖＝组内正边／全部正边；纯度＝组内正边／（组内正边＋组内负边）；边展开到本次商品清单上的
  商品对（版本边覆盖所有取到这两个版本的商品对）。四档单次跑完都在 0.2 秒上下。**纯度对人工参照组
  的口径留人工确认轮**——ADR-0040 判据 4 的验收线（≥80%）要对参照组算，本机还没有参照组。
- 收益真实但不决定性（瓶颈在正边只有 323 条）；12 店全量数据到位后重跑，见 ADR-0040 代价三。
