# SKU 维度同款分组研究更新：只读事实核验

核验日期：2026-10-17

范围：按任务指定读取研究文档、ADR、SKU 规格、`matching.py`、`sku_matching.py`、`sku_recommendations.py`、`analysis.py` 和 `config/analysis.toml`；另外只读查看了当前实现直接依赖的 `sku_codes.py`、`sku_grouping.py` 和 `sku_drafts.py`，用于核对编码解析和调用链。未修改仓库文件，未运行模型调用，未作准确率判断。

## 结论先行

1. `docs/research/同款分组判定效率调研.md` 是 2026-09-22 的商品级效率研究。其问题、结论和规模数字围绕商品、`candidates=6`、440 商品及 14 人团展开；文件中没有 `SKU`、`sku`、`商家编码` 或 `merchant_code` 术语命中。因此不能直接把该研究的 14 人团结论当作 50 SKU 组的结论。
2. 当前代码已经有 SKU 默认粒度、SKU 冻结/回放、编码优先、SKU 图文判断和多候选推荐调用链：`analysis.py:195-200, 385-394, 495-522`。但 ADR-0050 和 SKU 规格仍标为“尚未实现”：`docs/adr/0050-sku-level-grouping-and-merchant-codes.md:3-5, 31`、`docs/design/sku-grouping-spec-2026-10-08.md:5-10, 219-222`。这证明文档状态需要重新核对；不能据此宣称完整规格已经实现。
3. SKU 名称参与模型比较和多候选上下文，但没有参与当前召回 token 索引：`matching.py:472-490` 只从 `product_name` 和图像生成召回特征；`sku_matching.py:6, 68-73` 复用该函数。模型比较则把 `matching_input` 送入请求并明确要求使用 `product_name`、`sku_name` 和图片：`matching.py:438-459`。推荐上下文还保留 `raw_sku_name`、`matching_input` 等字段：`sku_recommendations.py:12-22, 52-60`。
4. 商家编码规则已在当前代码中单独实现：半角/全角井号取闭合片段，去首尾空白、英文大写归一；单一不同值成为 `merchant_code`，多个不同值标记歧义；只有单 SKU 且没有真实 SKU 名称时才从商品名称兜底：`sku_codes.py:6-25`。编码规则在匹配前运行，唯一合法同码目标可直接增员，多个目标转入多候选：`sku_grouping.py:536-589`。两边已有编码时，SKU 图文配对路径直接判为不合法，交给编码/人工规则：`sku_matching.py:20-28`。
5. 对 50 个 SKU，当前配置的召回上限为每个成员 6 个候选、判断分数下限为 4、并发为 2：`config/analysis.toml:7-15`；配置读取也以这些值构造 `MatchingConfig`：`analysis.py:238-250`。**推论**：50 个成员的完整无向两两关系有 `50×49/2=1225` 对，而每成员最多取 6 个候选，唯一候选对的理论上限不超过 `50×6=300`，还会被分数下限、同组跳过、编码和人工约束进一步减少。因此研究应单独记录“50 SKU 组的候选对数/实际调用数”，不能沿用商品级 14 人团的数字。
6. 当前 SKU 图文装配没有显式的组成员数上限或 50 SKU 专用预算闸门：`sku_matching.py:9-11` 的 `LIMITATIONS` 为空，相关路径只检查单例来源组、人工约束和排除条件。对一个自动目标组，提议条件是“至少存在一条正边，并且对目标组成员没有已知负边”：`sku_matching.py:137-159`。**推论**：未知边不会阻止把 SKU 加入较大的目标组；在大组场景下，单条正边可能支撑增员，而未召回/未判定的其余关系不会自动形成反证。这是 50 SKU 组需要显式实验和产品约束的组装风险。
7. 多候选推荐的上下文按候选组成员展开，不只传组 ID：`sku_recommendations.py:52-60`；执行时把待推荐 SKU 和所有候选组成员放进 `products`，再由 `ImageJudge.recommend` 为每个产品追加图像证据：`sku_recommendations.py:98-111`、`matching.py:413-429`。**推论**：若候选组本身有 50 个成员，单次推荐请求的文本和图片规模会随组成员数线性增长；当前列出的代码没有按组大小截断、分批或单独的成本上限。实际 token、延迟、供应商上限和失败率仍需实验确认。

## 带路径和行号的事实

### 1. 旧研究文档的口径与当前 SKU 需求不一致

- 研究标题和取证范围是“candidates、多轮判定与 80% 纯度目标”，取证文件列的是 `matching.py`、`analysis.py` 等，并没有 SKU 粒度范围说明：`docs/research/同款分组判定效率调研.md:1-5`。
- 研究的问题拆解是 `candidates=6` 对“14 人组”、多轮与扩大 candidates 的比较，以及 80% 正确组目标：`docs/research/同款分组判定效率调研.md:9-17`。
- 研究结论中的 440 商品、k=6 最大团、14 人组结构性不可能和 `candidates ≥17` 都是商品级离线复算口径：`docs/research/同款分组判定效率调研.md:21-27`。该文件对 `SKU`、`sku`、`商家编码`、`merchant_code` 做只读文本检索没有命中，所以没有现成的 SKU 版基线。
- 研究的落地建议仍以判断缓存、E2 标定、星形编排、并发和并列扩边为主：`docs/research/同款分组判定效率调研.md:482-486`。这些事项可以保留，但必须把“商品级召回/判定”与“SKU 编码优先及 SKU 图文路径”分开描述。

### 2. 当前代码已经存在 SKU 调用链，但文档仍写未实现

- `AnalysisConfig` 的默认成员粒度是 `sku`，只允许 `sku` 或旧兼容粒度 `product`：`bestseller_monitor/analysis.py:193-200`。
- 新分析快照若为 SKU，会跳过旧商品账本，走版本化 SKU 草稿和 SKU 模型工作流：`bestseller_monitor/analysis.py:383-394`。
- SKU 工作流顺序是：回放 SKU 草稿、套用共享决定、执行编码规则、再执行 SKU 图文匹配：`bestseller_monitor/analysis.py:495-522`。
- ADR-0050 的状态仍是“已接受（设计已确认，尚未实现）”，并明确说“当前代码仍是旧实现”：`docs/adr/0050-sku-level-grouping-and-merchant-codes.md:3-5, 25-31`。
- SKU 规格也写明“尚未实现”，并要求发布文档不当作实施授权：`docs/design/sku-grouping-spec-2026-10-08.md:5-10`；文档关系部分仍要求标明“尚未实现”：`docs/design/sku-grouping-spec-2026-10-08.md:217-222`。

需要更新的事项：把文档状态改为“已实现、部分实现或待验收”中的可验证状态，并列出未覆盖的规格条目。仅凭上述代码存在，不能证明全部 T1–T30 已通过。

### 3. SKU 名称在哪些阶段参与

- 召回函数生成的文本 token 只来自 `product_name`；图像存在时再加入 8×8 灰度图的视觉 token：`bestseller_monitor/matching.py:472-490`。取每个成员的 top-N 候选在 `matching.py:497-507`，SKU 路径从 `sku_matching.py:6, 68-73` 调用同一函数。
- 因此，当前代码可以直接证明：`raw_sku_name`/`matching_input.sku_name` 不参与这一步的召回 token 生成。它们是否通过其他未列出的上游特征间接影响 `product_name`，不能从这里推定。
- 对级模型比较会把每个 SKU 的 `matching_input` 作为文本输入；没有该字段时才退回 `product_name`：`bestseller_monitor/matching.py:438-445`。SKU 专用 prompt 明确要求用商品名、SKU 名称和图片，并要求同名不能单独作为证据：`bestseller_monitor/matching.py:448-459`。
- `sku_drafts.py` 当前构造的 `matching_input` 是商品名称加 SKU 名称；单 SKU 时 SKU 名称为空：`bestseller_monitor/sku_drafts.py:50-62`。这与规格中“商品名称有值、单 SKU 的 SKU 名称为空、原始名称另存”的要求一致：`docs/design/sku-grouping-spec-2026-10-08.md:101-104`。
- 多候选推荐上下文保留 `product_name`、`raw_sku_name`、`matching_input`、图片哈希/来源、编码和既有图文判断：`bestseller_monitor/sku_recommendations.py:12-22`；候选组上下文还保留组 ID、人工成员和所有候选成员：`sku_recommendations.py:52-60`。

需要更新的事项：研究应新增“召回阶段不使用 SKU 名称、对级判断/推荐阶段使用 SKU 名称”的阶段图和实验问题。不能把“模型 prompt 要求使用 SKU 名称”写成“SKU 名称已经参与召回”。

### 4. 商家编码规则和实际执行边界

- 规格/ADR 规定编码是证据而不是身份；人工约束优先，编码优先于普通图文；同码不再请求模型核验，异码默认分开，至少一方无有效编码时才走商品名、SKU 名称和 SKU 图片：`docs/adr/0050-sku-level-grouping-and-merchant-codes.md:15-19`、`docs/design/sku-grouping-spec-2026-10-08.md:89-95`。
- 当前解析器使用 `[ # ＃ ]` 的闭合片段形式，去首尾空白并只把英文字母大小写视作等价；空值不产出编码，重复同码不冲突，多个不同规范化值产生 `code_ambiguous=True` 且不选任一个：`bestseller_monitor/sku_codes.py:6-25`。
- 单 SKU 且原始 SKU 名称为空或为系统默认占位时，解析器从商品名称取编码；存在真实 SKU 名称时没有编码，不继续从商品名称兜底：`bestseller_monitor/sku_codes.py:15-24`。该边界也写在规格：`docs/design/sku-grouping-spec-2026-10-08.md:99-104`。
- 编码应用先收集人工/排除锚点组；同码唯一目标直接加入并撤销确认，多目标保留候选组并转 `pending_candidates`，没有目标时建立或复用自动同码组：`bestseller_monitor/sku_grouping.py:547-589`。
- SKU 图文路径的 `_legal` 对两边都已有 `merchant_code` 的配对直接返回 false；注释明确相同或不同编码都归编码/人工规则处理：`bestseller_monitor/sku_matching.py:20-28`。对无编码成员，若没有图片则暂时独立；有图片才进入召回/判断：`sku_matching.py:54-73`。
- 编码不是永久不可推翻事实：规格允许人工覆盖异码或纠正同码误合并，并要求人工拆组不可被自动重合：`docs/design/sku-grouping-spec-2026-10-08.md:91-95, 118-122`。

需要更新的事项：研究应把编码命中率、歧义率、同码直接归组数量、异码拦截数量、进入模型的无编码对数量作为独立成本分解；不能只用总候选对数估算 SKU 成本。

### 5. 50 SKU 组的成本和组装风险

- 当前分析配置为 `concurrency=2`、`candidates=6`、`min_score=4`：`config/analysis.toml:7-15`；代码的配置读取和校验分别在 `analysis.py:238-250`、`matching.py:165-183`。
- SKU 匹配对每个有图成员调用 `scored_pairs(eligible, candidates)`，按召回分排序后交给分数下限过滤：`bestseller_monitor/sku_matching.py:68-87`。在 50 个成员、`candidates=6` 的假设下，唯一候选对上限是 300；完整无向两两组合是 1225。这个 300/1225 比值是算术推论，不是运行实测。
- SKU 自动归组的目标条件不是与目标组全部成员都有正边，而是至少一个正边、所有目标成员的关系没有已知负边：`bestseller_monitor/sku_matching.py:137-159`。因此 50 SKU 组的风险重点是“未知边密度”和“单条正边是否足以增员”，而非只看是否能形成完整团。
- 当前代码没有 50 SKU 的组大小限制或单组预算字段：`bestseller_monitor/sku_matching.py:9-11` 的限制列表为空；`sku_recommendations.py:25-49` 只做合法候选筛选，没有组大小阈值。
- 多候选推荐把全部候选组成员放入上下文，执行时还把待推荐成员和候选组所有成员放入图文请求：`bestseller_monitor/sku_recommendations.py:52-60, 98-111`、`bestseller_monitor/matching.py:413-429`。一个 50 SKU 候选组会导致约 50 个候选成员上下文和对应图片证据进入一次推荐请求（加上待推荐 SKU）；这是规模推论，实际 token/图像限制和延迟未测。
- 旧 ADR-0040 的 50% 是“后续边界判定数不超过首轮判定数的 50%”的预算规则，不是 50 SKU 组的成员上限：`docs/adr/0040-correlation-clustering-and-boundary-judgments.md:74-79, 123-134`。研究更新时应避免把两个“50”混读。

建议新增一组离线验收指标：按组大小 1、2–6、7–14、15–50 分层，记录召回候选对、低分阻断对、编码直接归组数、实际模型调用数、推荐上下文成员数、图片数、缓存命中数、失败/停止数、自动增员后待确认组数和人工复核分钟数。当前仓库材料没有这些 50 SKU 实测数据。

### 6. 多候选上下文和缓存事实

- 只有来源组是单例、非人工组、未排除且至少两个合法候选组时，才进入推荐路径：`bestseller_monitor/sku_recommendations.py:25-49, 90-100`。
- 推荐上下文包含完整候选成员、人工成员、排除约束、分析日期、待推荐成员证据和既有图文判断：`sku_recommendations.py:12-22, 52-60`。
- 推荐结果必须是某个精确候选组 ID 或 null；null 会保持 `pending_candidates`，不会按组号或顺序强行选组：`sku_recommendations.py:120-128`；规格也明确要求唯一推荐不确定时暂时独立：`docs/design/sku-grouping-spec-2026-10-08.md:114-122`。
- 缓存键由完整上下文摘要构成，并在应用前重新检查当前合法候选语境：`sku_recommendations.py:74-87, 108-119`。这支持“语境变化不能误命中”的设计目标，但仍需实测跨机共享和旧客户端拒绝闸门。

需要更新的事项：研究应把“候选组数量”和“候选组成员总数”分开计费/计时；应明确推荐缓存命中只在完整语境不变时成立，不能用旧的只写 `recommendations` 快照直接宣称已有共享推荐缓存。规格本身也保留了这一实施前核验项：`docs/design/sku-grouping-spec-2026-10-08.md:124-131, 210-215`。

## 明确需要更新的研究事项

1. 把研究对象拆成商品级旧路径与 SKU 级新路径，注明研究日期、代码版本和实现状态。
2. 增加 SKU 召回基线：明确 `product_name + image tokens` 当前进入召回，`sku_name` 目前只进入对级模型输入和推荐上下文。
3. 增加商家编码成本分解：解析来源、规范化、歧义、同码直接归组、异码拦截、无编码进入模型的比例。
4. 新增 50 SKU 组的规模实验，不使用商品级 440/14 人团数字替代；至少测候选对数、实际调用数、上下文成员/图片数、token、延迟、失败和人工复核量。
5. 单独验证大组装配：未知边是否允许单条正边增员、负边覆盖不足时的误合组风险、自动增员后的整组待确认行为，以及是否需要组大小/每组预算闸门。
6. 把多候选从“候选组个数”扩展为“候选组成员总数”，并验证 50 成员候选组的请求大小和供应商限制。
7. 核对 ADR-0050/规格“尚未实现”与当前 SKU 代码调用链的关系；逐条标记已实现、部分实现、未实现和未验收，避免研究引用过时状态。
8. 保留 ADR-0040 的相关聚类/边界预算结论，但明确其对象是商品级旧研究或通用边界协议，不能自动推导 SKU 组的准确率、成本或 50 成员行为。

## 当前仓库无法确认、需要用户或实验确认的问题

- 没有 50 SKU 真实样本和人工真值，无法确认 300 候选对上限是否常见、正边率、纯度、覆盖率或最终误合组率。
- 无法从这些文件确认 50 SKU 组主要由同码规则形成，还是由无编码图文路径形成；两者的模型成本完全不同。
- 没有实际运行记录可以确认单次 50 成员多候选推荐的 token 数、图片数是否触及供应商限制、实际延迟、重试和费用。
- 无法仅凭代码证明当前 SKU 代码已经在目标部署环境启用，也无法证明规格 T1–T30 已全部验收；需要测试证据、部署版本或用户确认。
- 无法从仓库静态代码推出任何准确率、80% 纯度或节省比例；这些必须用人工真值和运行数据测量。
- 旧商品级研究中的 E2 数字、相关聚类回放数字和外部供应商容量数字不能直接作为 SKU 50 组的实测结论；本报告没有重新调用模型或外部服务。

### 由此新增的待确认点

- 26–50 SKU 参照组需要从跨商品候选关系中抽样并由业务人员确认，不能按单商品 SKU 数代替。
- SKU 图片样本不是全量库存样本，实验必须记录是否有图、图片来源和缺图情况。
- 在人工参照组建立前，不能把商家编码相同或模型已有分组当成真实同款组。
